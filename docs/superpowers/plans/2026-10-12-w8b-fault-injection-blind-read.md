Branch `w8b-fault-injection-blind-read` from main 682b636. Ledger `.superpowers/sdd/2026-10-12-w8b-fault-injection-blind-read/progress.md`. Written by the unattended controller on 2026-10-12. The report, the check and the hints it builds on are described in `docs/superpowers/plans/2026-10-12-w8-field-diagnostics.md` (Pinned interfaces and Amendments).

**Goal.** Rehearse the whole field-debugging loop before the real SCADA exists. (H) The dev OPC UA simulator can be told, by environment variables, to misbehave the way a real server does: refuse our certificate, want a login, offer other security policies, answer slowly, drop connections, return Bad status codes, report a wrong time. (I) For each fault the controller produces the `summary` report in a scratch stack and gives an Opus reader ONLY that text (no repo, no tools): it must name the failing step, the likely cause and what the owner should ask or change; whatever it cannot tell is a gap in the report, fixed once. The reports become `docs/field-debugging-examples/`. (E, rest) `scripts/collect-diagnostics.ps1` grows services, logs, database and API sections with a scrubber; a new `scripts/collect-diagnostics.sh` does the same on Linux; ONE shared fixture file (`backend/tests/fixtures/scrub_cases.tsv`, already written) pins the scrubbing rules for the Python, PowerShell and awk copies.

**Merge cut.** Done when tasks A1-A3, B1, B2, D1 and the blind-read round are built and gated. No migration, no frontend change, no new endpoint (the report and the check only change if the blind read finds a gap).

## Pinned interfaces (do not renegotiate; propose a change in your report)
**Fault switches (`backend/dcdash/simulator/faults.py`).** All optional, empty or unset means off:
| Variable | Meaning |
|---|---|
| `SIM_FAULT_POLICIES` | `none` (default), `basic256sha256`, or `none,basic256sha256`: the security policies the endpoint offers (a secure policy needs a server certificate: the simulator makes a self-signed one at start, in memory or a temp dir) |
| `SIM_FAULT_UNTRUSTED_CERT=1` | the endpoint offers Basic256Sha256/SignAndEncrypt only and validates every client certificate against an EMPTY trust list, so any client certificate is refused; conflicts with an explicit `SIM_FAULT_POLICIES` that contains `none` (startup error) |
| `SIM_FAULT_AUTH=required` | only the UserName token is offered (no Anonymous); needs `SIM_OPCUA_PASSWORD` (user `sim`) or startup fails; a wrong or missing login is refused by the user manager |
| `SIM_FAULT_SLOW=<seconds>` | float, 0 < x <= 60: every OPC UA service response is delayed by that long |
| `SIM_FAULT_DROP=<seconds>` | int >= 2: every N seconds all client connections are closed by the server (the listener stays up) |
| `SIM_FAULT_BAD=ADDR:Status[,ADDR:Status]` | for example `LVP01_kW:BadSensorFailure,LVP02_V:BadNodeIdUnknown`: those variables answer with that Bad status code; ADDR must exist in the model, Status must be a `ua.StatusCodes` name starting with `Bad` |
| `SIM_FAULT_SKEW=<seconds>` | signed int, abs(x) <= 86400: the server's clock (`ServerStatus/CurrentTime` and the timestamps it stamps) is that many seconds ahead of real time (negative: behind) |

`Faults` is a frozen dataclass (`policies: tuple[str, ...] = ("none",)`, `untrusted_cert: bool`, `auth_required: bool`, `slow_seconds: float`, `drop_seconds: int`, `bad_nodes: tuple[tuple[str, str], ...]`, `skew_seconds: int`) with `Faults.from_env(environ: Mapping[str, str]) -> Faults` (raises `FaultConfigError(ValueError)` with a plain sentence for a bad value, an unknown `SIM_FAULT_*` name (a typo must not silently run a fault-free rehearsal) or a conflict) and `describe() -> list[str]` (one line per active fault). `OpcUaSim(sim, port, username="sim", password=None, *, faults: Faults | None = None)`; `tests/helpers.opcua_server(sim=None, password=None, faults=None)`. `simulator/main.py` calls `Faults.from_env(os.environ)` once, logs ONE warning line `FAULT INJECTION ACTIVE: <describe>` when any fault is on, and passes the object to `OpcUaSim`. The HTTP and Modbus simulators are unaffected (OPC UA only; the docs say so). Stopping an `OpcUaSim` must leave no global state changed (no monkeypatch that outlives the instance), because the tests run many servers in one process.

**Shared scrubber fixture (`backend/tests/fixtures/scrub_cases.tsv`).** Tab separated, 4 columns (name, known values joined by `|` or `-`, input, expected), `\t` and `\\` escapes, `(empty)` for the empty string, `#` comments; its header states the rules. Every copy exposes a self-test mode that reads the file and prints one line per case: `case <name> OK` or `case <name> FAIL expected=<..> got=<..>`, then `SCRUB SELF-TEST <n> OK <m> FAILED`, exit code 0 only when none failed: `collect-diagnostics.ps1 -ScrubSelfTest <path>` and `collect-diagnostics.sh --scrub-self-test <path>`. The Python scrubber is tested against the same file in `backend/tests/test_scrub_fixture.py`, which also holds the one `load_cases()` helper the script tests import.

**Offline script output (both scripts).** Same shape as today's ps1: first line `DCDASH-DIAG v1 | collect-diagnostics.<ext> | <shell version>`; `== NAME ==` sections; last line `END OF DIAGNOSTICS <12 hex>` = first 12 hex of SHA-256 over every line before it joined by LF (UTF-8, no trailing LF); file UTF-8 without BOM, LF. New sections after TOOLS ON PATH: `SERVICES` (containers via `docker compose ps -a` when docker and a `compose.yaml` in the project folder exist; otherwise Windows services named `dcdash*` / `postgres*` or systemd units `dcdash*` / `postgres*` / `docker`; "none found" is a valid answer), `DATABASE` (`docker compose exec -T db pg_isready` when containers exist, else a TCP connect to 127.0.0.1:5432 with milliseconds), `API` (`GET http://127.0.0.1/api/health` and `http://127.0.0.1:8000/api/health`: status code, milliseconds, the first 300 characters of the body, scrubbed; 3 s timeout), `LOGS` (the last 30 lines of every service from `docker compose config --services`, each clipped at 240 characters and scrubbed). Parameters: ps1 `-ProjectDir` (default: the current folder if it has a `compose.yaml`, else the script's parent folder if it has one, else none), sh `--project-dir DIR` likewise. A SECOND file `dcdash-diag-<timestamp>-logs.txt` (same footer rule, header `DCDASH-DIAG-LOGS v1`) holds the last 300 lines per service (clipped at 1000 characters, scrubbed); it is saved, never printed, and the main report says where it is. The scrubber is applied to EVERY log line; its `known` list is built from the project folder's `.env` (the values of keys whose name contains PASSWORD, SECRET, TOKEN or KEY, 4+ characters; the report prints only their COUNT). Every external command runs with a time limit (10 s; `docker compose logs` 30 s) so a hung Docker cannot hang the script. Exit codes: 0 report written, 1 the file could not be saved.

- **A2b: the client side of that finding** (a real defect the fault work surfaced; the collector uses it on the real SCADA path, so keep the happy path byte-for-byte as it is and test it). Per-instance fix, no class patch: a small `Client` subclass (or the reviewer's instance-level wrap, exp4) records an `ua.ErrorMessage` status and fails every pending future with `ConnectionResetError` (or a `UaStatusCodeError` with the recorded code when an ERR was received) when the connection is lost; use it in `OpcUaConnector._new_client` and the check's `open_session`/`get_endpoints`, so the check shows `session FAIL BadSecurityChecksFailed (0x80130000)` and the collector's `last_error` says the same. (2) `_new_client` never sets `client.application_uri`, so the collector announces asyncua's default URI instead of the certificate's SAN URI (`urn:dcdash:collector` in the README certificate) and a server that compares them answers `BadCertificateUriInvalid` even after trusting the certificate: set it from the client certificate's SAN URI when a secure policy is configured (public certificate only, never the key) and reword the `BadCertificateUriInvalid` hint to say which two URIs differ. Tests: ERR at OPN gives the status within 1 s (not a timeout), a server that accepts and closes gives `ConnectionResetError` with its hint, an untouched healthy session behaves exactly as before, the ApplicationUri test against an asyncua server with a `URI | PEER_CLIENT` validator.
- **SLOW** delays EVERY incoming message (Hello, OpenSecureChannel, CreateSession, ... all). The session step needs four round trips under ONE timeout, and so does the collector's connect, so a server that answers each request in about t/4 can never be connected: A3 rows become `SLOW=0.3, timeout_seconds=2` -> all OK, and `SLOW=1.5, timeout_seconds=1` -> `endpoints` TimeoutError. Add a sentence to the timeout hint: the handshake needs about four round trips, so answers of about a quarter of the timeout can still time out.
- **DROP** is redefined: `SIM_FAULT_DROP=<seconds>` (float >= 0.2) closes each client connection that many seconds AFTER IT WAS ACCEPTED (a short-lived-connection gateway). A3 row (7) then uses `DROP=0.5` with the REAL `TIMING_PAUSE` (do not apply the module's `quick_timing` fixture to it): `timing` fails with `ConnectionResetError` and its hint; a collector scenario uses `DROP=0.3` + `SLOW=0.2` so each poll dies in its handshake.

## Review focus (plan review and whole-wave review)
1. Isolation of the fault code: no way to enable a fault outside the dev `simulator` service; a typo in a variable name fails loudly; no state left behind after `OpcUaSim.stop()`.
2. Realism of each fault: would a real server produce this status/behaviour, and does the check name the same step a real failure would? (A fault that makes the check fail at an artificial step trains the reports on the wrong thing.)
3. The three scrubber copies agree with the fixture AND with each other on inputs the fixture does not list (long lines, CRLF, a line with 5000 `://`, non-ASCII, a very long run of non-space text: no catastrophic backtracking in the PowerShell regex or the awk loop).
4. The offline scripts never print a secret: `.env` values only as a count, the `known` list applied to the logs file and to every error text, no environment dump, no `docker inspect` (it prints container environment).
5. Graceful degradation: no docker, no compose file, no `.env`, a hung command, a service that does not exist.
6. The blind-read protocol itself: the reader gets only the text and the owner's four-line message; the ground truth is hidden from it; every scenario is judged on three questions.
