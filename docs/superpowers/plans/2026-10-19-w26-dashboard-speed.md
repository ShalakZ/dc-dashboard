## 0. What the Opus plan review changed (report `.waves/w26/plan-review.md`, C=2 I=7 M=13)
- **C1 (decisive).** Revision 0 of this plan built per-asset hour COLUMNS in bucket order. The review measured on a62fce0 that a parent's PRICED hours are not in bucket order (`cost._sum_children` keeps first-appearance order) and that Billing's day sums and the comparison add hours in that order: summing in bucket order changes the digits on 160 of 200 test days. So **the engine's arithmetic and the order of every addition stay exactly as they are**. The grid engine is parked (backlog BJ) with this finding as its design constraint (a priced series must carry its own hour order).
- **The speed now comes from** (1) a cache of COMPACT DERIVED VALUES computed from today's engine (so no digit can change: the same functions run on the same objects), (2) the pure computation on one compute thread and the SQL read in batches (the loop stays free), (3) cheap representation changes that do not touch a fold: tuple rows, integer casts in SQL, one local-date map for `rate()`.
- C2, I1 to I7 and the M-items are folded into section 2 (P3 to P12) below; each is also a `Ruling:` line in the ledger.

## 2. Rulings that refine the brief
- **P1 What is cached.** Compact, immutable-by-contract values computed by `core/figures.py` from TODAY'S engine: (a) `MonthDays`: for a whole local month, per asset the list of Billing day entries (`day_entries(priced, days, now=<unbounded>, rate_on)`), plus `own`, `own_from`, the snapshot's `tree` and `tariffs`; shared by both sides of every comparison, Billing JSON/CSV and a closed month's `live`; (b) `WindowValues`: for a window `(first, last, end)` and a source (energy or cost), per asset the exact value tuple the non-series branch of `_fill_billing` builds (`_Value` fields), used by plain value widgets and the breakdown. NOT cached: series-mode widgets, the asset and fleet summaries (one-day windows), Check month (review I2: its inputs differ; it keeps one batched read on the thread, always fresh). Entries hold no hour-level objects (about 3 MB per month instead of 95).
- **P2 The masked entries equal `day_entries`.** `entries_at(month_days, asset_id, now)` returns the cached entries with `None` where the local day starts after `now`; a unit test proves it equals `day_entries(priced, days, now=now, rate_on)` for many `now`s, zones (DST) and trees. Entry dicts are shared: every consumer treats them as read-only, and `month_costs` COPIES each day dict into its response (review I4: `test_api_billing_close.py:340-347` mutates what it gets).
- **P3 Snapshot consistency (C2).** The shared computation owns its session on a separate small engine (`pool_size=2, max_overflow=1`, a semaphore of 2 computations; review I3) and runs in ONE `REPEATABLE READ` transaction: config fingerprint, tree, tariffs, data fingerprint and rows come from one snapshot. The value carries its own `tree` and `tariffs`; the consumer takes EVERY figure-side lookup (`rate_on`, `rated`, `rate_per_kwh`, `rate_change`, `contributing_meters`, names and paths of Billing) from the value's tree and tariffs, never from the request's; an asset id missing from the value's tree reads as "no figure". A requester accepts a value only if the snapshot's config fingerprint equals the one it read itself; else it retries (three times, then it uses the value anyway, consistent with itself).
- **P4 Fingerprints.** Config: one statement per request, `md5` of the text of `row(...)::text` rows (unambiguous: names with commas, NULL parents) of `assets(id,parent_id,sort_order,name)`, the energy_kwh/active_power_kw `mappings(id,asset_id,point_id,metric,scale,interval_seconds)` and `tariffs(id,asset_id,rate_per_kwh,effective_from)`, each ordered by id; the zone and the params join the key. Data: one statement over exactly the rows the engine reads for the window (`energy._ROWS`: the rows of `[start, end)`, the baseline of each counter, the first bucket of each point), each row hashed WHOLE with its `kind` (`hashtextextended(row(kind, point_id, bucket, min_value, max_value, sum_value, n, last_value, minutes)::text, 0)`), reduced with `sum(hash::numeric)` and `count(*)` per kind (review M1 and the advisor: no per-column sums, no XOR, so duplicates cannot cancel; the text keeps the sign of zero).
- **P5 TTL and switches.** `DCDASH_FIGURE_CACHE_TTL` seconds (default 30), `DCDASH_FIGURE_CACHE=0` (off). A value is served without any data statement for TTL seconds after its last data check; then the data fingerprint is compared (equal: renew; different: recompute and REPLACE the entry, review M11). `close_month` runs `month_costs` inside `figure_cache.require_fresh()` (a context variable; review I4: `month_costs` keeps its two-argument signature) so a close never uses an entry inside its TTL.
- **P6 Test isolation (review I6).** An async autouse fixture in `conftest.py`: before and after every test it cancels and AWAITS every in-flight cache task, empties the store, bumps a generation counter (a late finisher of an older generation stores nothing) and sets the TTL to 0 (every request revalidates; keep-warm is off at TTL 0). It runs before the `db` fixture's `TRUNCATE`.
- **P7 Thread.** One `ThreadPoolExecutor(max_workers=1)` in `core/compute.py`; `await run(fn, *args)` runs a PURE function (no `AsyncSession`). `sys.setswitchinterval(0.001)` is set when the module is imported (review M5: ASGI test clients run no lifespan); `shutdown(cancel_futures=True)` in the lifespan's shutdown.
- **P8 Representation-only engine changes (T2L).** `HourRow` becomes a `NamedTuple`; `n` and `minutes` are cast to integers in `energy._ROWS` (the column list stays; `Decimal == int` keeps the `test_api_billing_check.py:433-435` pin); rows are kept as tuples; `cost_by_hour` computes one bucket-to-local-date map per call instead of an `astimezone` per asset-hour; `hourly_energy` is split into a row read and a pure `assemble` (names: `read_energy_rows`, `assemble`) so the pure part can run on the thread. `HourEnergy` / `HourCost` stay frozen dataclasses unless a grep shows no `replace/asdict/astuple/fields` use and the oracle stays bit-equal; then they may become `NamedTuple`s (equality becomes tuple equality; optional). No fold, no order, no `sum()` vs `+=` changes.
- **P9 Oracle.** `tests/reference_engine.py` = today's `core/energy.py`, `core/cost.py`, `core/daycost.py` copied UNCHANGED (header "copied from main a62fce0; do not edit"); `tests/test_engine_oracle.py` compares new against it on seeded random worlds with `repr` of every float: trees to depth 6, children in random order, a first child with gaps that a later child fills (review C1) and the same one level deeper, own-metered mixed with unmetered siblings, a silent counter as the first child, a meter starting mid-window, power rows with `n <= 0`, three or more children with non-dyadic mixed-magnitude values, `-0.0`, resets and glitches, `own_from` before/inside/after the window, a mid-month rate change in a DST zone. Generators use non-dyadic floats (review I1).
- **P10 Reads.** T4 changes the row read to batches of about 5,000 through `AsyncSession.stream()` (still ONE `readings_1h` statement and at most two statements in all: `test_energy_engine.py:360-387`).
- **P11 Keep-warm and start-up warm-up (T3c) are decided after T3b is measured with a live inserter** (review I7, advisor): if the current month recomputes about once per TTL under live data and that is acceptable, T3c goes to backlog BJ.
- **P12 Open for the owner (safe defaults taken).** Byte-equal (no tolerance), 30-second freshness, one worker, w26b gated by the R12 table, the grid engine parked.
- **Time line (advisor).** Code frozen by about 03:45; the full backend suite, the Playwright run, the browser review, one fix wave, the re-review and the merge need the rest; session ends about 06:33 and the merge order must not start with less than 30 minutes left. ## 6. Review focus
The brief's six points, plus: (a) a cache hit equals a cold compute bit for bit and the corpus is equal cold, warm and off; (b) no consumer mutates a shared entry or value; (c) the fingerprints see every input of a figure (rename two siblings, a scale, a tariff row, the zone, a mapping interval, late rows, a re-pointed mapping); (d) `require_fresh` on close; (e) a failed or cancelled shared computation; (f) the compute thread touches no `AsyncSession`; (g) the pool: no deadlock with 20 concurrent waiters; (h) every figure-side lookup uses the value's own tree and tariffs.
