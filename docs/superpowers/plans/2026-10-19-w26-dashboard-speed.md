## 2. Rulings that refine the brief (the ledger carries the same lines)
- **P1 Representation.** A shared hour grid per window (`buckets: list[datetime]`, ascending, regular UTC hours for a window read) and, per asset, one `Series` of parallel `array('d')`/`bytearray` columns (`kwh`, `present`, `est`, `has`) and, once priced, `cost` (`array('d')` plus a `priced` bytearray) and `unpriced`. Absence is a flag, not a value. Dense fast paths (`map(operator.add, a, b)` over whole columns) only where BOTH operands are fully present/priced; a per-element loop with the exact absent/None rules of today's code otherwise. Both are tested bit for bit against the oracle.
- **P2 Oracle.** `backend/tests/reference_engine.py` is today's `core/energy.py` + `core/cost.py` + `core/daycost.py` (and the `_fill_billing` window sum) copied UNCHANGED, renamed only by module path. Property tests compare new against oracle with `==` and `repr` on every float (so `-0.0` counts).
- **P3 Cache unit.** One entry per `(window start, window end, zone, config fingerprint)` holding the whole tree's energy grid, plus, once someone asked for cost, the priced grid for the same key (tariffs are in the key). Names, paths, `now`, day entries, closed snapshots: per request.
- **P4 The shared computation owns its session.** It runs as its own task with its OWN `AsyncSession` in one REPEATABLE READ transaction (config fingerprint, tree, meters, tariffs, data fingerprint and rows from one snapshot), so a cancelled first request cannot kill it and an entry is always consistent with its key. Waiters `await asyncio.shield(task)`.
- **P5 Fingerprints.** Config: one statement, md5 over the sorted text of `assets(id,parent_id,sort_order,name)`, the energy_kwh/active_power_kw `mappings(asset_id,point_id,metric,scale,interval_seconds)` and `tariffs(id,asset_id,rate_per_kwh,effective_from)`; the zone string joins the key in Python. Data: one aggregate over the metering points' rows of the window plus the baseline and first-bucket rows: `count(*)`, `min(bucket)`, `max(bucket)`, `sum(n)`, `sum(minutes)` and, for each float column, a sum of the built-in `hashfloat8(col)` cast to bigint (exact and independent of row order, unlike a float sum); the T3a implementer verifies `hashfloat8` exists in the test image and otherwise sums the columns cast to numeric.
- **P6 TTL.** `DCDASH_FIGURE_CACHE_TTL` seconds (default 30) and `DCDASH_FIGURE_CACHE=0` (off). `tests/conftest.py` gets an autouse fixture that sets the TTL to 0 (every request revalidates the data fingerprint) and empties the cache and the in-flight table before and after each test. Keep-warm (brief R6) is T3b: built after the core is committed.
- **P7 Close.** `close_month` and `month-check` call the cache with `fresh=True`: the data fingerprint is checked on the spot and the entry is used only if equal.
- **P8 Thread.** One module-level `ThreadPoolExecutor(max_workers=1)` in `dcdash/core/compute.py`; `await compute(fn, *args)` runs a PURE function (no `AsyncSession`, no request object). `sys.setswitchinterval(0.001)` is set at app start (T4 measures it before keeping it).
- **P9 Reads.** `hourly_energy` keeps its signature and runs ONE statement for all rows (meters are read by `load_meters`, a second); rows arrive in batches of about 5,000 through `AsyncSession.stream()` with `yield_per`, stored as tuples per point (no dataclass per row). `HourRow` becomes a `NamedTuple` ONLY if no test uses `dataclasses.replace/asdict/fields` on it (the implementer greps); else it stays a frozen dataclass and the fast path uses plain tuples.
- **P10 Open for the owner (safe defaults taken).** Byte-equal (no tolerance), 30-second freshness, one worker, w26b gated by the R12 table.
