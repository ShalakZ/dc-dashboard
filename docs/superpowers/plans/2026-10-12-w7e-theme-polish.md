**Goal:** After W7d the owner asked for four things (O-17 to O-20): a YouTube-style loading bar along the top edge in the theme's marker colour (O-17); buttons, links, hover and selection that take the chosen theme's colour instead of always blue (O-18); the profile panel's Mode and Theme colour as two dropdowns instead of seven radios (O-19); icons in the Assets workspace (O-20).

**Architecture:** Front end only. Nothing under `backend/`, no migration, no API change. (2) `ProfileMenu` swaps its two radio fieldsets for two labelled native `<select>`s plus a swatch chip. (3) `src/lib/kindIcon.ts` maps a kind text to an `IconName`; fifteen new inline-SVG icons go into `Icon.tsx` and are placed in the tree, the asset header, the summary page, the tiles and the quick find. (4) `src/lib/progress.ts` is a small timer-driven state machine with a store; `TopProgress` (mounted in `Layout`) feeds it from the route, React Query and Suspense fallbacks and draws a 3 px bar with CSS transitions.

**Tech Stack:** React 19, react-router 7, TanStack Query 5, plain CSS (`@layer w6` plus the unlayered `themes.css`), Vitest + Testing Library, Playwright (controller only).

7. **Loading bar.** `src/lib/progress.ts` exports `createProgress(timers?)` and the singleton `progress`; phases `idle | reset | run | finish | fade`; sources `fetching | mutating | pending` (counts) plus `pulse()` (a navigation). Constants: `SHOW_DELAY_MS = 120`, `MIN_SWEEP_MS = 400`, `SETTLE_MS = 100`, `FINISH_MS = 150`, `FADE_MS = 200`. Rules: with no `attach()` (no bar mounted) it never leaves `idle` and starts no timer; `attach()` re-evaluates the counts at once (a count set while detached, for example before the bar's own attach effect or after StrictMode's remount, must still show). Counts above zero arm a SHOW_DELAY timer in `idle`; if the counts reach zero first, nothing ever shows. `advance()` does nothing outside `reset`. `getCount(source)` exists for the tests. `pulse()` shows at once (no delay) and holds the bar at least MIN_SWEEP_MS (a pulse while running restarts the hold). While wanted (counts above zero or a hold) in `run`, nothing changes; when not wanted, wait SETTLE_MS of continuous quiet (chained loads, a lazy chunk and then its queries, would otherwise finish and restart), then `finish`, FINISH_MS later `fade`, FADE_MS later `idle`. Wanted again in `finish` or `fade`: go to `reset`; the component forces a style flush (`void el.offsetWidth` in a layout effect) and calls `advance()`, which moves `reset` to `run`, so the restart begins at zero without sweeping backwards. The last `detach()` clears every timer and returns to `idle`; counts survive a detach (they belong to their sources). `add(source)` returns an idempotent remove (used by `Pending`, safe under StrictMode's mount, unmount, mount). `getPhase`/`subscribe` feed `useSyncExternalStore`. No `requestAnimationFrame` loop, no timeout on a long load (it waits at 85 percent).
   `TopProgress` (`{ store = progress }`): a `useLocation().pathname` that differs from a `useRef` holding the previous pathname calls `pulse()` (a "skip the first run" flag would fire on StrictMode's second mount); `useIsFetching({ predicate })` with a module-level predicate `(query) => query.state.data === undefined` (INITIAL loads only, so polling and background refetches never show; verified in the plan review: it counts the retry wait and an error ends it) feeds `setCount("fetching", n)`; `useIsMutating()` feeds `"mutating"`. The counts are set to 0 only in ONE unmount effect (`useEffect(() => () => { setCount("fetching", 0); setCount("mutating", 0); }, [store])`), never in the cleanup of the effect that sets them (that would cancel and restart the 120 ms delay each time a query joins). `Pending` (`{ store = progress }`) does `useEffect(() => store.add("pending"), [store])` and renders nothing; it goes into the Suspense fallbacks of the two lazy routes in `App.tsx` (the shared `loading` element), the chart in `AssetPage` and the editor in `DashboardPage` (their texts "loading chart…" and "loading editor…" stay), and `HomeRedirect`'s `loading` return. `Layout` mounts `<TopProgress />` OUTSIDE `.shell`, immediately before it next to the skip link: `Layout.test.tsx` pins `.shell`'s children to exactly `HEADER.navbar` and `DIV.frame`; the bar is fixed-position so its place in the markup changes nothing on screen. `WidgetBody`'s lazy widgets are not touched (the widgets are out of scope).
   CSS (`@layer w6`, tokens only): `.top-progress { position: fixed; inset: 0 0 auto 0; height: 3px; z-index: 46; pointer-events: none }` (46: above the top bar 45, below the sidebar tip 50, the pop-ups and the dialogs at 1000), its child `span` is `background: var(--side-accent)`; per `data-phase`: `idle` width 0, opacity 0, no transition; `reset` width 0, opacity 1, no transition; `run` width 85%, opacity 1, `transition: width 30s cubic-bezier(0, 0.9, 0.1, 1)` (about 38 percent after half a second, 71 percent after five seconds, 85 at the end: tune by eye in the mid-load capture, keep ONE transition); `finish` width 100%, opacity 1, `transition: width 150ms ease-out` (a running transition is replaced from its current value); `fade` width 100%, opacity 0, `transition: opacity 200ms linear`. `@media (prefers-reduced-motion: reduce)`: width 100% in every phase, no width transition, opacity 1 in `reset`, `run` and `finish`, 0 in `idle` and `fade`. `app.css` already has a universal `transition: none !important` for reduced motion inside the layer, which beats these rules, so the fade is instant; accepted (the plan review measured it). The element is `aria-hidden="true"`, has no role and announces nothing. The selector never contains `.navbar` or `.side` (the `app.css.test.ts` accent check).
