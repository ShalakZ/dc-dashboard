## 2. Contract pinned by this plan (server and client both build to it)
**Config.** `WidgetConfig.scope: "fixed" | "focus" | "children"`, default `"fixed"`, dropped from the stored dump at its default (`_without_defaults` gains `("scope", "fixed")`). Rules (`_check_type_rules`): a following scope (`!= "fixed"`) needs `assets == []` (422 `assets: leave the assets empty; the focus chooses them`) and skips the "choose at least one asset", "exactly one asset" (stat, gauge, compare) rules; `children` only for `timeseries`, `bar` (bars `asset` or `time`) and `table` (else 422 `scope: ...`), never with `compare` or `bars: "kind"`; `focus` with `bars: "kind"` needs `root` unset (422 `root: ...`); all other existing messages keep their text and order for `fixed`.
**Request.** `WidgetDataRequest.focus: StrictInt, 1..2147483647 | None = None` (extra stays forbidden; the client leaves the key OUT when null). A request carrying `focus` needs `assets.view` (`user.can`, else `HTTPException(403, INSUFFICIENT_PERMISSION)`), checked first, also for a fixed widget. `focus` is ignored by a `scope: "fixed"` widget (its block is `null`).
**Answer.** `WidgetData.focus: null | {asset: {id, name, path} | null, state: "ok" | "gone" | "choose", children: {shown, count} | null, top_level: int | null}`. Resolution (`core/widgets.py::_resolve_focus`, pure, over the tree `compute_widget` already loads; then the unchanged paths run on a resolved copy `config.model_copy(update={"scope": "fixed", ...})`):
- `focus` given and not in the tree: `{asset: null, state: "gone"}`, `missing = [focus]`, nothing computed (a deleted and a never-existing id: byte-identical answers).
- No `focus`: ONE top-level asset means that asset is the target (R5); otherwise `focus` scope on a breakdown looks at the whole site (`root` None, state ok, `top_level` = N), `focus` scope on any other type answers `{asset: null, state: "choose", top_level: N}` and nothing, `children` scope lists the top-level assets (asset null, `children` = shown/count of them, `top_level` N).
- Target `T`: `focus` scope: `assets = [T]` (breakdown: `root = T`, assets `[]`); `children` scope: the first `MAX_ASSETS` of `tree.children(T)`, `children = {shown, count}`; a leaf: shown 0, count 0, nothing computed.
- `empty` results skip the fill functions (`unit`/`metric` stay null; the client draws a sentence from `focus.state`).
**Create.** `DashboardIn.recipe: Literal["power"] | None = None`. With `recipe == "power"`: `core/recipes.py::power_widgets(...)` returns widget dicts; every one passes `validate_config`; dashboard, widgets and ONE `dashboard.created` audit row (`detail` = Blank's keys plus `"recipe": "power"` and the real `widgets` count) are written in one transaction; the dashboard `range` is the body's (the dialog preselects This month for Power). Blank (no `recipe`) is byte-for-byte today's.
**Client (api/types.ts).** `WidgetScope`, `WidgetConfig.scope?`, `WidgetFocus`, `WidgetData.focus?`, `DashboardIn.recipe?: "power"` (the S0 scaffold commit).
**Cache and body.** `useWidgetData(type, config, preset, enabled = true, focus: number | null = null)`: key `[...keys.widgetData, type, config, preset]` when `focus === null`, else `[..., focus]` appended; body `{type, config, range}` plus `focus` only when non-null; `placeholderData` rule unchanged (it reads `before[1]`, `before[2]`). `WidgetView` passes a focus ONLY when `config.scope` is `focus`/`children` and the context holds one; the CSV source and the Details panel carry the same `focus` key (left out when null).
**Focus context** (`components/dashboard/FocusContext.tsx`, T3a): `{focus: number | null, allowed: boolean, assets: Asset[] | undefined, name: string | null (the focus asset's name), notice: string | null, setFocus(id | null), reportGone(id)}`; default value (no provider: unit tests of a lone `WidgetView`) is `{focus: null, allowed: false, ...}`. `FocusProvider` wraps viewer AND editor in `DashboardScreen` (`pages/DashboardPage.tsx`). Rules: `?asset=` is read only with `can("assets.view")`; without it the parameter is ignored and `notice` is R3's sentence; digits only (`/^[1-9]\d*$/`), else R4's gone sentence and `replace` clear; the asset list (`useAssets`) is requested only when an `asset` parameter is present, the dialog is open or a breakdown needs it (drill-through, T5); `setFocus` PUSHES `?asset=<id>` (`null` pushes the bare path), keeping other parameters and `location.state`; list loaded and the id absent, or an answer with `focus.state === "gone"` (`reportGone`), clears with `replace` and sets R4's sentence; list loaded, ONE top-level asset and `focus` equals it: cleared with `replace`, no sentence (R5). Widgets never wait for the list.
**Styles.** Three new files, created empty in S0 with their `main.tsx` imports so parallel tasks never share a stylesheet: `styles/focus-follow.css` (T3b: dimming, the quiet line), `styles/focus-header.css` (T4, T5), `styles/start-from.css` (T7).
