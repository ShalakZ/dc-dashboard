# w32 System events Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the system's own journal (`diag_events`) a page of its own, make a source's trouble ONE counted incident instead of repeated rows, show a long outage on Sources, and link each "started a check" audit entry to how the check ended.

**Architecture:** No migration. An incident is the existing `source.offline` / `points.bad` journal row whose open `detail` gains `state`, `count`, `last_at`, ...; a per-source `IncidentBook` in the collector (new `collector/incidents.py`, one background writer, never awaited on the poll path) opens, bumps (at most once a minute) and closes it, and closes the incidents of sources that are no longer polled. New read code lives in a new package `dcdash/events/` and a new router `api/events.py`; nothing under `core/` changes (so no engine-id change and no "figures recomputed" sentence). The front end gets one page (`/events`) in the Audit page's style, a banner on Sources, an Outcome row in the Audit drawer and a card on Storage.

**Tech Stack:** Python 3.12, FastAPI, asyncpg/SQLAlchemy, Postgres/Timescale JSONB; React 19, TypeScript, React Query, vitest, Playwright.

**Spec:** `.waves/w32.md` (the brief; its rulings R1-R11 are binding unless this plan says "Ruling P#"). Plan review: `.waves/w32/plan-review.md` (Opus, 0 Critical, 11 Important, 17 Minor, all folded in below, see "Review fold-in"). Tier: **M** (Ruling P1).

## Facts checked in the code (main 717a979) and corrections to the brief
Everything in the brief's "What the supervisor verified" was re-read and holds, except:
1. **`config_invalid` / `secret_undecryptable` do not repeat "every 600 s".** They run only when `reload` runs and are gated to once per 600 s per source; a never-edited source journals them once per collector start. After the change a reload bumps the count instead.
2. **Two job kinds end in the journal differently.** `source.tested` and `source.test_all` enqueue `test_source` jobs (`api/sources.py:416,432`): their end is `job.finished` (`detail.ok`, `detail.status`, `detail.error`). `source.checked` enqueues `check_connection`: `check.finished` when the job is `done`, `job.finished` when `failed`. `fail_stale_jobs` (a collector restart mid-job) and a dropped/timed-out journal write leave a finished job with NO journal row.
3. **`audit_log` has no index on `ts` or `detail`** (0001: `id` primary key only). The reverse link searches `ORDER BY id DESC LIMIT 1`, and only for jobs an audit action starts (`check.finished`, or `job.finished` with `detail.kind` in `test_source`, `check_connection`); the audit page's outcome query narrows the journal by `kind` and `ts >= min(ts of the page)` on `diag_events (ts)`.
4. `sources.status` defaults to `unknown`; `mark_source(online)` refreshes `last_seen` every 10 s while online; a failed Test, a scan, or a removed last mapping can leave `status = offline` on a source nobody polls.
5. Routers are registered in the tuple in `api/main.py:140`; every route needs a row in `tests/auth_expectations.py` (`_all(...)`), `tests/test_route_gates.py` checks one gate per route. Routes of R4 are `diagnostics.view` ONLY (R3: the page, not the routes, also needs `sources.view`).
6. `diagnostics/report.py::_journal` reads the newest 300 (summary) or 1,000 (full) journal rows by `ts`, and per-source "errors:" lines come from them: an incident opener whose `ts` never moves would fall out of the report (Task 1b merges the open incident rows in).
7. `formatSpan` (`frontend/src/lib/age.ts:5`) gives one unit (`45 s`, `3 min`, `5 h`, `2 d`). The brief's `4 d 2 h` needs `formatSpanLong` (added in Task 4a). Python `format_span`: under a minute `45 s`, under an hour `3 min`, from an hour two units with a zero second unit dropped (`2 h 5 min`, `2 h`, `4 d 2 h`, `4 d`).
8. Connector failure codes reach `source.offline` as `code`: the seven of the brief plus `needs_profile` (`connectors/modbus.py:141,147`); the parity test collects every `ConnectorError("<status>"` literal under `connectors/`.
9. Could NOT verify: the owner's journal size; real SCADA error texts. Row size: measured on the scratch stack (ledger).

- **P1 Tier M** (brief): no migration, no money path, no new permission. Costs if wrong: no measured "before" line in the CHANGELOG.
- **P3 One writer per book.** Incident writes are not `journal.record_soon` calls: `IncidentBook` owns ONE background task that takes dirty sources one at a time (coalescing per source, like `_StatusWriter`), each write a single SQL statement through `pool.fetch`, so order per source is guaranteed, the pool never gives it more than one connection, a frozen database never delays a poll, and no MAX_PENDING flood happens at start. Bumps are not rate limited (throttled to 60 s per incident). Flapping sources (up/down every few seconds) still write two rows per flap: parked in BQ.
- **P4 No seeding query; the database is the truth.** `open_or_bump` updates the newest open row of `(kind, source)` else inserts; `close_open` closes every open row of `(kind, source)`; counts increment in SQL (`count + inc`), so a restart continues the real count. In memory each `(source, kind)` has a phase `unknown` (collector just started) / `open` / `closed`, and each poll group (key = interval; `SETUP` = -1 for a setup failure) has a state `pending` (a task for it was just (re)started, nothing reported yet) / `troubled` / `ok`. **A close needs: no key `troubled`, no key `pending`, at least one key `ok`, phase `unknown` or `open`.** Phase `unknown` + all reported ok runs ONE `close_open`, silent when nothing was open ("a start with no open incident journals nothing"). (Review I1.)
- **P5 "True start", `source.offline` only.** The INSERT branch of `open_or_bump` for kind `source.offline` sets `detail.since = sources.last_seen` when the stored `sources.status` is already `offline` and `last_seen` is not null. `points.bad` never has `since`. Durations are `now() - COALESCE((detail->>'since')::timestamptz, ts)`; `incident.first_at` is the same value. (Review I6.)
- **P6 Recovery text is UTC.** The collector does not know the site zone: `back online after 4 d 2 h; 1,204 failed reads counted since 22 Oct 10:06 UTC` (the date is the opener row's `ts`, when counting began; the duration counts from `since` when there is one); the page builds its own headline from the structured fields in the site zone. One recovery row per `close_open` call (earliest first_at, summed count), even when overlapping processes left two open rows. (Review minor 4, 16.)
- **P7 `offline_since` contract:** while `status == "offline"`, the earlier of (the open `source.offline` incident's `since`, else its `ts`) and `last_seen`, ignoring nulls; `null` when the source is not offline or has neither. `failed_reads` is the open incident's `count`, else null. The banner shows for an enabled source with `polls` true AND `mapped_points > 0` AND `status == "offline"` AND `offline_since` older than 2 minutes (`OFFLINE_BANNER_SECONDS = 120`); it says `has not answered since it was added` when `last_seen` is null. (Review I10.)
- **P8 One incident per (source, kind); the row says how it stands now.** A bump updates `level`, `code`, `message` and `detail.last_error`; the INSERT also stores `first_code` and `first_error` (the cause that opened it); `ts` never changes. For `points.bad` the book keeps each group's latest summary (`bad`, `total`, `statuses`, `sample`) and composes the source's message and detail at write time (bad and total summed, statuses merged, sample cut to 5); the recovery total is the sum of the groups' last totals. (Review I7.)
- **P9 The detail cap never cuts the incident keys.** `state`, `count`, `last_at`, `since`, `first_code`, `first_error`, `last_error` (<= 200 chars), `interval`, `closed_*` are always stored; the extra keys (`statuses`, `sample`, ...) are cut to fit `journal.MAX_DETAIL_BYTES` minus 800 (first `sample`, then `statuses`, then all extras become `{"extras_truncated": true}`). (Review I5.)
- **P10 Writer failure rules.** The writer snapshots `inc` when it starts a write and subtracts it only on success; phase and `last_write` change only on success; a failed write leaves the source NOT dirty (the next `trouble`/`clear` marks it again: the poll cadence is the retry cadence, no hot loop); the `reconcile` write stays queued and is retried every 5 s until it succeeds; `close()` cancels in two rounds with `asyncio.wait(timeout=1)` each (as `journal.cancel_pending`), is idempotent (`_close_down` may call `scheduler.stop()` twice), and a private book made by `run_group` is closed in its `finally`. (Review I4, minor 5.)
- **P11 Reconcile is database truth, after the cancels.** `Scheduler.reload` calls `book.sync(...)` AFTER `_cancel(stale)` and BEFORE creating the new tasks; `sync` (synchronous) marks the restarted/new keys `pending`, drops keys that are no longer wanted, marks sources with no wanted key (and no setup failure this round) as stopped (their pending increments and dirty marks are dropped, `trouble` for them is ignored until they come back), and queues ONE statement in the writer: close every open `source.offline` / `points.bad` row whose `source_id` is not in the kept set (polled plus setup-failing) with `closed_by: "polling_stopped"` and no recovery row. It runs on the first reload too (a source disabled or deleted while the collector was down). A group task that ends by itself (`config_invalid`) keeps its key `troubled`. Tasks do not attach or detach; `trouble`/`clear` on an unknown key register it. (Review I1-I3.)

### Task 1a: `IncidentBook` - per-task Opus review after 1b

**Files:** Create `backend/dcdash/collector/incidents.py`, `backend/tests/test_incidents.py`.

**Interfaces (produces):**
```python
KINDS = (journal.SOURCE_OFFLINE, journal.POINTS_BAD)
BUMP_EVERY_SECONDS = 60.0
SETUP = -1                                    # the pseudo group key of a setup failure (secret_undecryptable)
def format_span(seconds: float) -> str        # P6/fact 7: "45 s", "3 min", "2 h 5 min", "2 h", "4 d 2 h", "4 d"
class IncidentBook:
    def __init__(self, pool, *, clock=time.monotonic) -> None            # the writer task starts lazily at the first dirty mark
    def trouble(self, source_id: int, key: int, kind: str, *, code: str | None, message: str, known: Sequence[str] = (),
                level: str = "warning", detail: Mapping[str, Any] | None = None) -> None   # a poll of group `key` is in trouble of `kind`
    def clear(self, source_id: int, key: int, kind: str, *, known: Sequence[str] = (), total: int | None = None) -> None  # a poll of group `key` had none
    def setup_failed(self, source_id: int, *, code: str, message: str, known: Sequence[str]) -> None    # = trouble(SETUP key, SOURCE_OFFLINE); also adds the source to this round's setup-failing set
    def begin_reload(self) -> None                                        # clears this round's setup-failing set
    def sync(self, wanted: Mapping[tuple[int, int], Sequence[str]], restarted: Collection[tuple[int, int]]) -> None  # P11; wanted = {(source, interval): known}
    async def close(self) -> None                                         # P10: two cancel rounds, idempotent
```
`trouble` and `clear` are synchronous, cheap and never raise. `trouble`: set the key's state `troubled` for `kind`, `inc += 1`, remember the latest text/known/summary, mark the source dirty when `phase != open` or `clock() - last_write >= BUMP_EVERY_SECONDS` (ignored for a stopped source). `clear`: set the key `ok`; when the close rule of P4 holds, mark the source dirty for a close.
**Writer statements** (single statements through `pool.fetch`, `asyncio.timeout(3)`, explicit casts on every parameter inside `jsonb_build_object` such as `$6::bigint`, `$7::text`, `$8::jsonb`; skeleton: `WITH t AS (SELECT id ...
