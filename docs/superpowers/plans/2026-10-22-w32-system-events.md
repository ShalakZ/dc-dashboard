# w32 System events Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the system's own journal (`diag_events`) a page of its own, make a source's trouble ONE counted incident instead of repeated rows, show a long outage on Sources, and link each "started a check" audit entry to how the check ended.

**Architecture:** No migration. An incident is the existing `source.offline` / `points.bad` journal row whose open `detail` gains `state`, `count`, `last_at`, ...; a per-source `IncidentBook` in the collector (new `collector/incidents.py`, one background writer, never awaited on the poll path) opens, bumps (at most once a minute) and closes it. New read code lives in a new package `dcdash/events/` and a new router `api/events.py`; nothing under `core/` changes (so no engine-id change and no "figures recomputed" sentence). The front end gets one page (`/events`) in the Audit page's style, a banner on Sources, an Outcome row in the Audit drawer and a card on Storage.

**Tech Stack:** Python 3.12, FastAPI, asyncpg/SQLAlchemy, Postgres/Timescale JSONB; React 19, TypeScript, React Query, vitest, Playwright.

**Spec:** `.waves/w32.md` (the brief; its rulings R1-R11 are binding unless this plan says "Ruling P#"). Tier: **M** (Ruling P1).

Costs if wrong: the CHANGELOG has no measured "before" line.
- **P3 One writer per book.** Incident writes are not `journal.record_soon` calls: `IncidentBook` owns ONE background task that takes dirty sources one at a time (coalescing per source, like `_StatusWriter`), each write a single SQL statement through `pool.fetch`, so order per source is guaranteed, the pool never gives it more than one connection, a frozen database never delays a poll, and no MAX_PENDING flood happens at start. Bumps are not rate limited (throttled to 60 s per incident); openers and closers are bounded by the incident itself. Flapping sources (up/down every few seconds) still write two rows per flap: parked in BQ.
- **P4 No seeding query.** The writer's statements are idempotent on the database's truth (`open_or_bump` updates the newest open row of `(kind, source)` else inserts; `close_open` closes every open row of `(kind, source)`). In memory a source's phase is `unknown` (collector just started) / `open` / `closed`; the first not-troubled observation in `unknown` runs ONE `close_open` (no-op when nothing is open, silent when nothing was open: "a start with no open incident journals nothing"). Counts increment in SQL (`count + inc`), so a restart continues the real count.
- **P5 "True start".** The INSERT branch of `open_or_bump` sets `detail.since = sources.last_seen` only when the stored `sources.status` is already `offline` (and `last_seen` is not null); durations are `now() - COALESCE((detail->>'since')::timestamptz, ts)`.
- **P6 Recovery text is UTC.** The collector does not know the site zone: `back online after 4 d 2 h; 1,204 failed reads since 18 Oct 07:52 UTC`; the page builds its own headline from the structured fields in the site zone.
- **P7 `offline_since` contract** (R7 made exact): while `status == "offline"`, the earlier of (the open `source.offline` incident's `since`, else its `ts`) and `last_seen`, ignoring nulls; `null` when the source is not offline or has neither. `failed_reads` is the open incident's `count`, else null. The banner says `has not answered since it was added` when `last_seen` is null. The banner condition is an enabled source with `polls` true and `status == "offline"` and `offline_since` older than 2 minutes (`OFFLINE_BANNER_SECONDS = 120` in `lib/eventText.ts`).
- **P8 One incident per (source, kind); the row says how it stands now.** A bump also updates `level`, `code`, `message` and `detail.last_error` (the reason can change from `unreachable` to `auth_failed`); the opener's `ts` never changes. `points.bad` bumps overwrite the status detail with the newest poll's.

```
SystemEvent = { id, ts: iso, level: "info"|"warning"|"error", component: string, source_id: number|null,
                source_name: string|null, source_deleted: boolean, kind: string, code: string|null, message: string,
                detail: object, incident: Incident|null }   // message and detail go through scrub_strings at read

   -> { items: SystemEvent[], next: string|null, total: number }      // newest first by (ts, id); open=1 -> only open incidents
GET /api/events/{id}  -> SystemEvent & { started_by: {audit_id, username: string|null, ts: iso}|null }  // started_by only with audit.view and only for check.finished / job.finished of a job an audit entry started
GET /api/events/options -> { kinds: string[], sources: {id, name}[] }   // name "deleted source #3" for a gone one

GET /api/settings/events (storage.view) -> { retention_days, max_rows, factory: {retention_days: 90, max_rows: 100000},
                                             bounds: {retention_days: [7,400], max_rows: [10000,1000000]}, kept, oldest: iso|null }
PUT /api/settings/events?confirm=true (storage.edit) body { retention_days, max_rows } -> same shape as GET
   shortening that would delete rows without confirm -> 409 { detail, deletes_now: number }; audited events.retention_changed {before, after, deleted_now?}
GET /api/sources items gain  offline_since: iso|null, failed_reads: number|null
GET /api/audit and /api/audit/{id} items gain  outcome: null | { state: "passed"|"failed"|"running"|"gone", text: string,
      event_id: number|null, counts: {passed, failed, running, gone}|null }   // only for source.tested / source.checked / source.test_all
```
`state` for several jobs (`test_all`): `failed` if any failed, else `running` if any running, else `passed` if all passed, else `gone`; `text` is `3 passed, 1 failed` (omit zeros). **Interfaces (produces):**
```python
KINDS = (journal.SOURCE_OFFLINE, journal.POINTS_BAD)
BUMP_EVERY_SECONDS = 60.0
def format_span(seconds: float) -> str            # "45 s", "3 min", "2 h 5 min", "4 d 2 h" (two units from minutes up)
class IncidentBook:
    def __init__(self, pool, *, clock=time.monotonic) -> None          # starts nothing until first use; one writer task, created lazily
    def attach(self, source_id: int, key: int, known: list[str]) -> None   # a group (key = interval) starts; remembers `known`
    def detach(self, source_id: int, key: int) -> None                 # a group's task ended (any reason): forgets its troubled flag, never closes
    def trouble(self, source_id: int, key: int, kind: str, *, code: str|None, message: str, level: str = "warning", detail: Mapping|None = None) -> None
    def clear(self, source_id: int, key: int, kind: str, *, total: int | None = None) -> None     # a poll of group `key` had no trouble of `kind`
    def setup_failed(self, source_id: int, *, code: str, message: str, known: list[str], detail: Mapping|None = None) -> None  # load_groups: secret_undecryptable
    def begin_reload(self) -> None
    async def reconcile(self, polled: Collection[int]) -> None         # open incidents of sources not in polled | setup-failing -> closed_by "polling_stopped"
    async def close(self) -> None                                      # cancel the writer (like _StatusWriter.close)
```
`trouble` is synchronous and cheap: it sets the group's troubled flag for `kind`, `inc += 1`, remembers the latest text, and marks the source dirty when `phase != open` or `clock() - last_write >= BUMP_EVERY_SECONDS`. `clear` removes the group's flag; if no group of `(source, kind)` is troubled and `phase in (unknown, open)` it marks dirty for a close (`phase` becomes `closed` after the write). The writer's two statements (both through `pool.fetch`, 3 s `asyncio.timeout`, never raise, log once per streak):
- `open_or_bump(kind, source_id, level, code, message, inc, detail)`: update the newest open row of `(kind, source_id)` setting `level`, `code`, `message` and `detail = detail || new` with `count = count + inc`, `last_at = now()`, `last_error`; else insert `{state: "open", count: inc, last_at, since?}` (P5). One statement, `RETURNING id`.
- `close_open(kind, source_id, closed_by, inc)`: update EVERY open row of `(kind, source_id)` to `state: "closed", closed_at: now(), duration_seconds, closed_by, count + inc`, `RETURNING id, source_id, kind, ts, detail`. For `closed_by == "recovered"` and a row that was open, then write the recovery row through `journal.record` (kind `source.online` / `points.recovered`, `detail = {incident_id, offline_seconds | bad_seconds, failed_reads | polls_with_bad_readings, interval}`, message per R5/P6, e.g. `back online after 4 d 2 h; 1,204 failed reads since 18 Oct 07:52 UTC`, `all 12 points read good again after 3 min`).
All text is scrubbed with the book's `known` for the source and cut like the journal (`journal.MAX_MESSAGE_CHARS`, `MAX_DETAIL_BYTES`) using the public helpers of `core.audit` (`scrub_url_credentials`, `clip_error`, `scrub_strings`, `plain`); `last_error` is clipped to 200 characters.
