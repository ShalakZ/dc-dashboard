## Review Focus

1. **A Change permission ticked without its See** (for example only `assets.edit`): the server accepts it, the person gets an empty sidebar or "no pages yet". The editor must say which See is missing, in words, before Save (Task 3: `permissionGaps`, tested).
2. **Role names that the server refuses** (same name in another case, a built-in's name or label, 65+ characters, only spaces): the dialog stays open with what was typed and shows the server's sentence; nothing is lost (Task 3 tests with mocked 409 and 422).
3. **A role that stops being deletable between page load and click** (someone gave it to an account): the 409 text is shown, the row stays, the list refreshes (Task 3).
4. **A permission id this build does not know** (newer server): the editor renders it from `GET /api/permissions`, keeps it ticked on save, and the page summary ignores it (Task 3).
5. **Keyboard only, and a reload**: the tab strip works with Arrow keys, Home and End; `/users/roles` survives a reload and the Back button; Escape closes the editor and the focus returns to the button that opened it; a person without `roles.manage` at `/users/roles` sees "No access", never a blank page (Task 4).

## Rulings taken while planning

- **R1 Editor = a large `Modal`, not a page or drawer.** The Drawer arrives in W7l; Modal already gives focus trap, Escape and focus return. Cost if wrong: the owner may prefer a side panel; swapping the container is a small change.
- **R2 Duplicate uses the server route** (`POST /api/roles/{id}/duplicate`, audit says `copied_from`), then opens the copy in the editor. Cancel keeps the copy (a real role, deletable). **New role** with "Start from Viewer/Operator" pre-ticks client-side and saves with `POST /api/roles`. Cost if wrong: a cancelled Duplicate leaves a "Copy of ..." role behind.
- **R3 Grid = one row per catalogue area, columns See and Change** (a cell may hold several checkboxes), then a **Sensitive actions** fieldset for every `risky` permission except `roles.manage` (shown only as a locked line "Managing roles is held by the Administrator role only", and ticked-and-disabled in the read-only view of the built-in Admin).
- **R4 Dependencies are hints, never auto-ticks** (`PERMISSION_NEEDS`), because the server accepts any combination and a role may be deliberately odd.
- **R5 The summary reuses the sidebar's own logic** (`visibleGroups`), so "Opens" is exactly the menu that person will see.
- **R6 URL and breadcrumb:** one route `/users/:tab?` (`undefined` = Users, `roles` = Roles, anything else = the Not found page); trail `Users & Roles / Users` or `Users & Roles / Roles`, the first part a link to `/users`. A person with `roles.manage` but not `users.view` is redirected (replace) from `/users` to `/users/roles` (theoretical today: only Admin holds `roles.manage`).
- **R7 `Need` gets an any-of form** `{ any: [...] }` for the page gate `users.view` OR `roles.manage`.
- **R8 The Tariffs page needs `["tariffs.view", "assets.view"]`** and reads the currency through `GET /api/settings/billing`, which Task 1 opens to `tariffs.view` (PUT stays `tariffs.edit`). This is the only cell of the frozen matrix that changes (Operator: 403 to pass); Task 1 records it as a named exception in the test, never in the fixture.
- **R9 Last-write-wins on a role edited by two admins** is not guarded (no version check on `PATCH /api/roles/{id}`); parked in the backlog with this reason: only Admin can edit roles and the audit log records both saves.
- **R10 No new endpoints.** The editor and the lists use the five role routes and `GET /api/permissions` as they are.
