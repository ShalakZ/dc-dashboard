## Facts checked in the code (LESSONS A12: the brief is not law)

- **The canvas today.** `pages/DiscoveryPage.tsx` (537 lines): `Canvas` holds `open` (sources/clusters), `moved` (this session's places), the W7t drag snapshot (`onNodeDragStart/Drag/Stop`, followers, Alt), `seeded = useMemo(buildGraph + nodeData)` and an effect that `setNodes(seeded.nodes)` keeping only `measured`. `ReactFlow` gets `Controls` and `Background`, `fitView` + `fitViewOptions={opening}` (from `initialView`), `minZoom 0.2`, `nodesConnectable={false}`, `edgesFocusable={false}`. `useReactFlow()` is used for `getIntersectingNodes/getNodes/fitView`. `afterPaint()` (two animation frames) is the existing "nodes are in the store" wait; `refit()` uses it.
- **Rebuilds drop `selected`.** The effect copies `measured` only, so a rebuild (expand, collapse, a refresh) loses a selection. A box selection must survive them: copy `selected` too.
- **Edges.** `buildGraph` (`lib/graph.ts`) makes `link()` edges (`e:` source->group->point, DASHED inline style `strokeDasharray: "6 4"`), `mappedLinks()` (`m:` point/group/source -> asset, solid) and asset->sub-asset (`a:`). React Flow's library CSS animates `.react-flow__edge.animated path` with `dashdraw` (period 10: the inline "6 4" is 10 as well, so the loop is seamless). That CSS is UNLAYERED and our rules live in `@layer w6`: an unlayered rule beats a layered one, so a reduced-motion override must be `animation: none !important` (a layered `!important` beats an unlayered normal rule). The same applies to every rule that restyles a library class (minimap, selection box).
- **Reduced motion today.** `app.css:673` sets `transition: none !important` for everything under `prefers-reduced-motion: reduce`; it does NOT stop animations. Every new keyframe animation needs its own `@media (prefers-reduced-motion: reduce)` rule, and the JS must not start what the CSS would stop (camera duration 0, `animated` off).
- **Keyframes in the CSS guards.** `app.css.test.ts` lets `@keyframes` steps (`from`, `to`, `50%`) pass the "selector names a class" rule, requires one page class per page file (the clash test: a class written bare in one style file and named in another fails), and tokens only inside `@layer w6`. New style files: `styles/graph-nodes.css` and `styles/graph-tools.css` (imported in `main.tsx` like the others).
- **Node sizes are load-bearing.** `SOURCE_H = 136` + `BLOCK_GAP = 40` and `ROW = 64` were measured for the 220 px nodes (graph.ts:50-60); `w7r.spec.ts:899-940` pins the first source's title AND its Create assets button inside the canvas at 1024x640. So the status dot, the protocol badge and the progress bar add NO height: the dot and the badge replace words in the existing facts line (`{connector_type} · {origin} · {status} · N points`), the progress bar is an absolutely positioned 3 px strip on the cluster's bottom edge.
- **Statuses.** The collector writes `online` / `offline` (`collector/scheduler.py:59,64`); a source never polled has another value (`unknown` in the fixtures). Connector types: `simulator`, `modbus`, `opcua` (`connectors/*.py`); there is no HTTP connector yet, an unknown type shows its raw name.
- **Ctrl+K is taken.** `components/QuickFind.tsx:41-52` listens on `document` for Ctrl/Cmd+K (not with Alt or Shift), skips when `[aria-modal="true"]` exists, and focuses the top bar's quick find. React's `onKeyDown` runs at the root container, BELOW `document`, so a handler on the canvas wrapper that calls `event.stopPropagation()` keeps the event from the quick find. That is the whole conflict rule (Decision 8): focus inside `.graph-canvas` -> Find; anywhere else -> the global quick find, untouched.
- **A click on empty canvas gives no focus.** React Flow's pane is not focusable, so "while the canvas has focus" would be true only after Tab. `.graph-canvas` gets `tabIndex={-1}` (programmatic focus target, no ring) so a click on the pane focuses the wrapper.
- **Menu primitives.** `RowActions` (`components/RowActions.tsx`) is bound to a trigger button; its look is `.row-menu-panel` (`app.css:282-286`), its placement `placePanel(box, size, viewport, gap, inset)` (a `Box` is `{top,left,right,bottom}`: a point is a box with equal edges), its Escape rule is `usePopover`'s capture-phase `stopPropagation` (a pinned popover or one with the focus swallows the key, so a dialog around it stays). A right-click menu has no trigger, so `GraphContextMenu` re-implements the keyboard rules (ArrowUp/Down wrap, Home/End, Tab closes) and reuses the class, `placePanel` and the `RowAction` type. `InfoTip` takes children and a label (default "What does this mean?").
- **Role gating is already in the node data.** `nodeData()` (DiscoveryPage.tsx:76) adds `onMap/onNewAsset/onCreateAssets/onRemove` only when the role may use them and the node qualifies. A menu built from the SAME callbacks in `node.data` is gated exactly like the buttons, by construction.
- **Unit-test mock.** `DiscoveryPage.test.tsx:21-95` replaces `ReactFlow` with a plain div (no `children`, no `Panel`), `useReactFlow` with three functions, `Controls`/`Background` with null. New code uses `setCenter/setViewport/getViewport/getZoom`, `useStore`, `Panel`, `MiniMap`, `ViewportPortal`, `onNodeMouseEnter/Leave`, `onNodeContextMenu`, `onPaneContextMenu`: the mock grows (T5 owns it), and the new pieces are separate components with their own tests.
- **Hint.** `HINT` (DiscoveryPage.tsx:30) is used twice (loading branch and canvas); `DiscoveryPage.test.tsx:722-779` pins its text, `<= 150` characters and "Alt or Option"; `w7t.spec.ts:1005` pins `<= 150`. `PageHeader`'s `sub` is a ReactNode inside `p.sub`.
- **Synthetic big graphs need no backend data.** An e2e or measuring script can answer `GET /api/discovery/graph` with a generated model through `page.route` (PUT/DELETE of the layout too), so "10 sources, one with 6,000 points, about 2,000 nodes" is reproducible on any stack.

1. **Order.** Plan -> ONE Opus plan review -> fold in -> **T0 scaffold** (controller: two style files and their imports, the two entries in `app.css.test.ts`'s page-file list, the type-only stubs `lib/graphFind.ts` and `lib/graphGuides.ts`) -> **Wave A** (T1 camera/focus/motion helpers and the highlight hook, T2 find/guides/prefs helpers, T3 status + nodes + live edges + grid-aligned defaults, T4 new components and the menu/key hooks; disjoint files, parallel) -> **T5** page wiring part 1 (camera, highlight, live edges, nodes, minimap, snap, box select, offer bar move) -> **T6** page wiring part 2 (menus, Find, guides, hint) -> **T7** e2e including the measurements (parallel with **T8** docs) -> gates -> whole-wave review -> fix wave -> merge. T5 and T6 edit the same file, so they are sequential; both are WIRING (the logic lives in the hooks and components of Wave A, review M11).
2. **Camera (U1).** `lib/graphCamera.ts`: `CAMERA_MS = 300`, `cameraMs(reduced)` (0 when reduced), `unionRect`, `keepInView(box, view, size, margin = 40)` -> the new `{x, y}` that brings the box inside the margin with the least movement (a box taller or wider than the room is aligned at its top or left margin) or `null` when it is already in. Fit View (the Controls button, via `<Controls fitViewOptions={{ duration }}>`), the refit after Tidy, Find and "a source opened" use it. After a source OPENS BY ITS OWN `+` BUTTON OR BY THE MENU'S Expand (not a group, not a close, and NOT Find or Expand all, which move the camera themselves: two viewport animations would fight, review M1), after `afterPaint()`, the union of the source node and its group nodes (their `measured` size, else 220x80) goes through `keepInView` with the live viewport and canvas size and `setViewport({ ...view, x, y }, { duration })`: the zoom never changes. The opening view (mount) is not animated. Reduced motion: duration 0 (the camera still moves, instantly).
3. **Snap and guides (U2).** **Ruling (review I2): the grid is 8 px, not 16, and the default places move onto it.** React Flow snaps the ABSOLUTE position, and today's default places are off a 16 px grid (`X.cluster = 360` is 8 mod 16, a group's y is its source's y + `SOURCE_H` 136 = 8 mod 16, sub-assets sit at +220), so a first nudge of one group would land it 8 px away from its untouched siblings. Every default is a multiple of 8 except `ASSET_INDENT = 220` (4 mod 8): T3 changes it to 224 (sub-assets 4 px further right per level; a `buildGraph` property test pins "every default place is a multiple of 8"); the saved layout and `initialView` are unaffected. Cost if the owner wants 16: change `SNAP_GRID` and the defaults together (`X.cluster` 352, `SOURCE_H` 144, `BLOCK_GAP` 48, `ASSET_INDENT` 224). `snapToGrid={snap}` `snapGrid={[8, 8]}`; the toggle is a `Snap to grid` button with `aria-pressed` in the top-right `Panel`, on by default, stored as `dcdash.discovery.snap` = `on`/`off` through `readStored/writeStored` (`lib/sidebarState.ts`, wrapped) in `lib/graphPrefs.ts`. The reported `node.position` of a drag is the snapped one (S:2172-2178 of the library, verified in the review), so the W7t followers (`placeFollowers`, `shiftedPlaces`) stay consistent. **Guides are visual only** (`lib/graphGuides.ts`, `alignGuides(dragged, others, { cap = 200, tolerance = 1 })`): while a node is dragged, for the 200 visible nodes nearest to it (by centre distance), a vertical guide appears where the dragged node's left, centre or right equals another's within 1 graph px, a horizontal one for top, middle, bottom; each guide spans the two nodes plus 24 px. No magnet: a magnet would move the dragged node away from the position the followers and the drop-to-map put-back are computed from. With snap on (8 px grid, defaults on the grid) equal edges are common; with snap off a guide shows only on an exact match (honest, never "nearly"). Drawn in a `ViewportPortal` as one `svg` (`overflow: visible`, 0x0 at the origin) with `vector-effect: non-scaling-stroke` lines in `--accent`, `pointer-events: none`, `aria-hidden`. The guides state lives INSIDE `AlignGuides` (it hands a `{ set(guides | null) }` handle to the page through a ref), so a drag frame does not re-render `Canvas` a second time; the page computes at most once per animation frame and cancels the pending frame in `onNodeDragStop` (review M6). **Droppable:** the wiring sits behind `const GUIDES_ENABLED = true` in the page; if T7's measurement shows a drag frame over 16 ms at 2,000 nodes caused by the guides, the fix wave sets it to `false`, writes a `Ruling:` and a backlog line (the helper and its tests stay).
4. **Focus highlight (U3).** `lib/graphFocus.ts`: `edgeIndex(edges)`, `pathOf(index, id)` (the node, every ancestor through the edges backwards, every descendant forwards, cycle-safe), `focusSet(index, ids, { cap = 20, maxNodes = 400 })` (the union; `null` when no ids, more than `cap` ids, a union bigger than `maxNodes` (hovering a source with 2,000 drawn points would build 2,000 objects and light everything: no highlight then), or a union no bigger than the ids: a node with no edge dims nothing), `pathEdgeIds(edges, set)` (both ends in the set), `focusIds({ hover, focused, selected })` (hover wins, then keyboard focus, then the selection). **`hooks/useGraphHighlight.ts` (T1, with tests; the page only wires it):** takes `{ nodes, edges, selectedIds, dragging }`, returns `{ shownNodes, shownEdges, active, handlers }`. Hover starts after a **120 ms dwell** and, when the pointer leaves, clears after an **80 ms grace** that a new enter cancels (sweeping from node to node across the pane never flashes the canvas; review I9). Hover is used only when the device can hover (`matchMedia("(hover: hover)")`, true when unknown: a tap on a touch screen emulates `mouseenter` and would leave a stuck highlight). Keyboard focus (from `onFocus`/`onBlur` on the wrapper: the node element that contains the target) counts only when `target.matches(":focus-visible")` (a mouse click on a node's button is not keyboard focus). No highlight while a drag runs. **Drawn without re-rendering 2,000 nodes:** the wrapper gets the class `has-focus` (one DOM change) and only the path nodes and path edges get the class `lit` (`className` on new node/edge objects; the others keep their identity, verified in the review: R:2344-2351, R:3031-3035); the CSS dims everything else: `.graph-canvas.has-focus .react-flow__node:not(.lit) { opacity: .35 }` (edges .25). The 120 ms opacity transition is kept ONLY if T7's measurement shows no frame over 16 ms during it at 2,000 nodes (a transition on 2,000 layers at once may not): the fix wave removes the transition, not the dimming. Dimmed text is below AA on purpose and only while the pointer rests: the same facts are on the lit path and in the summary. The path of an asset goes up through its mapped points to their groups and source (reverse `m:` edges) and down to its sub-assets.
5. **Live edges (U4).** **Ruling (review I1):** the library's `.react-flow__edge.animated path { stroke-dasharray: 5 }` would turn the solid mapped edges dashed, which contradicts the legend "Dashed: discovered. Solid: assets." So: `buildGraph(model, open, { moved, ignoreSaved, animate })`; with `animate` true, a source that `isLive` (enabled and `status === "online"`) gets `animated: true` on its `e:` edges (already dashed `6 4`, period 10: the library's `dashdraw` loops seamlessly) and on the `m:` edges leaving its nodes with the inline style `strokeDasharray: "8 2"` (period 10, mostly solid with a small gap that flows: still reads as a solid asset link, but alive); asset->asset (`a:`) edges never. If, after the build, more than `LIVE_EDGE_LIMIT = 300` edges are animated, none are (the count is of ANIMATED edges). The page passes `animate = !reducedMotion`. CSS: `.react-flow__edge.animated path { animation: none !important }` under reduced motion (belt and braces; the library sheet is unlayered). SVG dash animation is repainted every frame, not composited: T7 measures idle CPU with 300 live edges and the fix wave lowers the limit if it is not near zero (review M8).
6. **Richer nodes (U5).** `lib/graphStatus.ts`: `sourceStatus(source)` -> `{ key: "online" | "offline" | "credentials" | "idle", label }` (credentials first when `needs_credentials`; then idle when not enabled; then `online`/`offline` by `status`; anything else idle, label "not polled"), `protocolLabel(type)` (`opcua` OPC UA, `modbus` Modbus, `simulator` Simulator, else the raw type), `isLive(source)`. `SourceNode`'s facts line becomes `<span class="gdot gdot-{key}" aria-hidden title="{label}"/> <span class="gproto">OPC UA</span> discovered · online · 60 points`: the status WORD stays in the text and it is the raw `source.status` as today (`unknown` stays `unknown`; beside an amber credentials dot it says whatever the status is, and the `needs credentials` badge below says the rest), colour is never the only signal, the dot is decoration. The remaining words must stay ONE text node in the facts `div` (`nodes.test.tsx:30-31` use `getByText(/discovered/)` and `/7 points/`; `:29` `/opcua/` becomes `/OPC UA/`). Protocol names match `lib/ports.ts:8-9` ("Modbus", "OPC UA"); `simulator` shows `Simulator`. The facts line wraps to two lines at 220 px for most sources and a third line would break `SOURCE_H`: T3 measures the WIDEST case (badge `Simulator`, `discovered`, `offline`, a four-digit count, a three-line name, the credentials badge); if a third line appears it drops the origin word from the line (the dashed/solid border and a `title` carry it) and writes a Ruling. 7. **Minimap (U6).** `components/graph/GraphMiniMap.tsx`: `<MiniMap pannable zoomable ariaLabel="Overview of the whole graph" nodeColor={...}/>` (`var(--token)` strings by node type: source `--accent`, group `--text-2`, point `--border-strong`, asset `--text`, unidentified `--field-border`), `null` when the canvas (`useStore(s => s.width)`) is narrower than 700 px. 8. **Find (U9).** `lib/graphFind.ts`: `buildFindIndex(model)` once per graph read (sources by name and endpoint, assets by name and kind, groups by key, points by name and address; `text` is the lowercased search string, `context` the muted second line such as `point in LVP01 · Plant OPC`), `findMatches(index, query, limit = 50)` -> `{ items, more }` (every whitespace-separated term must be a substring of `text`; rank: label starts with the first term, then a word in the label starts with it, then anywhere; ties by kind order source, asset, group, point and then index order, no `localeCompare` over thousands), `findPlan(model, open, entry, budget = EXPAND_NODE_BUDGET)` -> `{ open, targetId, note }`. **The budget uses `expandAll`'s cost rule (review I5):** opening a CLOSED source draws its groups plus the points of every group already in `open.clusters` (`graphView.ts:68-72`), and opening a point's group draws all its points. Plan: cost = (source closed ? groups + points of its already-open groups : 0) + (target is a point and its group is closed ? the group's points : 0). Over budget: first drop that source's already-open groups from the result's `clusters` (they close; the note says so), then, if the target's own group alone still exceeds the budget, leave it closed, `targetId` is the group node and the note says "LVP01 has 6,000 points, too many to draw at once. Showing the group instead." A group, a source and an asset have no point cost. Never mutates its inputs. `components/graph/FindBox.tsx`: a card under the `Find` button in the top-right panel: an ARIA 1.2 combobox (input `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, the listbox in the DOM only with results, one `aria-live="polite"` line "N results" / "No match", `type="button"` everywhere), arrows move, Enter chooses, Escape closes and returns the focus to whatever had it before (the Find button or the canvas), a click outside closes; the active option survives a re-run of `search` (a graph refresh while the box is open). Choosing: `setOpen(plan.open)`, the toast when `note`, `afterPaint()`, then **`await setCenter(...)`** (`zoom = clamp(current zoom, 0.75, 1)`, the camera duration; it resolves when the move is done) and only THEN focus the node element with `preventScroll` (review I3: React Flow's wrapper `onFocus` calls `setCenter` with no duration when a `:focus-visible` node is off screen, which would cut the animation short and lose the zoom clamp), the node gets the class `flash` for 1.5 s (a 2 px `--accent` outline; the timer holds under reduced motion too, only the pulse animation is off). **Ctrl+K and the wrapper's other keys live in `hooks/useCanvasKeys.ts` (T4):** `onKeyDown` on the `.graph-canvas` wrapper acts only when `canvas.contains(event.target)` (the DOM, not React's portal tree), the target is not inside `.graph-tools` or `.graph-menu`, and no `[aria-modal="true"]` exists (the same test as `QuickFind.tsx:45`; review M3): Ctrl/Cmd+K without Alt or Shift, `key.toLowerCase() === "k"` -> `preventDefault()` + `stopPropagation()` and open the box; anywhere else on the page the global quick find keeps the key. The Find button's accessible name is `Find`; the top bar's field is "Quick find", so every Playwright lookup of the new controls is `exact: true`.
9. **Menus (U8).** `components/graph/GraphContextMenu.tsx`: props `{ at: { x: number; y: number } | { box: Box }, items: RowAction[], label: string, returnFocus: () => HTMLElement | null, onClose: () => void }`; a portal on `document.body`, `role="menu"` `aria-label`, class `row-menu-panel graph-menu`, placed by `placePanel` (a point is a box with equal edges), focus into the first enabled item on open, ArrowUp/Down wrap, Home/End, Tab closes, Escape closes with `stopPropagation` in the capture phase (the innermost layer only) and returns the focus, a press outside, a scroll, a resize or the canvas moving (`onMoveStart`) closes. Choosing an item closes the menu and puts the focus on `returnFocus()` BEFORE running `onSelect` (a dialog opened by the item then records the node as the place to return to; the same rule as `RowActions`). **Items come from the node's own `data` callbacks:** source: Details (`onSelect`), Collapse/Expand (`onToggle`, by `expanded`), Create assets… (`onCreateAssets`), Remove (`onRemove`, danger); group: Collapse/Expand, Map… (`onMap`), New asset… (`onNewAsset`); point: Map… (`onMap`). A node with no items (asset, unidentified service) shows the CANVAS menu. Canvas menu: Expand all, Collapse all, Tidy layout, Fit view (disabled when the bar's buttons are aria-disabled). **`hooks/useCanvasMenu.ts` (T4, with tests)** owns the state: one `menu` keyed by target, opened by `onNodeContextMenu`, `onPaneContextMenu` and `onSelectionContextMenu` (review I8: while a box selection is active React Flow draws a rectangle over the selected nodes and a right-click there fires the selection event, not the node one; it gets the canvas menu), all with `preventDefault`; from the keyboard by `ContextMenu` or Shift+F10 (handled in `useCanvasKeys`, `preventDefault`, anchored to the focused node element's box; on anything else inside the canvas the canvas menu at the canvas centre). **Idempotent (review I4):** browsers also fire a native `contextmenu` event at the focused element for those keys (Chromium on Windows from the key-up path, so a `keydown` `preventDefault` is not a reliable stop; jsdom and Playwright's key events do not make it, so no automated test sees it): opening the menu for a target that already has a keyboard-opened menu, or a `contextmenu` for the same node within 400 ms of a keyboard open, is ignored, and a `contextmenu` with zero pointer coordinates is anchored to the node's box. The whole-wave reviewer checks it by hand with the real keys on Windows Chrome if available, otherwise it is parked. The menu closes when the `model` changes (it holds callbacks of nodes that may be gone). Every action has a visible button already (node buttons, the bar, Controls): the menu is never the only path.
10. **Box select (U7).** React Flow's own and ALREADY ON (`selectionKeyCode` defaults to `'Shift'`, `multiSelectionKeyCode` to Meta on a Mac and Control elsewhere, verified in the review): the plan passes `selectionKeyCode="Shift"` explicitly and does NOT pass `multiSelectionKeyCode` (review M2: on a Mac a Ctrl-click is also a right-click, so Ctrl as the multi key would open the menu). A multi-drag never maps (`dragged.length <= 1`, unchanged).
