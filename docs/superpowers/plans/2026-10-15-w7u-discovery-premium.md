## Facts checked in the code (LESSONS A12: the brief is not law)

- **The canvas today.** `pages/DiscoveryPage.tsx` (537 lines): `Canvas` holds `open` (sources/clusters), `moved` (this session's places), the W7t drag snapshot (`onNodeDragStart/Drag/Stop`, followers, Alt), `seeded = useMemo(buildGraph + nodeData)` and an effect that `setNodes(seeded.nodes)` keeping only `measured`. `ReactFlow` gets `Controls` and `Background`, `fitView` + `fitViewOptions={opening}` (from `initialView`), `minZoom 0.2`, `nodesConnectable={false}`, `edgesFocusable={false}`. `useReactFlow()` is used for `getIntersectingNodes/getNodes/fitView`. `afterPaint()` (two animation frames) is the existing "nodes are in the store" wait; `refit()` uses it.
- **Rebuilds drop `selected`.** The effect copies `measured` only, so a rebuild (expand, collapse, a refresh) loses a selection. A box selection must survive them: copy `selected` too.
- **Edges.** `buildGraph` (`lib/graph.ts`) makes `link()` edges (`e:` source->group->point, DASHED inline style `strokeDasharray: "6 4"`), `mappedLinks()` (`m:` point/group/source -> asset, solid) and asset->sub-asset (`a:`). React Flow's library CSS animates `.react-flow__edge.animated path` with `dashdraw` (period 10: the inline "6 4" is 10 as well, so the loop is seamless). That CSS is UNLAYERED and our rules live in `@layer w6`: an unlayered rule beats a layered one, so a reduced-motion override must be `animation: none !important` (a layered `!important` beats an unlayered normal rule). The same applies to every rule that restyles a library class (minimap, selection box).
- **Reduced motion today.** `app.css:673` sets `transition: none !important` for everything under `prefers-reduced-motion: reduce`; it does NOT stop animations. Every new keyframe animation needs its own `@media (prefers-reduced-motion: reduce)` rule, and the JS must not start what the CSS would stop (camera duration 0, `animated` off).
- **Keyframes in the CSS guards.** `app.css.test.ts` lets `@keyframes` steps (`from`, `to`, `50%`) pass the "selector names a class" rule, requires one page class per page file (the clash test: a class written bare in one style file and named in another fails), and tokens only inside `@layer w6`. New style files: `styles/graph-nodes.css` and `styles/graph-tools.css` (imported in `main.tsx` like the others).
- **Node sizes are load-bearing.** `SOURCE_H = 136` + `BLOCK_GAP = 40` and `ROW = 64` were measured for the 220 px nodes (graph.ts:50-60); `w7r.spec.ts:899-940` pins the first source's title AND its Create assets button inside the canvas at 1024x640. So the status dot, the protocol badge and the progress bar add NO height: the dot and the badge replace words in the existing facts line (`{connector_type} · {origin} · {status} · N points`), the progress bar is an absolutely positioned 3 px strip on the cluster's bottom edge.
- **Statuses.** The collector writes `online` / `offline` (`collector/scheduler.py:59,64`); a source never polled has another value (`unknown` in the fixtures). Connector types: `simulator`, `modbus`, `opcua` (`connectors/*.py`); there is no HTTP connector yet, an unknown type shows its raw name.
- **Ctrl+K is taken.** `components/QuickFind.tsx:41-52` listens on `document` for Ctrl/Cmd+K (not with Alt or Shift), skips when `[aria-modal="true"]` exists, and focuses the top bar's quick find. React's `onKeyDown` runs at the root container, BELOW `document`, so a handler on the canvas wrapper that calls `event.stopPropagation()` keeps the event from the quick find. That is the whole conflict rule (Decision 8): focus inside `.graph-canvas` -> Find; anywhere else -> the global quick find, untouched.
- **A click on empty canvas gives no focus.** React Flow's pane is not focusable, so "while the canvas has focus" would be true only after Tab. `.graph-canvas` gets `tabIndex={-1}` (programmatic focus target, no ring) so a click on the pane focuses the wrapper.
- **Menu primitives.** `RowActions` (`components/RowActions.tsx`) is bound to a trigger button; its look is `.row-menu-panel` (`app.css:282-286`), its placement `placePanel(box, size, viewport, gap, inset)` (a `Box` is `{top,left,right,bottom}`: a point is a box with equal edges), its Escape rule is `usePopover`'s capture-phase `stopPropagation` (a pinned popover or one with the focus swallows the key, so a dialog around it stays). A right-click menu has no trigger, so `GraphContextMenu` re-implements the keyboard rules (ArrowUp/Down wrap, Home/End, Tab closes) and reuses the class, `placePanel` and the `RowAction` type. `InfoTip` takes children and a label (default "What does this mean?").
- **Role gating is already in the node data.** `nodeData()` (DiscoveryPage.tsx:76) adds `onMap/onNewAsset/onCreateAssets/onRemove` only when the role may use them and the node qualifies. A menu built from the SAME callbacks in `node.data` is gated exactly like the buttons, by construction.
- **Unit-test mock.** `DiscoveryPage.test.tsx:21-95` replaces `ReactFlow` with a plain div (no `children`, no `Panel`), `useReactFlow` with three functions, `Controls`/`Background` with null. New code uses `setCenter/setViewport/getViewport/getZoom`, `useStore`, `Panel`, `MiniMap`, `ViewportPortal`, `onNodeMouseEnter/Leave`, `onNodeContextMenu`, `onPaneContextMenu`: the mock grows (T5 owns it), and the new pieces are separate components with their own tests.
- **Hint.** `HINT` (DiscoveryPage.tsx:30) is used twice (loading branch and canvas); `DiscoveryPage.test.tsx:722-779` pins its text, `<= 150` characters and "Alt or Option"; `w7t.spec.ts:1005` pins `<= 150`. `PageHeader`'s `sub` is a ReactNode inside `p.sub`.
- **Synthetic big graphs need no backend data.** An e2e or measuring script can answer `GET /api/discovery/graph` with a generated model through `page.route` (PUT/DELETE of the layout too), so "10 sources, one with 6,000 points, about 2,000 nodes" is reproducible on any stack.

## Decisions taken here (the brief stands; these refine it; the owner may overrule any)

1. **Order.** Plan -> ONE Opus plan review -> fold in -> **T0 scaffold** (controller: two empty style files and their imports, the type-only stubs `lib/graphFind.ts` and `lib/graphGuides.ts`) -> **Wave A** (T1 camera/focus/motion helpers, T2 find/guides/prefs helpers, T3 status + nodes + live edges, T4 new components; disjoint files, parallel) -> **T5** page wiring part 1 (camera, highlight, live edges, nodes, minimap, snap, box select) -> **T6** page wiring part 2 (menus, Find, guides, hint) -> **T7** e2e (parallel with **T8** docs) -> gates -> whole-wave review -> fix wave -> merge. T5 and T6 edit the same file, so they are sequential.
2. **Camera (U1).** `lib/graphCamera.ts`: `CAMERA_MS = 300`, `cameraMs(reduced)` (0 when reduced), `unionRect`, `keepInView(box, view, size, margin = 40)` -> the new `{x, y}` that brings the box inside the margin with the least movement (a box taller or wider than the room is aligned at its top or left margin) or `null` when it is already in. Fit View (the Controls button, via `<Controls fitViewOptions={{ duration }}>`), the refit after Tidy, Find and "a source opened" use it. After a source OPENS (not a group, not a close), after `afterPaint()`, the union of the source node and its group nodes (their `measured` size, else 220x80) goes through `keepInView` with the live viewport and canvas size and `setViewport({ ...view, x, y }, { duration })`: the zoom never changes. The opening view (mount) is not animated. Reduced motion: duration 0 (the camera still moves, instantly).
3. **Snap and guides (U2).** `snapToGrid={snap}` `snapGrid={[16, 16]}`; the toggle is a `Snap` button with `aria-pressed` in the top-right `Panel`, on by default, stored as `dcdash.discovery.snap` = `on`/`off` through `readStored/writeStored` (`lib/sidebarState.ts`, wrapped) in `lib/graphPrefs.ts`. The default columns (`X.cluster = 360`, `ASSET_INDENT = 220`, `SOURCE_H = 136`) are not all multiples of 16 and are left alone: a drag lands on the grid, an untouched node stays where the rule put it. **Guides are visual only** (`lib/graphGuides.ts`, `alignGuides(dragged, others, { cap = 200, tolerance = 1 })`): while a node is dragged, for the 200 visible nodes nearest to it (by centre distance), a vertical guide appears where the dragged node's left, centre or right equals another's within 1 graph px, a horizontal one for top, middle, bottom; each guide spans the two nodes plus 24 px. No magnet: a magnet would move the dragged node away from the position the W7t followers (`placeFollowers`, `shiftedPlaces`) are computed from, and the drop-to-map put-back would no longer agree with what React Flow saved. With snap on, equal left edges are common (grid), with snap off a guide shows only on an exact match (Ruling: honest, never "nearly"). Drawn in a `ViewportPortal` as one `svg` with `vector-effect: non-scaling-stroke` lines in `--accent`, `pointer-events: none`, `aria-hidden`, updated at most once per animation frame. **Droppable:** if T6's measurement shows a drag frame over 16 ms at 2,000 nodes, or the schedule is short, T6 removes the wiring (the helper and its tests stay), writes a `Ruling:` and a backlog line.
4. **Focus highlight (U3).** `lib/graphFocus.ts`: `edgeIndex(edges)`, `pathOf(index, id)` (the node, every ancestor through the edges backwards, every descendant forwards, cycle-safe), `focusSet(index, ids, cap = 20)` (the union; `null` when no ids, more than `cap` ids, or when the union is no bigger than the ids: a node with no edge dims nothing), `pathEdgeIds(edges, set)` (both ends in the set), `focusIds({ hover, focused, selected })` (hover wins, then keyboard focus, then the selection). The page keeps `hoverId`, `focusId` (from `onFocus`/`onBlur` on the wrapper: the node element that contains the target) and no highlight while a drag runs. **How it is drawn without re-rendering 2,000 nodes:** the wrapper gets the class `has-focus` (one DOM change) and only the path nodes and path edges get the class `lit` (`className` on the node/edge objects, derived in a `useMemo` over `nodes`/`edges` that allocates new objects only for the path); the CSS dims everything else: `.graph-canvas.has-focus .react-flow__node:not(.lit) { opacity: .35 }` (edges .25) with a 120 ms opacity transition (the global reduce rule already removes transitions). Dimmed text is below AA on purpose and only while the pointer rests: the same facts are on the lit path and in the summary. The path of an asset goes up through its mapped points to their groups and source (reverse `m:` edges) and down to its sub-assets.
5. **Live edges (U4).** `buildGraph(model, open, { moved, ignoreSaved, animate })`: with `animate` true, every edge that belongs to a source that `isLive` (enabled and `status === "online"`) gets `animated: true` (its `e:` edges and the `m:` edges leaving its nodes); asset->asset edges never; above `LIVE_EDGE_LIMIT = 300` edges in the whole graph none animate. The page passes `animate = !reducedMotion`. CSS: `.react-flow__edge.animated path { animation: none !important }` under reduced motion (belt and braces).
6. **Richer nodes (U5).** `lib/graphStatus.ts`: `sourceStatus(source)` -> `{ key: "online" | "offline" | "credentials" | "idle", label }` (credentials first when `needs_credentials`; then idle when not enabled; then `online`/`offline` by `status`; anything else idle, label "not polled"), `protocolLabel(type)` (`opcua` OPC UA, `modbus` Modbus, `simulator` Simulator, else the raw type), `isLive(source)`. `SourceNode`'s facts line becomes `<span class="gdot gdot-{key}" aria-hidden title="{label}"/> <span class="gproto">OPC UA</span> discovered · online · 60 points`: the status WORD stays in the text (colour is never the only signal), the dot is decoration. Colours are existing tokens: online `--ok`, offline `--crit`, credentials `--warn`, idle `--text-2` (AA text colour, so the 3:1 non-text rule holds on `--bg` and `--surface` in every theme: a test pins it). The online dot pulses (`@keyframes gdot-pulse` with percentage steps, `animation: none` under reduced motion). The protocol badge is a plain rectangle (`--radius-sm`, 1 px `--border-strong`), not a pill. `ClusterNode` keeps "N mapped" (pinned by `nodes.test.tsx:154`, `discovery.spec.ts:124-149`) and adds `<span class="gprogress" aria-hidden style={{ width: "NN%" }}/>` (the share of mapped points, at most 100), `title="3 of 6 mapped"`. SourcePanel is untouched.
7. **Minimap (U6).** `components/graph/GraphMiniMap.tsx`: `<MiniMap pannable zoomable ariaLabel="Overview of the whole graph" nodeColor={...}/>` (`var(--token)` strings by node type: source `--accent`, group `--text-2`, point `--border-strong`, asset `--text`, unidentified `--field-border`), `null` when the canvas (`useStore(s => s.width)`) is narrower than 700 px. Its library colours are set with the `--xy-minimap-*` custom properties on `.graph-canvas .react-flow` (the names are in `node_modules/@xyflow/react/dist/style.css`; the implementer reads them, no guessing) in `graph-tools.css`.
8. **Find (U9).** `lib/graphFind.ts`: `buildFindIndex(model)` once per graph read (sources by name and endpoint, assets by name and kind, groups by key, points by name and address; `text` is the lowercased search string, `context` the muted second line such as `point in LVP01 · Plant OPC`), `findMatches(index, query, limit = 50)` -> `{ items, more }` (every whitespace-separated term must be a substring of `text`; rank: label starts with the first term, then a word in the label starts with it, then anywhere; ties by kind order source, asset, group, point and then index order, no `localeCompare` over thousands), `findPlan(model, open, entry, budget = EXPAND_NODE_BUDGET)` -> `{ open, targetId, note }`: opens the parents it needs; a point whose group is closed opens the group only when the group has at most `budget` points, else the group stays closed, `targetId` is the group node and `note` says so ("LVP01 has 6,000 points, too many to draw at once. Showing the group instead."). `components/graph/FindBox.tsx`: a card under the `Find` button in the top-right panel: an ARIA 1.2 combobox (input `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, the listbox in the DOM only with results, one `aria-live="polite"` line "N results" / "No match", `type="button"` everywhere), arrows move, Enter chooses, Escape closes and returns the focus to whatever had it before (the Find button or the canvas), a click outside closes. Choosing: `setOpen(plan.open)`, the toast when `note`, `afterPaint()`, `setCenter` on the node with `zoom = clamp(current zoom, 0.75, 1)` and the camera duration, the node gets the class `flash` for 1.5 s (a 2 px `--accent` outline; the 1.5 s timer also holds under reduced motion, only the pulse animation is off), and the node element takes the focus (`preventScroll`). **Ctrl+K:** an `onKeyDown` on the `.graph-canvas` wrapper: Ctrl/Cmd+K without Alt or Shift, `key.toLowerCase() === "k"`, `preventDefault()` + `stopPropagation()` and open the box; anywhere else on the page the global quick find keeps the key. The Find button's accessible name is `Find` (no "Find in graph" substring clash: the top bar's field is labelled "Quick find"; the Playwright lookups below are exact).
9. **Menus (U8).** `components/graph/GraphContextMenu.tsx`: props `{ at: { x: number; y: number } | { box: Box }, items: RowAction[], label: string, onClose: () => void }`; a portal on `document.body`, `role="menu"` `aria-label`, class `row-menu-panel graph-menu`, placed by `placePanel` (a point is a box with equal edges), focus into the first enabled item on open, ArrowUp/Down wrap, Home/End, Tab closes, Escape closes with `stopPropagation` in the capture phase (the innermost layer only) and returns the focus, a press outside, a scroll, a resize or the canvas moving (`onMoveStart`) closes. Choosing an item closes the menu, puts the focus on the node's element BEFORE running `onSelect` (a dialog opened by the item then records the node as the place to return to; the same rule as `RowActions`). **Items come from the node's own `data` callbacks:** source: Details (`onSelect`), Collapse/Expand (`onToggle`, by `expanded`), Create assets… (`onCreateAssets`), Remove (`onRemove`, danger); group: Collapse/Expand, Map… (`onMap`), New asset… (`onNewAsset`); point: Map… (`onMap`). A node with no items (asset, unidentified service) shows the CANVAS menu. Canvas menu: Expand all, Collapse all, Tidy layout, Fit view (disabled when the bar's buttons are aria-disabled). Opened by `onNodeContextMenu`/`onPaneContextMenu` (`preventDefault`) and, from the keyboard, by `ContextMenu` or Shift+F10 on a focused node (the wrapper's `onKeyDown`, `preventDefault`, anchored to the node element's box); on anything else inside the canvas those keys open the canvas menu anchored at the canvas centre. Every action has a visible button already (node buttons, the bar, Controls): the menu is never the only path.
10. **Box select (U7).** React Flow's own: `selectionKeyCode="Shift"`, `multiSelectionKeyCode={["Control", "Meta"]}`, `panOnDrag` as is. The work is (a) keeping `selected` across rebuilds, (b) the selection box and selected nodes in tokens (`.react-flow__selection`, `.react-flow__nodesselection-rect`: `--accent-tint` fill, 1 px `--accent`, with `!important` where the library's unlayered rule would win), (c) the existing W7t drag logic: dragged nodes are all selected nodes, `below` excludes dragged ids, so a source and its own group selected together move their points once (a T5 unit case pins it), (d) the highlight of a selection (union of paths, cap 20).

Drag a group onto an asset or press New asset…` (under 100 characters) followed by an `InfoTip` (label `What can I do on the canvas?`) with five lines: Alt or Option while dragging moves a node alone; Shift-drag selects, Ctrl or Cmd adds; Ctrl+K finds while the canvas has focus; right-click or Shift+F10 opens the actions; hovering or selecting lights the path. ## Review Focus (for the plan review and the whole-wave review)

1. **Performance, measured:** 10 sources, one with 60 and one with 6,000 points, about 2,000 drawn nodes: drag frame time with guides, hover-to-highlight, Find keystroke to results, the minimap redrawing during a drag. `has-focus` must not re-render every node; only path nodes get new objects.
2. **Reduced motion:** no pulse, no flowing dashes, camera duration 0, no flash animation, no highlight transition (the global rule), and the JS does not start what CSS would stop; the unlayered library CSS needs `!important` overrides.
3. **Keyboard parity and focus:** every menu action has a button; Find and the menu follow the popover checklist; Ctrl+K inside the canvas is Find and outside it the global quick find, with no double handling; the ContextMenu key and Shift+F10; focus after choosing an item and after Escape is on a named element, never `<body>`.
4. **No regression:** drop-to-map, bulk create, Remove, Clear unmapped, the opening view (W7r), Tidy layout, Alt-drag, the W7t parent-and-children drag including a multi-selection (children move once), snap on and off, the put-back after a drop on an asset.
5. **Looks:** dark, light and the four presets at 1440, 1024 and 800; tokens only; node heights unchanged (the facts line must not wrap to a third line); the top-right panel never covers the first source at 1024; AA/3:1 of the dots; no cream background, italic accents, numbered labels, monospace labels or pill buttons.
6. **Find correctness:** a point in a closed group (opens source and group), an over-budget group (honest note), an ungrouped point, an asset, the same name in two sources, a query with regex characters, 50 results and "N more", the graph refreshing while the box is open.
