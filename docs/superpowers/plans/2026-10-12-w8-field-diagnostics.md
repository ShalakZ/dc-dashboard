## Global constraints (every task)
- Read-only toward the SCADA; no new network listener; no call-home; no writes to a source. Only Read, GetEndpoints, discovery and Browse-class requests.
- UI: `ui-design-rules.md` and the W6/W7a rules (tokens only in `@layer w6`, inline-SVG icons, no cream/off-white background, no italic accents, no "01/02" labels, no monospace labels, no pill buttons; the report text area may use a monospace font because it is data, not a label). Playwright matches names by case-insensitive SUBSTRING: audit every `getByLabel(`/`getByRole(` in `frontend/e2e/*.ts` against each new heading, `aria-label`, `<label>` and button name.
- Secrets: a source's password lives in `sources.secret` (Fernet), NOT in `config`, so `hidden_parts(config)` never sees it. Everything that writes or returns free text from a source (journal, job result, report) scrubs with `scrub_url_credentials(text, known=...)` where `known` holds `hidden_parts(config).values()` of that source AND its decrypted secret (min 4 chars, see `_MIN_KNOWN`). Never iterate `os.environ` or print `Settings` (the database URL holds the DB password). Never in output: password hashes, `DCDASH_SECRET_KEY`, session tokens, private keys.
- Tests: backend `cd backend && uv run pytest <files>` (Docker testcontainers; `tests/conftest.py` has a `TABLES` TRUNCATE list: add `diag_events` there); frontend `cd frontend && npx vitest run <files>`; `npm run typecheck`. Implementers never run `docker`, `scripts/*`, `npx playwright test`, nor touch Compose project `dcdash` or volume `dcdash_dbdata`.
- New audit action strings need an entry in `frontend/src/lib/auditText.ts` (+ its test) because `backend/tests/test_audit_describers.py` checks parity. A route that changes data must call `audit(...)` in its own body (`test_audit_coverage.py`).

## Pinned interfaces (do not renegotiate; propose a change in your report instead)
**Build id (`backend/dcdash/core/build.py`).** `@dataclass(frozen=True) class BuildInfo: build_id: str; build_time: str`; `build_info() -> BuildInfo` reads env `DCDASH_BUILD_ID` (default `"dev"`) and `DCDASH_BUILD_TIME` (default `"unknown"`); module constant `STARTED_AT: float` (monotonic at import) and `uptime_seconds()`.

**Journal (`backend/dcdash/core/journal.py`, table `diag_events`).** Columns: `id bigserial PK, ts timestamptz NOT NULL DEFAULT now(), level text (info|warning|error), component text (collector|api|scan|job), source_id integer NULL (no foreign key: the journal outlives the source), kind text, code text NULL, message text, detail jsonb NOT NULL DEFAULT '{}'`; indexes `(ts)` and `(source_id, ts)`. Writer: `async def record(pool, component, kind, message, *, level="info", source_id=None, code=None, detail=None, known=()) -> bool`: wraps everything in `asyncio.timeout(3)` and `except Exception`, NEVER raises, returns False on any failure (logs one warning per failure streak only); message = `clip_error(scrub_url_credentials(message, known))` cut at 500 chars; `detail` through `scrub_strings(detail, known)` (give `scrub_strings` an optional `known=()` parameter, behaviour unchanged without it) and cut to 2 KB serialized (over the limit: `{"truncated": true}`); a per-process limiter of 120 events per minute drops the rest (counts them, one warning). Read side: `async def recent(pool_or_db, *, limit, source_id=None, since=None)` used by the report. Kinds (constants in the module): `collector.started`, `source.offline` (code = ConnectorError status: `unreachable|auth_failed|timeout|protocol_error`), `source.online`, `points.bad` / `points.recovered`, `job.finished`, `check.finished`, `clock.skew`, `http.5xx`.
Housekeeping (`collector/housekeeping.py`): delete journal rows older than 14 days and trim to the newest 20 000 rows; its result dict gains a `journal` count.

**Connector status carried through.** `PointValue` (frozen dataclass in `connectors/base.py`) gains a trailing defaulted field `status: str | None = None` (for example `"BadNodeIdUnknown (0x80340000)"`); the OPC UA connector fills it for a bad DataValue; the writer's row tuples are unchanged.

**Check job.** Job kind `check_connection`, params `{"source_id": int}`; handled by the collector. The job's `result` is rewritten after EVERY step (each write scrubbed with the source's `known` values) so the UI shows steps live; shape:
`{"source_id": 3, "connector_type": "opcua", "started_at": iso, "finished": bool, "ok": bool|null, "first_failed": step_id|null, "steps": [{"id": "dns", "name": "DNS resolution", "ok": true|false|null, "ms": 12, "summary": "...", "error": {"class": "OSError", "status_name": "BadSecurityChecksFailed"|null, "status_hex": "0x80130000"|null, "message": "..."}|null, "hint": "..."|null, "detail": {}}], "clock": {"server_time": iso|null, "local_time": iso, "skew_seconds": float|null}}`.
`ok: null` on a step means skipped (an earlier step it depends on failed). OPC UA step ids in order: `dns, tcp, endpoints, certificates, session, server_time, namespaces, read_points, timing`. A non-OPC UA source gets one step `test` (the connector's `test()`), hint "detailed step-by-step check exists for OPC UA sources only". The report treats a missing check as "no connection check has been run" and an unfinished one as "running".
API: `POST /api/sources/{id}/check` (operator) returns 202 `{"job_id": n}`; 409 `{"detail": "a connection check is already running for this source", "job_id": n}` while a pending or running `check_connection` job exists for that source; 429 with `Retry-After: 5` while one finished less than 5 s ago (database clock); both guards run under `pg_advisory_xact_lock(<source_id>)` in the same transaction as the insert; audit action `source.checked` `{source_id, name, job_id}`.

**Report.** `GET /api/diagnostics/report?detail=summary|full&mask=0|1&source=<id>&format=text|json` (admin only; default `detail=summary`, `mask=0`, `format=text`). Audit action `diagnostics.report` `{detail, mask, source_id, parts, chars}` written in the route body and committed (the content is never audited). `format=text` returns `text/plain; charset=utf-8` (all parts joined by one blank line); `format=json` returns `{"format": "DCDASH-REPORT v1", "build_id", "detail", "mask", "checksum", "parts": [{"index", "of", "text", "chars", "lines"}], "legend": [{"alias", "original"}]}` (legend empty unless `mask=1`; it is shown in the UI only, never in any text). Text layout: every part starts with `DCDASH-REPORT v1 | PART i OF n | build <id> | <generated UTC iso>`, sections are `== NAME ==` blocks in this fixed order: ENVIRONMENT, SETTINGS, SOURCES, SOURCE HEALTH, POINTS, CONNECTION CHECKS, JOURNAL, SCANS, STORAGE AND RETENTION, AUDIT TAIL, API ERRORS; every part ends with `--- PART i OF n | chars=N lines=N ---` and the last part ends with a final line `END OF REPORT <checksum>` where checksum = first 12 hex chars of sha256 over the full masked body (all parts' text before the footers, joined by "\n"). A part holds at most 12 000 characters (split on line boundaries, preferring section boundaries); `summary` is capped at one part and `full` at about 60 000 characters (each section builder takes a line cap and ends with `... N more lines omitted`; every line is clipped at 300 chars). The builder is a pure function of data it is handed plus a small async collector `gather(db, ...)`; sections are allow-listed fields, never a dumped config or settings blob.

**Check hints (`backend/dcdash/diagnostics/hints.py`).** `hint_for(status_name: str|None, exc_class: str|None, step_id: str) -> str|None`, a lookup table of plain-language lines (what the usual cause is and what to ask the SCADA or network team), including at least: `BadSecurityChecksFailed`, `BadCertificateUntrusted`, `BadCertificateInvalid`, `BadCertificateHostNameInvalid`, `BadIdentityTokenRejected`, `BadUserAccessDenied`, `BadTcpEndpointUrlInvalid`, `BadNodeIdUnknown`, `BadTimeout`/connect timeout, `ConnectionRefusedError`, DNS failure (`gaierror`), clock skew beyond 300 s (local cause first: the Docker Desktop/WSL2 VM clock drifts after the host sleeps; compare the container clock with the database clock), `BadSecurityPolicyRejected`, `BadSessionClosed`.
