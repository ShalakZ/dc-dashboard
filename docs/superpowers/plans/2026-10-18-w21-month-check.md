## 1. Facts checked in the code (each line of the brief re-read; corrections marked FIX)
- `month_costs` (`backend/dcdash/api/billing.py:91`) and the energy engine (`core/energy.py`, `core/cost.py`) are read as the brief says. The engine reads `readings_1h` (a real-time continuous aggregate of `readings_1m`; columns `point_id, bucket, min_value, max_value, sum_value, n, last_value, minutes`; bad-quality samples excluded; a row exists only for an hour with at least one good sample). `_ROWS` returns the month's rows, each COUNTER point's baseline (the last bucket before `start`) and every point's first bucket ever.
- `counter_hours`: previous = baseline or None; `last < previous` is a reset (`max(0, max-prev) + (last-min)`); otherwise `last - previous` (so an hour whose `min < previous <= last` is a dip the engine treats as a plain rise); no previous: `last - min`. `power_hours`: rows with `n <= 0` skipped; coverage `min(1, minutes/60)` when `interval_seconds <= 60` (`MINUTE_COVERAGE_MAX_INTERVAL`), else `min(1, n*interval/3600)`; hour = `sum/n * coverage`. A power-only meter with no rows is `HourEnergy(0, True, has_data=False)` for every hour of the range; a silent counter is `{}`. Splice: an own meter counts from `own_from = max(first_bucket, start)`; before that the asset is the sum of its children (`assemble`). `HourEnergy.estimated = not meter.counter`. `cost_by_hour` prices an own hour with `rate_at(tariffs, tree, asset, bucket.astimezone(zone).date())`; `_price`: `unpriced = kwh > 0 and rate is None` (kwh already scaled).
- `load_meters` picks per asset the `energy_kwh` mapping, else `active_power_kw` (`Meter(point_id, scale, interval_seconds, counter)`). Voltage/current-only assets (the seeded panels) have NO meter.
- `AssetTree` has `children`, `ancestors_or_self`, `path`, `preorder`, `nodes`. `billing._now()` is the clock the billing tests patch (`monkeypatch.setattr("dcdash.api.billing._now", ...)`); the new endpoint must call it through the module so one patch moves both endpoints.
- Routes are registered in `dcdash/api/main.py:139` (`billing.router` in a tuple); every route needs a `ROUTE_PERMISSIONS` entry (`backend/tests/auth_expectations.py:79`) and the gate test `test_route_gates.py` fails on a missing one. A caller's permissions: `user.can("sources.view")`.
- Point and source names are NOT shown by any `billing.view` or `assets.view` route today (`GET /api/mappings/{id}` is `assets.edit`). FIX of the brief ("with the asset path and the point it reads"): the point and source NAMES are returned only when the caller also holds `sources.view` (else `null`); the point ADDRESS is never returned. See D12.
- FIX (data for the acceptance runs): the history seeder clamps its range to `now - (raw_retention - 1)` days (30 days by default), so the "finished seeded month" holds only its last days and EVERY seeded meter would read "started part way through the month". The look stack therefore sets the raw retention to 90 days (PUT /api/settings/storage) BEFORE seeding, so September is whole; the gap (09:00-15:00 local, six hours, in a complete earlier day) and the one reset are then inside it. In the pilot hall a counter feed also has a kW twin mapped on the same asset (the counter wins), 8 B feeds are power-only at 1800 s, panels have voltage and current only, 6 free racks have two unmapped feed assets each.
- Front end: `Drawer` (portaled, modal, focus return via the opener or `returnFocus`), `MonthDialog` has `extra?: string | null` (a second paragraph "fixed before the dialog opens"), `BillingPage` passes `{kind:"close", month}` in its `dialog` state, the header `actions` today are `[Close|Reopen month…][Download CSV]` and are ABSENT for a viewer with neither right. `ESTIMATED_TIP` ("Estimated from average power; this asset has no energy counter.") is the existing tooltip. ## 2. Decisions (Rulings; the plan review may overturn them)
- **D1 Read-only; nothing existing moves.** The diff touches NONE of `core/energy.py`, `core/cost.py`, `core/billing_close.py`, `api/billing.py` (a final `git diff --stat main -- <those>` must print nothing). Proof of R1: that diff, the existing billing suites untouched and green, and a `month_costs` JSON for the finished seeded month saved on the pre-change look stack (Task 0) and compared byte for byte after the last backend commit (the finished month's readings do not change).
- **D2 Where the maths lives.** `backend/dcdash/core/month_check.py` (pure, no database, imports `HourRow`, `Meter`, `counter_hours`, `power_hours`, `MINUTE_COVERAGE_MAX_INTERVAL` from `energy.py`; edits nothing there). The route and the one batched statement live in a new `backend/dcdash/api/billing_check.py` (router registered after `billing.router`; same 409 words as `month_costs` for an unusable zone, pinned by a test that compares the two texts).
- **D3 What is looked at.** Every asset in `load_meters` (its OWN meter; parents are not repeated), over the UTC hours that begin in `[month start, stop)` where `stop = min(month end, floor_to_hour(now))` (an open month stops at the last COMPLETE hour). A meter's expected hours start at `max(first_bucket, month start)`. State: `not_begun` (now before the month; nothing is read), `open`, `finished` (by the site clock, like the page's `month < current`). `hours` = hours in `[start, stop)` (0 when the first hour of the month has not finished: "nothing to look at yet").
- **D4 The seven findings and the rules (the contract of section 3).** Per meter, in order of how much they can change a bill:
  1. `silent`: `never` (the point never recorded anything), `none_in_month` (it has earlier readings but none in the expected range; `last_reading` = the last bucket before the month), `trailing` (the last expected hours have no reading: `since` = first hour of the trailing run, `hours` = its length).
  2. `gaps`: runs of whole expected hours with no row, EXCEPT the trailing run (that is `silent`). Counted: `runs`, `hours`, `longest_hours` with `longest_start`, `first_start` (start of the first missing hour), `last_end` (end of the last missing hour). **Counter**: a run no longer than `tolerated` is normal and ignored, where `tolerated = 0` for polling under 3600 s and `ceil(interval/3600)` hours for 3600 s and slower (a slow poll leaves hourly buckets empty by design; the same tolerance applies to the trailing run). **Power-only**: no tolerance (the engine counts an hour without a row as nothing), and also `short_hours` / `short_minutes` = hours that HAVE a row but are covered less than fully by the engine's own coverage rule (`row_coverage`, identical to the factor in `power_hours`); the item exists when there is a run OR `short_minutes >= 60` (D8). A counter's part-covered hour loses no energy (the hour counts last minus previous last), so it is never reported.
  3. `estimated`: every power-only meter, listed always (even silent ones, because the page shows `~` for them): `hours_estimated` = hours with a row and `n > 0` (exactly the hours `power_hours` returns), `hours_total` = its expected hours.
  4. `resets`: counter rows classified exactly as `counter_hours` branches: `reset` when `last < previous`, `dip` when `min < previous <= last`; the first row (no previous) is never flagged; the baseline is the last bucket before the month (as in the engine). Returned: `resets`, `dips`, the first five `events` by time.
  5. `started`: `first_bucket > month start` (the asset counts the sum of its children before it, nothing if it has none); `after_month` when the first reading is at or after the month's end; `children` = number of children. Counted as a thing to check.
  6. `unpriced`: own hours of the meter with scaled `kwh > 0` and no rate (rate lookup by local date of the hour, `rate_at`), summed: `kwh`, `hours`, `days`, `first_day`, `last_day`.
  7. `flat` (counters only): a run of consecutive expected hours, each with a row whose `min == max == last` and equal to the previous row's last (or, for the first row with no baseline, `min == max == last`), at least `FLAT_HOURS = 24` long. Returned: `runs`, `longest_hours`, `longest_start`, `first_start`. A missing hour breaks a run.
  8. `unmetered` (information only, never counted): leaf assets (no children) that have no meter of their own and no meter above them (nothing measures them). `total` and the first 50.
- **D5 What counts as a "thing".** `things` = the sum of the `total` of the seven groups 1-7 (one per meter and kind of finding). `unmetered` is never counted. `meters` = meters with at least one expected hour; `meter_hours` = the sum of their expected hours.
- **D6 Wording is on the client, from structured data**, so the vitest suite can scan every sentence for banned words (`ok`, `ready`, `verified`, `correct`, `accurate`, `guarantee`, `safe`, `all good`, `passed`, a `%` sign). Headlines: `N things to check` / `Nothing to check` / `Nothing to look at yet` (state `not_begun`, `hours == 0`, or `meters == 0`, each with its reason). Every answer says what it looked at ("Looked at 217 meters, 720 hours each ..."). The owner's estimate rule is ONE sentence in the Estimated group: "An hour is marked estimated when the asset has no energy (kWh) counter, so its energy is worked out from average power (kW) readings; anything that adds up estimated hours is marked estimated too." Counter versus power consequences: counter gap = the energy is not lost, it is counted in the hour the readings return (in a later month when the gap runs past month end); power-only gap = that time counts as 0 kWh.
- **D7 Times** in the site timezone as `YYYY-MM-DD HH:MM` (new `formatSiteDateHour` in `lib/siteTime.ts`); the API returns ISO UTC and the client formats.
- **D8 Thresholds (stated in the answer under `limits` and in the docs):** `flat_hours = 24`, `short_minutes = 60` (less than an hour of partly-missing coverage in a whole month is not listed), `cap = 50` items per group (the answer carries `total`, so "and N more" is always the true number).
- **D9 Placement.** A `Check month` button in the page header actions, LEFTMOST (so Close/Reopen month and Download CSV keep their place from the right edge), for every viewer. It holds a fixed count slot (`.check-count`, `min-width: 3ch`, shows `99+` above 99) filled by the answer or a skeleton; no layout shift. It opens the `MonthCheckDrawer` (`Drawer`, wide). The header now always has a button for a viewer, so the reserved header height follows `site.isPending || month !== null` for everybody.
- **D10 The query** `useBillingMonthCheck(month)` is enabled when `month !== null`, `staleTime` 5 minutes, no polling, key `["billing","month-check",month]`; the drawer reads the same cache.
- **D11 The Close month dialog** gets ONE extra paragraph (`MonthDialog extra`), text decided at the click from the page's current check answer ("Month check: 3 things to check (see Check month on the page)." / "... nothing to check ..." / "... not read yet ..."), no link or button. - **D12 Permission and exposure.** Route gate `billing.view` only (`ROUTE_PERMISSIONS` gets `GET /api/billing/month-check`). `point` / `source` names appear only for a caller who holds `sources.view` (else `null`; the drawer then omits "reads ..."). No address, no source URL, no credentials, ever.

## 3. The API contract (the front end and the tests are written against exactly this)
`GET /api/billing/month-check?month=YYYY-MM` (gate `billing.view`; `month` optional = the current site month; pattern `^\d{4}-(0[1-9]|1[0-2])$` as `/costs`; 422/409 as `/costs`).
```
{ "month": "2026-09", "timezone": "Asia/Qatar", "state": "not_begun"|"open"|"finished", "closed": false,
  "from": "2026-08-31T21:00:00Z", "to": "2026-09-30T21:00:00Z", "hours": 720, "meters": 217, "meter_hours": 150480,
  "things": 12, "limits": {"flat_hours": 24, "short_minutes": 60, "cap": 50},
  "groups": { "silent": G, "gaps": G, "estimated": G, "resets": G, "started": G, "unpriced": G, "flat": G,
              "unmetered": {"total": 28, "items": [{"asset_id": 1, "path": "A / B"}]} } }
G = {"total": int, "items": [Item]}            // items: at most cap, worst first, ties by path then asset_id
Head = {asset_id, path, kind: "counter"|"power", point: str|null, source: str|null, interval_seconds}
silent    = Head + {reason: "never"|"none_in_month"|"trailing", since: iso|null, hours: int|null, last_reading: iso|null}
gaps      = Head + {runs, hours, longest_hours, longest_start: iso, first_start: iso, last_end: iso, short_hours, short_minutes}
estimated = Head + {hours_estimated, hours_total}
resets    = Head + {resets, dips, events: [{at: iso, kind: "reset"|"dip"}]}      // first five by time
started   = Head + {first_reading: iso, after_month: bool, children: int}
unpriced  = Head + {kwh: float, hours: int, days: int, first_day: "YYYY-MM-DD", last_day: "YYYY-MM-DD"}
flat      = Head + {runs, longest_hours, longest_start: iso, first_start: iso}
```
`closed` = the month has an active close (its billed figures are frozen; the check describes today's stored readings). Worst first: silent by hours desc (`never` first), gaps by hours desc, estimated by hours_estimated desc, resets by resets+dips desc, started by first_reading desc, unpriced by kwh desc, flat by longest_hours desc. A `not_begun` month, or `hours == 0`, returns empty groups and `things: 0`.
