# w13 Dashboard widget overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The dashboard widgets follow the theme (light, dark and the four presets), look professional, give an engineer the details one step away, and the parked widget bugs are fixed. Front end only.

**Architecture:** The frozen "island" (unlayered literal CSS, `all: revert`, white card, black border) is deleted from `app.css` and `themes.css`. The widget rules move into `@layer w6` files that use `--widget-*` and `--chart-*` tokens (defined once in `app.css` `:root`, dark values in `themes.css`). ECharts options take a `ChartTheme` read from those tokens at render time (`useChartTheme`, re-read when `data-mode` or `data-theme` on `<html>` changes). A new right-hand `Drawer` ("Details") shows what a widget shows, from data the widget already fetched; pure helpers in `lib/widgetDetails.ts` decide what is exact enough to show.

**Tech Stack:** React 19, ECharts 5 (`echarts-for-react`), react-grid-layout 2, TanStack Query, vitest + Testing Library, Playwright (isolated scratch stack `dcdash_e2e_w13_vis`, ports 18219 / 18573).

**Spec:** `.waves/w13.md` (the owner's words, rulings R1 to R8). Roadmap row, backlog section and CHANGELOG at close-out.

**Tier: M** (front end only, no migration, no backend change, no permission, nothing deleted; visual and wide, so the plan review and the whole-wave review are Opus and the whole-wave review looks at real screenshots). Per-task Opus review: none (nothing here touches auth, data deletion, money or a migration).

## Decisions (each is also a Ruling in the ledger)

1. **R1 follow the theme**: the island goes; widgets use the app's content tokens and the new `--widget-*` / `--chart-*` tokens (design note below).
2. **Details button on the card, drawer on click** (R8 b): an icon button in the frame header (`aria-label="Details for <title>"`), only in the read-only dashboard (not in edit mode, not in the editor preview). CSV stays on the card and is the drawer footer's `Download CSV` too (D3 below). A "larger focused view" (R8 f) is NOT built (the drawer is the focused view; a second ECharts instance in a drawer is not cheap): backlog.
3. **Tooltips** (R8 c): keep two decimals (R6: no rounding change; "full precision" would change the figures the widget shows); ADD the quality state in words to a line (estimated, partial, no rate) beside the markers. Unit and time are already there.
4. **Time series summary** (R8 d): built, exact only: lowest, highest (and when), latest bucket value; energy/cost: total only when no bucket is null, highest bucket, latest bucket. Each labelled with what it is computed over ("of the hourly values shown", "of the 5-minute..." is NOT claimed for a metric: "of the buckets shown").
5. **Gauge** (R8 e; the arc itself is SVG, D1): the scale ends are text labels (min and max, with the unit); the figure and the asset name are HTML text (no overlap by construction, readable by a screen reader), the arc is `role="meter"` with `aria-valuemin`, `aria-valuemax`, `aria-valuenow`, `aria-valuetext`. No thresholds are invented (the widget has none).
6. **Charts** (R3): one `chartTheme.ts` (`ChartTheme`, `readChartTheme`, `useChartTheme`, the shared axis/legend/tooltip option parts). `timeSeriesOption(data, tz, theme = LIGHT_CHART)` and `barOption` keep their old call shapes (a default theme argument), so the option tests only change where a colour or a name changed. The chart wrapper is `role="img"` with an `aria-label` built by `chartDescription` (type, assets, metric and unit, window), and the Details panel carries the same figures as a table (the real text alternative).
7. **Band series toggle with their line**: the line series is emitted FIRST (z 3), then the two band series (z 2) which take the line's NAME and colour (ECharts draws a legend icon from the first series of that name: a hidden band first would make every icon invisible, review I4), keep their ids (`band-min-<id>`, `band-span-<id>`; the tooltip already filters on the `avg-` id), so one legend entry switches all three. The remembered legend selection is stored by ASSET id and mapped to the current labels on every apply, so a ` ~` or ` *` appearing does not lose it; an id that is gone is ignored, and the selection is applied only when the legend is shown and at least one series would stay visible.
8. **Grouped bar dash slot**: a bucket with no rate becomes a zero-height bar item with `itemStyle.color: "transparent"` (not opacity 0: that hides its label too, review I5) and a `label` showing the dash, which sits in that asset's own slot; the tooltip text still comes from the precomputed lines; the by-asset (single series) mode keeps its `markPoint`.
9. **Loading**: `Skeleton` shapes per type inside the card (`SkeletonRegion` once per widget, label "Loading <title>"), initial load only; the lazy-chart `Suspense` fallback is the same shape. The card never changes size (LESSONS A2).
10. **Heading level**: the widget title is an `h2` (the page has the `h1`, the Details drawer title is the dialog name). No spec looks up a widget heading by level (grep done).
11. **The pins that must change on purpose** are listed below; nothing else is touched.

## Design direction (R2: written by an Opus designer from the baseline screenshots; the controller's rulings on it follow)

Full note: `.waves/w13/design-note.md` (measured contrasts, the Token list; it is the SOURCE for every token value and the implementers read it). In one paragraph: a widget is a quiet app card (`.page-card` family: `--widget-bg` ground, 1px `--widget-border`, `--widget-radius` 6px) with a 36px header (title 13px / 600, small icon buttons), a dense body in the app's type scale, an optional one-line footer for "since" and the marker hint, and charts in one measured 8-colour palette (same in all presets, no red; series 6 to 8 dashed; single-series charts use `--accent`) whose ink, grid and tooltip come from the same tokens. The gauge is a 180 degree arc with no needle, ticks or numbers; the scale ends, figure, unit and name are HTML below it. Details are one click away in the existing Drawer. Tweaks: card density and corners = `--widget-pad --widget-head-h --widget-row-h --widget-radius --widget-shadow --widget-figure --widget-figure-sm`; palette = `--chart-1..8 --chart-band-opacity --chart-grid --chart-tip-bg`; gauge = `--gauge-track --gauge-fill --gauge-width`.

Rulings on the note (each also in the ledger):
- **D1 The gauge arc is SVG, not ECharts.** The note's semicircle needs a radius computed from the box on every resize, with no needle, ticks, title or detail: an inline SVG (`viewBox`, `preserveAspectRatio="xMidYMax meet"`, `pathLength="100"`, `stroke-dasharray`, `vector-effect: non-scaling-stroke`, colours from `--gauge-track` / `--gauge-fill` through CSS) does that with no JS measuring, follows the theme with no reader, never re-renders a canvas on a stream batch, and drops ECharts from the gauge's chunk. The angle tokens of the note are therefore NOT tokens (the semicircle is a code constant; a 240 degree arc is a small code edit, said in the CHANGELOG). R6 holds: the value, its text and its markers are the same strings.
- **D2 The marker hint and the since line move to one footer line for every type** (the note's footer): `hint = markerHint(flagsOf(data))` for ALL widget types (today stat and table build their own hint next to the figure; `flagsOf` already gives them `noRate`, which fixes the missing "— no rate" in one place). Each text stays in its own `<small>` so the exact-text tests still match.
- **D3 CSV stays in the header and is also the drawer footer's "Download CSV"** (the note); below 200px card width only the drawer one is reachable. The header button's name stays `Download CSV for <title>`; the drawer's is exactly `Download CSV`.
- **D4 The drawer title is `Details: <widget title>`** (the note says the bare title): a second heading with the card's name would match `getByRole("heading", { name })` lookups.
- **D5 New icons `pencil` and `grip`** are added to `components/Icon.tsx` by Task 1 (with `Icon.test.tsx`), so the parallel tasks can use them.
- **D6 Series 6 to 8 are dashed lines**; bars are not dashed (the legend and tooltip carry the names).
