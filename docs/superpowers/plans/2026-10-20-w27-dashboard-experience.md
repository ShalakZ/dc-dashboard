# w27 - The dashboard experience: figures that read at a glance, cards that use their room, a template gallery, a first-run guide, three flow fixes - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dashboard figures read at a glance (separators, MWh and k/M scaling, the exact value one hover away), stat and gauge figures use their card, New dashboard becomes a two-step template gallery fed by the server, a short guide and a few help texts explain a dashboard, and the header says when the figures were read.

**Architecture:** A pure module `lib/figures.ts` owns every rule of how a figure is shown (three faces: card, tick, exact); every dashboard call site uses it. Nothing is stored anew (no migration, no permission): the guide's memory is in `localStorage`.

**Tech Stack:** FastAPI + SQLAlchemy async + pytest (backend); React 19 + TypeScript + Vitest + React Query 5 + ECharts + Playwright (frontend); plain CSS with tokens inside `@layer w6`.

**Spec:** `.waves/w27.md` (the brief; rulings R1 to R14 are its, refined below).

## Decisions (each is also a `Ruling:` line in the ledger)
- **D1 Rounding and grouping, in `lib/figures.ts`, use no locale API at all.** Rounding is `toFixed(d)` (what the cards, Billing and every old figure use, so no figure moves by a cent against today's), grouping is a comma every three digits of the integer part written by a regular expression. A German default locale therefore cannot change a digit (the brief's `Intl.NumberFormat("en-US")` is met in intent; `Intl` rounds on the shortest decimal and prints 1.005 as "1.01" while Billing prints "1.00"; a card and Billing must agree). Costs if wrong: an exact half-cent value differs by 0.01 from an `Intl` rendering; one function moves.
- **D2 Scale selection is one function over a GROUP of values.** `pickScale(unit, values)` looks at the largest |value| (after the card rounding) and returns a `Scale` shared by every figure of the group (R3). A figure then formats itself in that scale; its decimals still follow its own shown magnitude. The change amount of a comparison picks its own scale.
- **D3 The chart axis keeps the data in base units** (no data changes): the axis label formatter divides by the scale's divisor and prints the tick face; the axis NAME carries the scaled unit ("MWh"; for cost "k QAR" and "M QAR", and "thousands" / "millions" with no currency; T3 checks that the name does not clip at 3 wide, `barAxis.ts:15,28`). Tooltips and the accessible text stay exact. A gauge picks ONE scale over its value, min and max (the ends, `aria-valuemin`/`max` and `aria-valuetext` agree; plan review 18).
- **D4 Refresh and Updated (amended by plan review 10, 24, 26).** Refresh is `queryClient.refetchQueries({ queryKey: keys.widgetData, type: "active" })`; Updated is the minimum `dataUpdatedAt` over the active widget-data queries that have `status === "success"` and `dataUpdatedAt > 0` (a query that has no answer yet, because `placeholderData` still draws the previous one, is skipped and the previous text stays, dimmed, in its slot; a failed refetch leaves the old time, which is honest), shown as site-time `HH:MM` in a fixed-width slot (nothing moves when it appears) and NEVER in a live region. The header keeps its floor at 1024 with the sidebar minimised and expanded. Header order: spacer, live, Updated, Refresh, "How to read this", then the range select, Focus (+ its InfoTip), the focus link, Edit - the two new buttons come BEFORE the range select so `w13.spec.ts:668-696` (at most six Tabs from "Dashboard range" to the first card's Details) still holds; the implementer counts the Tabs.
- **D5 Template contract (T5 produces, T6 consumes).** `GET /api/dashboard-templates` (gate `dashboards.edit`) answers
  `{"nothing_metered": bool, "templates": [{"id": "power"|"cost"|"areas"|"day", "title": str, "description": str, "range": RangePreset, "recommended": bool, "needs": str | null, "widgets": [{"type": str, "x": int, "y": int, "w": int, "h": int, "source": "metric"|"energy"|"cost" | null, "compare": "none"|"same_days_last_month", "bars": "asset"|"time"|"kind", "scope": "fixed"|"focus"|"children"}]}]}`
  in the order power, cost, areas, day. A text widget has `source` null, `compare` "none", `bars` "asset", `scope` "fixed" (never null, so the client types stay plain). Ids, titles and descriptions are the server's; Blank is the client's own card.
- **D6 Recommendations (R8, exact; amended by plan review 5 and 20).** `metered` = ids from `load_meters`. `nothing_metered` = no metered id in the tree. When nothing is metered every template has `recommended=false` and `needs=null`. Otherwise: `power` recommended; `cost` recommended iff `rate_at(tariffs, tree, a, today)` is not None for at least ONE metered asset `a` (`today` = the site's local date; a future-dated row or a row on an unmetered branch does not count; the site default does, through `rate_at`), else `needs="Needs a rate in Tariffs."`; `areas` recommended iff the default focus has at least two children with a meter at or under them (else `needs="Needs at least two areas with a meter."`); the default focus follows `_resolve_focus`: the sole top-level asset when there is exactly one (its children are the "children"), else the top-level assets themselves are the "children"; `day` never recommended, `needs=null`. Pilot hall: power, cost, areas tagged. `--metering panels`: not areas. `template_catalog(tree, kinds, metered, tariffs, today)` takes the tariff rows and the date, not a bool.

### Task 1: `lib/figures.ts` (the rules of R1 to R3)
**Files:** Create `frontend/src/lib/figures.ts`, `frontend/src/lib/figures.test.ts`.
**Interfaces (Produces, used by T2, T3, T4, T10):**
```ts
export interface Marks { estimated: boolean; partial: boolean }          // same shape as Flags in widgetFormat.ts
export interface Scale { divisor: number; unit: string | null; letter: "" | "k" | "M"; axisName: string | null }
export type Family = "energy" | "cost" | "plain";
export function familyOf(unit: string | null, source: "metric" | "energy" | "cost"): Family;  // kWh/kW/kVA/kvar -> energy (step 1,000 to M, G); source cost -> cost; everything else plain
export function pickScale(family: Family, unit: string | null, values: readonly (number | null | undefined)[]): Scale;  // largest |value| after rounding decides; never throws on null/NaN
export const IDENTITY: (unit: string | null) => Scale;
export function cardFigure(value: number | null | undefined, scale: Scale, marks: Marks): string;  // digits only: "~275.43*" with the scale letter, no unit; "—" for null/NaN/Infinity
export function cardText(value, scale, marks): string;     // cardFigure + unitSuffix(scale.unit)  (a dash gets no unit)
export function exactText(value: number | null | undefined, unit: string | null, marks: Marks): string;  // base unit, "~275,430.26 kWh"; dash without unit
export function tickText(value: number, divisor?: number): string;   // separators, only the decimals needed (at most 2): "18,000", "0", "0.5"
export function groupDigits(digits: string): string;  // "1234567.5" -> "1,234,567.5"; used by all faces
```
Rules (R2 verbatim): energy family steps by 1,000 (kWh to MWh to GWh; kW to MW to GW; kVA to MVA; kvar to Mvar), cost uses k and M, every other unit never scales. Card face by |v| in the shown unit: below 10,000 two decimals; 10,000 to below 100,000 zero decimals; from 100,000 step up one unit (iterate while the family has a next unit). Cost: below 100,000 two decimals; to below 1,000,000 `k` with two decimals; from 1,000,000 `M` with two decimals (above 1,000 M it keeps the separators, no next letter).
