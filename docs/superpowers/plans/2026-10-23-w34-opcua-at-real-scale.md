# w34: OPC UA at real scale - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Every implementer brief says: "Edit files with the Edit tool or an anchored sed, never with a script that rewrites a whole file."

**Goal:** The OPC UA connector can read a tag by an address that survives a SCADA project change (opt-in), reads a large source in slices, browses without one round trip per tag, and the simulator can pretend to be a 15,000-tag SCADA so all of it is tested.

**Architecture:** One pure function `stable_address` (new `connectors/opcua_ids.py`) is the only place the number in `ns=3;s=20403:Site.Tag` is stripped; the read, the browse upsert, the mapping guards, the tag-list/import/check lookups and the move overlap all go through it, and only for a source whose JSON config has `stable_addresses: true` (default false, no migration). The slice size is one helper shared by the poll and the connection check. A separate OPC UA server in the simulator process (`simulator/scada.py`, off unless `SIM_SCADA_PORT`) numbers its tags like the real SCADA does, renumbers on demand and enforces a read limit.

**Tech Stack:** Python 3.12, asyncua 1.1.8 (pinned `>=1.1.5,<1.2`), asyncpg/SQLAlchemy, FastAPI, pytest (testcontainers Postgres), React/Vitest, Playwright.

**Spec:** `.waves/w34.md` (the brief, rulings R1 to R16; "the brief" below). Plan ledger: `.waves/w34/progress.md`. Tier **M** with ONE tier-L piece (the address handling decides which stored point a value lands on; money): T2 to T5 ("T1a") get ONE per-task Opus review (python-reviewer or database-reviewer, `model: "opus"`, effort high) and a scoped re-review after a logic fix.

## Decisions (refining the brief; each is also a `Ruling:` in the ledger)
- **D1 One address-key helper.** `connectors/opcua_ids.py` exports `stable_address(address: str) -> str` (R2, exactly the brief's grammar) and `address_key_for(connector_type: str, config: object) -> Callable[[str], str]`: `stable_address` when `connector_type == "opcua"` and `isinstance(config, dict) and config.get("stable_addresses") is True`, else the identity function. EVERY matcher takes its key function from `address_key_for` (never reads the flag itself) and compares in Python, never as a regex in SQL. `AddressIndex` (same module): built from `(address, value)` pairs and a key function; `get(address)` looks up `key(address)`; keys shared by two or more entries are NOT served by `get` and are listed by `ambiguous_keys()`. Tag list, import and the move overlap use it.
- **D2 `browse_source` keeps its `int` return.** New `browse_source_detailed(pool, source_id, factory) -> BrowseResult(count, matched_stored, ambiguous)` (dataclass in `collector/browse.py`) does the work; `browse_source` returns `.count` (so `scan.py` and every existing test stay green); the `browse_source` JOB returns `{"count", "matched_stored", "ambiguous"}` (zeros for other connectors). Browse matching (option on, decided in Python after loading the source's points with their mapped flag): for each descriptor `d` (address already stable), `key = stable_address(d.address)`; existing points with that key `L`: `len(L)==0` insert under `d.address`; `len(L)==1` update that point's name/type/unit by id and keep its stored address (`matched_stored += 1` when the stored address differs from `d.address`); `len(L)>=2`: if exactly one is mapped update that one (`matched_stored` as above), else touch none and `ambiguous += 1`; a SECOND descriptor of the same browse with a key already handled counts as `ambiguous` and inserts nothing (two server nodes with one stable form is exactly the R13(1) case). Option off: today's upsert, unchanged.
- **D3 Locks.** Source row FIRST, always. PATCH already takes it (FOR UPDATE). `accept` already takes it (FOR NO KEY UPDATE). `create_mapping` and the tag-list commit take it (`with_for_update(key_share=True)`, i.e. FOR NO KEY UPDATE, the same mode `accept` uses, which conflicts with PATCH's FOR UPDATE and with itself) BEFORE `lock_assets` and any point/mapping insert, and ONLY for a source with `connector_type == "opcua"` (every other source: no new lock, no new behaviour). The guard helper (`api/address_guard.py`) is called after that lock. The browse (collector) takes no source lock (it never did): a browse racing a mapping is benign (it updates the one mapped candidate or counts `ambiguous`). The Opus review ticks each route against PATCH.
- **D4 The guard helper.** `api/address_guard.py`: `async def mapped_twin(db, source, point_id) -> Point | None` (the OTHER mapped point of `source` with the same stable form as `point_id`'s address, only when `address_key_for(source.connector_type, source.config)` is not the identity; one SELECT of the source's mapped points' `(id, address)`); `async def mapped_twins_of_source(db, source) -> list[tuple[Point, Point]]` (first five pairs for the PATCH refusal text, sorted by id); `twin_sentence(a, b)` builds the owner's sentence (brief R4). Used by PATCH, `create_mapping`, `accept` (every point of the request, also against each other) and the tag-list commit.
- **D5 `read()` shape (T2).** With the option on: `sent[i] = stable_address(stored[i])`; stored addresses that are identical strings read once; a group of DISTINCT stored strings with one stable form is not read: each comes back BAD, status `two points are the same tag (stable address <x>)`; the rest are read; the answer is built from the caller's list in the caller's order (`strict=True` zip kept). Option off: the code path is the old one (no key function call at all).
- **D6 Slices (T7).** `slice_size(server_limit, cap)` in `opcua_ids.py` (R9). The poll's connector asks `MaxNodesPerRead` once per instance inside its first read session, caches the size and a halved size on `self`. `BadTooManyOperations` = `ua.UaStatusCodeError` with that code on the whole request (the shape server raises it; fact-check item 9 confirms how 1.1.8 surfaces a ServiceFault). Every count in the brief (450 -> 200/200/50, advertised 120 -> 120s, advertises 0 but enforces 120 -> one refused 200 then 100s) is a test against the shape server's counters.
- **D7 Faster browse keeps today's order exactly (T10).** The walker fetches the tree level by level (batched Browse with BrowseNext, batched DisplayName and unit reads) into memory and then REPLAYS today's depth-first walk over it (`stack.pop()` order, first-visit `seen`, namespace-0 skip, then `sorted(key=name)` stable), so tie order and dedupe are identical, not only the default simulator's golden. New module `connectors/opcua_browse.py`; `OpcUaConnector.browse` delegates to it. Falls back to nothing: if the golden `cmp` fails, T10 does not merge (R1).
