# w36: Discovery at scale by tag shapes - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax. The brief with every ruling (R1 to R17) is `.waves/w36.md`; this plan refines it and wins where they differ (see "Plan rulings").

**Goal:** a person maps a large source (about 15,000 tags) by deciding about a few dozen tag SHAPES (billing first), never thousands of points; every decision goes through the existing tag-list dry run, commit and Undo; and a large source can no longer freeze Discovery or slow the Points page.

**Architecture:** a pure package `backend/dcdash/shapes/` (`core.py` groups a source's points into shapes; `lines.py` turns shape decisions into tag-list CSV lines plus safety checks), two new read-only routes in `api/shapes.py`, an additive `large` field on `GET /api/discovery/graph` that trims a source over 1,000 points to its mapped points, a new page `/sources/:id/shapes` that ends in the EXISTING `POST /api/sources/{id}/tag-list` (dry run, then real run with `expect_*`, Undo toast), two canvas guards and a 200-row cap on the Points page. No migration, no permission, no write path of its own; nothing under `core/`, `figures/`, `ingest/`, `collector/` changes (R2).

**Tech Stack:** Python 3.12 / FastAPI / SQLAlchemy async / pytest (`uv run pytest`), React 19 / TypeScript / @xyflow/react / Vitest / Playwright.

**Spec:** `.waves/w36.md` (the brief). Branch `wave/w36` from `main` f6dd393 (schema 0018). Tier M, tier-L process for T2 (R1, brief header).

## The contract (backend and front end build against exactly this)
**Shape rules (`shapes/core.py`, R3).** `member_text(address, name)` = `tag_name(address)` if `has_number_prefix(address)`; else `name` when `name != address`; else (the name fell back to the node id) the part after the cluster of a stable form `[ns=N;]s=<cluster>.<tag>` (regex `^(?:ns=[0-9]+;)?s=[^.\s]*\.(\S+)$`), else `name`. Digit runs are ASCII `[0-9]+` only (a Unicode digit such as Arabic-Indic is an ordinary character; documented, tested). `shape_key(text)` = text with every digit run replaced by `#`, case-folded. Label = the first member's spelling with the digits of a run kept when EVERY member has the same digit string at that run, else `#`. Letters are never generalised. A key with one member is not a row (`other`). Equipment of a member = first token of `_tokens(text)`; per-equipment count = the largest number of members of one shape on one equipment value. Equipment-population check (R9 outlier): population = all equipment values (over ALL the source's points) whose first-token shape key equals the first-token shape of this shape's equipment; `with_shape` = those with at least one member of this shape; `missing` = the rest (first 5 names, then `missing_total`); `equipment` is `null` when the member text has fewer than 2 tokens. `duplicates` of a shape = the number of its members whose `member_text` equals another member's text exactly (a renumbering that left both numbered addresses of every tag in a source whose option "Stable tag addresses" is off; `same_tag_map` is `{}` there). `similar`: shapes with the same rest-of-key after the first token, the same guessed metric and unit hint set, first tokens of equal length >= 3 that differ in exactly one character position and that character is a letter in both.
Order of rows: `billing == "counter"` first, then `"power"`, then the rest; inside each group by member count descending, then by label (natural). `billing`: `counter` when the shape's suggestion metric is `energy_kwh`, `power` when `active_power_kw`, else `null`.
Suggestion: `guess_mapping` over the members; the shape's suggestion is the most common `(metric, scale, custom_unit)`; `mixed: true` when members disagree; `interval_seconds` = `default_interval(metric)`; always `guess: true`. `unit_hints`: up to 3 distinct non-empty hints; `mixed_units: true` when more than one distinct non-empty hint exists.

**`GET /api/sources/{source_id}/shapes?q=` (`discovery.view`)** answers
`{source_id, source_name, points, mapped, other_tags, other_examples: [{name,address} x3], shapes: [Shape x <=300], shapes_total (all shapes of the source before `q` and the cap), more_shapes, assets: [{id,parent_id,name,kind,icon}], matches?: {count, first: [{name,address,shape: key|null} x5]}}`
with `Shape = {key, label, count, mapped, twins, duplicates, examples: [{name,address} x3], unit_hints: [str], mixed_units: bool, suggestion: {metric, scale, interval_seconds, custom_unit, guess: true, mixed: bool}, billing: "counter"|"power"|null, per_equipment: int, equipment: {population, with_shape, missing: [str x<=5], missing_total}|null, similar: [key], rule: null}`. `q` (2 to 100 chars, plain, case-insensitive substring of name or address; shorter or longer is a 422) keeps the shapes with a matching member and adds `matches`. 404 for an unknown source. One statement for the source's points plus the mappings of those points; one Python pass. Gate: under 1 s at 30,000 points on the look stack (ledger).

**`POST /api/sources/{source_id}/shapes/lines` (`discovery.accept`, read-only, no audit; EXEMPT with the reason "a read sent as POST: the body is the decisions")** takes
`{decisions: [{shape: key, metric: Metric, unit?: str<=20, scale?: float>0, interval_seconds?: int>=1, name_from: "part1"|"parts12"|"part1_part2"}] (1..60), parent_id: int|null (INT32), create_assets: bool}` (extra keys forbidden; `scale` bounded like the planner's `Scale`/`MAX_SCALE`, `interval_seconds` <= 2,678,400, `unit` printable: a bad value is a 422, not a problem line; the path id is `SourceId`, INT32) and answers
`{csv: str, lines: int, blocking: bool, by_shape: [{shape, label, lines, assets, skipped_mapped, skipped_twins}], checks: [{kind, severity: "blocking"|"warning", shape: key|null, text}], samples: [{shape, tag, address, asset, unit_hint, metric, scale}] (<=5 per shape, natural order), plan_assets: int|null, parent_path: [str]}`. `by_shape[].assets` = the NEW asset path elements below the parent that the decision's lines would create, an UPPER BOUND (an asset that already exists is counted as new; for `part1_part2` the parents and the children together: 200 PDUs with one meter each say 400): the page says "up to". `samples[].scale` is the scale actually written. `plan_assets` = `len(plan.assets)` of the route's own read-only planner run (the assets that run would create), `null` when the planner did not run (a check blocked before it, or no line); `parent_path` = the names it put the new assets under (`[]` for the top level, also for a parent that is gone). **The parent is chosen by id and written by name**, so the page refuses **Map N points** (and reloads the lines) when the tag-list dry run's `assets_to_create_total` differs from `plan_assets`: a parent renamed or deleted after the lines call would otherwise be planned as a second tree.
The server re-reads the source's points (never the client's list) and runs the same shape grouping. CSV: header `tag,asset,metric,unit,scale,interval_seconds` unquoted; every data cell quoted with `"` doubled; `tag` = the stored address; `asset` = the parent's path from the root (names joined with `/`) + `/` + the derived name (`part1` = first token, `parts12` = first two tokens joined by one space, `part1_part2` = first token as an asset and the second as a child asset beneath it); `metric` the decision's; for a non-custom metric `unit` is empty (the planner never sees the unit, so `lines` reads the shape's unit hints itself with `ingest.normalise.scale_for`, hints compared without case and without spaces, over ALL the shape's members) and `scale` is: with ONE hint on EVERY member, `scale_for(hint, metric)` for every line (a decision `scale` that is not `math.isclose` to it, rel 1e-9, blocks as `units`; a hint `scale_for` refuses blocks as `units` unless the decision states a `scale`, which is then used); with several hints, or a hint on some members and none on the others, a blocking `mixed_units`; with no hint on any member, the decision's scale, else the shape's suggestion scale when the metric equals the suggested metric, else 1 (written empty when 1); for `custom` the unit is the decision's unit, else the shape's single unit hint, else a blocking check; `interval_seconds` only when the decision gives it. Mapped members and twins of mapped points are left out and counted. `csv` is `""` when `blocking`. **Names are compared by the database key** (`lower(btrim(regexp_replace(name, '\s+', ' ', 'g')))`, the `_PART_KEYS` statement of `api/tag_lists.py`), never by Python `casefold`: `build_lines` takes a `key_of(part) -> str` argument that the route fills from PostgreSQL (the pure tests pass `" ".join(s.split()).lower()`). **After building the CSV the route runs `parse_tag_list(csv.encode())` and `api.tag_lists._plan_for(db, source_id, connector_type, config, parsed, create_assets, lock=False)` and turns a `TagListRefused` or every planner problem into blocking checks of kind `planner` (the first 5, each with tag, derived asset and the planner's own reason; the rest counted), so no list the planner would refuse is ever offered.** Check kinds: `gone` (shape key not in the source now), `too_many` (more than 1,000 lines, OR more than 1,000 NEW asset path elements below the parent counted across all decisions together and conservatively as if none existed: `part1` and `parts12` one per distinct derived name, `part1_part2` the distinct first parts plus the distinct (first, second) pairs: `at most 1,000 tags at a time (the limit of a tag list): choose fewer shapes`), `collision` (two lines on one derived asset key with one non-custom metric, inside a shape or across decisions; two clusters' tags of one name, whose stable addresses differ, are a collision that names both addresses), `renumbered` (blocking, under EVERY metric, custom too; shown INSTEAD of `collision` when the colliding members have equal `member_text` AND equal `stable_address`, and for an unmapped member whose tag is already mapped under another numbered spelling: `200 tags of this shape appear twice (the SCADA renumbered them); switch on "Stable tag addresses" for this source and browse again, or decide them on the Points page`), `mixed_units` (non-custom metric and more than one distinct unit hint compared case-insensitively and without spaces, so `kWh` and `kwh` are one, OR a hint on some members and none on the others: `This shape has the units kWh and Wh (3 name kWh and 1 names Wh); map it as custom or decide it on the Points page`, `120 tags of this shape name the unit Wh and 80 name none; map it as custom or decide it on the Points page`), `units` (non-custom metric, one hint on every member: the decision's scale contradicts the unit, `The unit "Wh" of the 3 tags of this shape means a scale of 0.001, but the scale chosen is 1; ...`, or the metric does not know the unit and the decision gives no scale, `... is not one that energy_kwh knows; map it as custom, or decide them on the Points page`), `address` (blocking, per shape: members whose stored address a tag list cannot name exactly are NOT written: a space at the start or end, an unprintable character such as a line break or a tab, or more than 500 characters: `3 tags of this shape have an address a tag list cannot name exactly (...); decide them on the Points page`), `name` (an empty or over-100-character derived name, a member with too few parts, a parent name or derived name containing `/`, a parent that no longer exists), `custom_unit`, `nothing` (a decision with 0 lines left: warning), `outlier` (warning, from `equipment`). Texts are plain sentences naming the numbers and an example, e.g. `3 tags of this shape would land on each asset (PDUA01 gets PL1, PL2, PL3); decide those tags on the Points page` (the advice offers "parts 1 and 2" only where it would really separate the tags), `198 of 200 like PDUA01 have this tag; PDUA17 and PDUA44 do not`.

**`GET /api/discovery/graph` (R4).** Constant `LARGE_SOURCE_POINTS = 1000` in `api/discovery.py`. A source with MORE than 1,000 points gets `large: {points, mapped, unmapped, rules_new}` (`unmapped` = points that are unmapped AND not the twin of a mapped point, the client's `isOfferable`, `lib/graph.ts:161`; `rules_new` 0 until T7), `point_count` = all its points, and `clusters`/`ungrouped` built (by the same `suggest_groups`, rows read `ORDER BY name, id` as today) from ONLY its mapped points plus the unmapped twins of mapped points (so mapped edges and twin rows still draw). `source_json` takes the total as a keyword (`total: int | None`) and uses it for BOTH `point_count` and `needs_credentials` (`not rows` would turn on for a large source with nothing mapped). A source with 1,000 points or fewer has exactly today's keys and values.
