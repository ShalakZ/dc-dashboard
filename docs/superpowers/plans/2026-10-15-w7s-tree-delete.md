## Facts checked in the code (LESSONS A12: the brief is not law)

- **What the owner saw.** LVP01 was the OPEN asset (`.node.is-selected`: `app.css:374` gives it `background: var(--accent-tint)` and a 3px left bar), LVP02/LVP03 were the picks (`tree-move.css:19`: the SAME `--accent-tint` plus a 1px frame). The count "2 picked" was right; the look told him 3. The Delete he pressed was the asset page's own (`assetActions` in `AssetsPage.tsx:52`), hence `Delete "LVP01"`. Picking exists only for Move (`PickSlot` in `AssetTree.tsx:285` offers `Move to...` and `Clear`).
- **Picking is gated by `assets.edit`**, nothing else: `move` (the whole feature bundle) is `undefined` without it, `kit` is null, no row is pickable, no `PickSlot`. Built-in roles: Viewer and Operator hold neither `assets.edit` nor `assets.delete` (`permissions.py:86-87`), Admin holds all, a custom role can hold `assets.edit` without `assets.delete`. So "the pick bar shows Delete only with `assets.delete`" can only be seen by Admin and by custom roles; the e2e case "no Delete" needs a custom role with `assets.view` + `assets.edit` (see w7p's role set-up, `e2e/roles.ts`).
- **The delete route** (`backend/dcdash/api/assets.py:177-225`): `GET /api/assets/{id}/impact` (`assets.delete`) returns `{assets, mappings, tariffs}` of the SUBTREE (the asset itself counts in `assets`). `DELETE /api/assets/{id}?confirm=true&expect_assets=&expect_mappings=&expect_tariffs=` locks the subtree, answers 404 "asset not found" when it is gone, 409 `{detail, assets, mappings, tariffs}` when any real count is HIGHER than the expectation (lower is fine), and writes ONE `asset.deleted` audit row `{asset_id, name, assets, mappings, tariffs}` per call. **Deleting a parent deletes its children**, so an id picked inside a picked parent answers 404 if it is sent after the parent: only roots may be sent (below).
- **Client helpers that exist:** `loadAssetImpact(id)` (`api/queries.ts:212`); `assetDeletePath(id, seen)`, `assetImpact(error)` (the 409 counts) and `assetLoss(impact)` (the sentence "N assets, M mappings and K tariffs will be deleted; their past energy and cost figures disappear from Billing and dashboards.") in `lib/impact.ts`; `toRoots(ids, index)` and `indexTree(tree)` (`has`, `parentOf`, `rankOf`) in `lib/treeMove.ts` (roots in tree order, ids not in the tree ignored); `visibleOrder(nodes, collapsed, visible)` in `lib/treeSelect.ts`; `namesLine(names, shown = 8)` in `lib/kindsBulk.ts`; `ConfirmDeleteDialog` (`message`, `loading`, `loadError`, `confirmLabel`, `onConfirm` whose rejection stays in the dialog, focus in / Tab wrap / Escape / focus back to the opener if it is still connected); `ImpactDeleteDialog` (single asset: `useQuery` with `gcTime 0`, a `refused` state when the server answers 409 with new counts); `useInvalidate()` (`api/queries.ts:262`, returns a promise); `useToast()` (`success`, `info`, `error`); `upperFirst` (`lib/upperFirst.ts`); `ApiError {status, detail, body}`.
- **The picks follow the list:** `AssetTree.tsx:530` `store.prune(byId.keys())` drops deleted ids from the picks as soon as the asset list no longer has them; failed or untried picks stay picked with no extra code.
- **Where the single delete navigates:** `AssetsPage.removed` leaves the page FIRST (`navigate("/assets")`) and only then refreshes (a refetch of the mounted summary of a deleted asset flashes a 404).
- **W7q's focus rule:** after a delete `focus({ preventScroll: true })` (an unscrolled focus call jumped the page to the top); Layout's `#main` has `tabIndex -1` and is the last-resort target (`useTreeMove.focusMainIfLost`).

The column's current width is `width.now` in `useTreeWidth` (`AssetTree.tsx:226`).

## Decisions taken here (the brief stands; these refine it; the owner may overrule any)

1. **The bar's Delete exists only while something is picked** (`count > 0`) and the viewer holds `assets.delete`; with nothing picked the bar keeps its hint and Move to... for the open asset, and the open asset's own Delete stays where it is (the page header). One place per meaning. No keyboard shortcut (S1). It is a text button "Delete" (accessible name "Delete the 2 picked assets": it contains the visible word), `type="button"`, `aria-disabled` plus a click guard while the page is locked (LESSONS A5), with the existing destructive styling (existing tokens only).
2. **Only roots are deleted.** `planDelete(ids, index)` reduces the picks with `toRoots`; a pick below another pick goes with its root. The dialog lists every picked name (title counts picks: `Delete 3 assets?`), says for each pruned pick `LVP02 is inside Data_Hall_1, which is also picked, so it goes with it.` (first 3, then `and N more are inside other picked assets, so they go with them.`), and the totals come from the roots' impacts only, so nothing is counted or sent twice (S2).
3. **Impact per root, with a small pool.** The dialog opens at once ("Checking what this deletes…") and asks `GET /api/assets/{id}/impact` for each root, at most 6 in flight, in a `useQuery` with the ImpactDeleteDialog's options (`gcTime 0`, `staleTime 0`, `retry false`, no refetch on focus). Any failure (a 404 included) is a `loadError` ("Could not check what this deletes: …") and Delete stays off: Cancel, the tree refreshes, try again. No new batch route (R4).
4. **Cap: 100 roots** (`MAX_ROOTS`). Over it no dialog opens; an error toast says `Up to 100 assets can be deleted at once (you picked 140 top-level ones). Pick fewer.` (it counts roots, because a picked branch counts once). Cost if wrong: an owner with 150 test roots deletes in two rounds.
5. **Plain or not.** `sum` is the sum of the roots' impacts. Unpicked descendants = `max(0, sum.assets - picked.length)`. Plain = no unpicked descendants, `sum.mappings === 0`, `sum.tariffs === 0`: message = names + pruned notes + `This can't be undone.`, button `Delete`. Otherwise the message is names + pruned notes + `assetLoss(sum)` (verbatim, so the billing warning is the existing words) + `This can't be undone.`, button `Delete anyway`. While loading the dialog shows the checking line and the button `Delete` (no width change when the answer lands: the ImpactDeleteDialog rule).
6. **The loop** (`deleteAssetsOneByOne`): roots in tree order, ONE `DELETE assetDeletePath(id, seen)` at a time with the counts that root's impact showed (or the newer counts after a refusal); a 404 is "already gone" (counted, not a failure, the loop goes on); **the first other failure stops the loop** (R5: deletion is one-way; after a surprise the person looks again): that root is `failed {id, name, reason, now?}`, every later root is `notTried`. `now` is the 409's new counts (`assetImpact(error)`). Reasons are sentences: 409 `more was added under it since the numbers were shown`, 401 `Your session has ended. Sign in again.`, otherwise `upperFirst(error.message)`. The sum of `seen.assets` over the deleted roots is `assets` (how many assets went).
7. **What the dialog does with the result.** Nothing went (no `deleted`, no `gone`) and the failure carries `now` (the first root grew): the dialog shows the new numbers (a `newer` map overrides that root's impact) and throws `More was added while this was open. The numbers above are updated; delete again to confirm.` (the single dialog's sentence); nothing is deleted. Nothing went, any other failure: throw `Error(<name> + reason)`, the dialog stays open and shows it. Something went: `onDone(result)`, the dialog closes, one toast: all gone -> success `Deleted 3 assets` (`Deleted 41 assets` when branches went: the server's subtree counts, the numbers the dialog showed; ` 1 was already gone.` appended for 404s; nothing but 404s -> info `Those assets were already deleted.`); stopped -> ERROR toast `Deleted 2 assets. "LVP03" could not be deleted: <reason>. 1 was not tried.` (the not-tried clause only when there are some).
8. **Invalidate once, after the loop; navigate before it.** `useTreeDelete.run` = the loop, then (if the open asset is a deleted/gone root or below one) `navigate` to the parent of that root (`/assets/<parent>`; `/assets` for a top-level root) (R7), then `await invalidate(keys.assets, keys.fleet, keys.billing, keys.widgetData, keys.tariffs, keys.auditAll, keys.graph)` in a `finally` (the set `useMoveAssets` refreshes; also after a partial failure and when nothing went: the screen may be out of date). The open asset is NOT navigated away when its delete failed or was not tried.
9. **Focus (S4, W7q's rule).** At the press the tree computes `focusAfter` (`focusAfterDelete`): the first surviving row after the first picked row in the visible order (a picked row's whole subtree counts as picked), else the last surviving row before it, else `null`. After a **full** success the hook focuses `ul.tree a[href="/assets/<focusAfter>"]`, else `#asset-tree-filter`, else `#main`, always `focus({ preventScroll: true })`, in an effect after the render that removed the dialog (so the dialog's own clean-up cannot undo it; the `useTreeMove.refocus` pattern). After a partial result nothing is done: the picks that remain keep the Delete button alive, and `ConfirmDeleteDialog` hands the focus back to it. The page never scrolls.
10. **The open row looks different from a pick (S3).** `app.css` `.node.is-selected` loses `background: var(--accent-tint)`: the open row keeps the 3px accent bar, the bold `--accent-ink` name and the accent icon; a pick keeps tint + 1px frame; open + picked is bar + frame + tint (the existing `.node[data-picked].is-selected` rule). No new token. Ink on the plain tree background must reach 4.5:1 in all eight looks (4 presets x light/dark): a test computes it from `themes.css`. `aria-current` stays. The bar's count text keeps `N picked`; when an open asset exists and is NOT picked, the count carries `title="The open asset is not counted unless it is also picked."` and a `sr-only` sentence `The open asset, <name>, is not counted.` in the group (sighted and screen-reader users get the same fact).
11. **The bar at the narrow end.** For a viewer who sees Delete (`assets.delete`) and a column narrower than `SLOT_ONE_LINE_MIN` (measured by the implementer from the real widths of "999 picked", Move to..., Clear and Delete in a browser; a constant in `AssetTree.tsx` with the measurement in a comment), the slot is TWO reserved lines from the start (the text on the first, the buttons on the second), so picking never moves the rows (LESSONS A2/A4). Wider columns and viewers without Delete keep today's single 32px line, byte for byte (no regression risk for everybody else).
12. **Not touched (S5):** the asset page's Delete, the kinds page, the move flow. A pick bar Delete acts on the PICKS only, never on the open asset unless it is picked.

## Rulings (also in the ledger)

Cost if wrong: N requests (cap 100) and a window in which the tree is half-deleted (reported honestly).
- **R5** Stop at the first failure (the brief's wording) instead of W7q's collect-and-continue. Cost if wrong: after one surprise the person re-picks the rest.
- **R6** Cap of 100 roots. **R7** After the open asset (or its ancestor) is deleted the page goes to the parent of the deleted root, else `/assets` (the single delete goes to `/assets`; the parent keeps the person where they were working). Cost if wrong: a one-line change.
- **R8** The toast counts assets that went (the server's subtree counts), not picks.
- **R9** A two-line slot only at narrow widths and only for viewers with Delete (Decision 11).
