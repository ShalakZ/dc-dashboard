# W7m: asset kinds as data, with a default icon each Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An administrator says ONCE what each kind of asset looks like. A new registry of asset kinds (`asset_kinds`, migration 0010) gives every kind a name and a default icon; an asset with no icon of its own shows its kind's icon. The keyword guesser (`lib/kindIcon.ts`) stays only as the suggestion offered when a kind is created and as the fallback for text that is not in the registry. Nothing the owner can see changes on upgrade.

**Architecture:** `asset_kinds(id, name, key, icon, created_at)`; `key` is the normalised name (Unicode NFC, blanks collapsed and trimmed, lower case: the front end's `kindKey` rule, computed in Python) under a UNIQUE index, so "Rack" and " rack " are one kind. `assets.kind` stays free text with no foreign key. The SERVER resolves the effective kind icon: `AssetOut` and the asset summary gain `kind_icon` (the icon of the registry kind whose key matches the asset's kind, `null` when none matches), so the tree, the header, quick find and the fleet summary need no second fetch and cannot flash. Display rule, front end: the asset's own `icon` (if in the catalogue), else `kind_icon` (if in the catalogue), else, ONLY when `kind_icon` is null/absent (unregistered text), the keyword matcher `kindIcon(kind)`, else generic. The kind routes live in `backend/dcdash/api/asset_kinds.py` (`GET/POST /api/asset-kinds`, `PATCH/DELETE /api/asset-kinds/{id}`), audited, behind `assets.view` (read) and `assets.edit` (write). Rename cascades into `assets.kind` in one transaction; delete is refused while assets use the kind. The page is `/assets/kinds`, a child route of the Assets workspace, opened from a button in the tree header.

**Tech Stack:** FastAPI + SQLAlchemy async + Alembic (pytest with a Timescale test container), React 19, react-router 7, TanStack Query 5, plain CSS, Vitest + Testing Library, Playwright (controller only).

## Decisions taken here (the brief's M1 to M7 stand; these refine them; the owner may overrule any)

1. **`asset_kinds` columns.** `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`, `name TEXT NOT NULL CHECK (btrim(name) <> '')`, `key TEXT NOT NULL CHECK (key <> '')`, `icon TEXT NOT NULL DEFAULT 'generic'`, `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`, `CREATE UNIQUE INDEX asset_kinds_key_uq ON asset_kinds (key)`. **`icon` is NOT NULL** (the brief said "NULL = generic"): one representation of "generic" instead of two (NULL and `'generic'`) removes a null case from the PATCH, the audit text and the front end. There is NO length CHECK in the database: `assets.kind` is unbounded text, so the seed must never fail on a long one; the API enforces 60 characters on every write (decision 3). Match the style of `0009_roles_permissions.py` (docstring, `UP`/`DOWN` lists, literals, nothing imported from `dcdash`).
2. **`key` is computed in Python, not in SQL.** SQL `lower()` depends on the collation; the front end's `kindKey` (`frontend/src/lib/kinds.ts`) is `kind.normalize("NFC").trim().replace(/\s+/g, " ").toLowerCase()`. `dcdash/core/asset_kinds.py::kind_key(text)` does the same: NFC, then collapse every run of ECMAScript whitespace (`[\t\n\v\f\r    -     　﻿]+`, spelled out, NOT Python's `str.split()` whose whitespace set differs) to one space, strip one leading and trailing space, `.lower()`. A frozen copy lives in the migration. Both sides are held to the SAME sample file (decision 11).
3. **Name rules (API) — validated in the route, not in an `Annotated` type** (plan review I6: a pydantic type answers a list that `ApiError.describe` renders as "name: Value error, …", and `StringConstraints(strip_whitespace=True)` does not strip the ES whitespace set). The body field is `name: str = Field(max_length=256)` (so a number, a list or null is still a 422 before coercion). A helper `clean_kind_name(raw) -> str` in `core/asset_kinds.py`, called by the routes in the way `roles.clean_name` is (read it, and `roles.refuse_unseen_characters`), raising `HTTPException(422, "<plain sentence>")`: (1) NFC; (2) replace each run of the ES whitespace class (decision 2) by one space, then `strip(" ")`, so the stored name always equals the front end's `cleanKind` of the same text; (3) 1 to 60 characters, else "A kind needs a name" / "A kind name is at most 60 characters"; (4) `roles.refuse_unseen_characters(name, "a kind name")` (control characters, invisible marks such as U+200B and bidi overrides are refused). The key must be non-empty after normalisation. Seeded names can be longer than 60 (decision 4): the 60-character rule applies to what a person writes.
4. **Seeding (migration 0010).** (a) every distinct `assets.kind` with a non-blank key and at most 200 UTF-16 code units (the matcher's own clamp, see decision 5): group by key IN PYTHON; ONE row per key, the `name` is `cleanKind(most used spelling)` (ES whitespace collapsed and trimmed; ties: code-point order of the raw spelling, `sorted(..., key=lambda s: (-n, s))`; never SQL `ORDER BY`, whose collation is not code-point), the `icon` is the keyword matcher's answer for the RAW most-used spelling; **a key whose spellings do not ALL get the same matcher answer is NOT seeded** (every spelling keeps today's matcher result: `LVPanel` -> panel and `lvpanel` -> generic share a key; plan review I2), and the rehearsal lists such keys; (b) then the starters `Site, Building, Room, Row, Rack, Panel, Meter, Circuit, Other equipment` and `generic` for any key that NO asset uses (a starter is skipped for a key assets already use, seeded or not: otherwise `SiTe`/`Site` would be re-seeded by the starter), with the matcher's answer for the name (`site building room row rack panel meter circuit generic generic`; `generic` gets `'generic'`). Rows are inserted in key order, so ids are stable between rehearsals. Longer, blank and conflicting kinds are not registered. Seeded names may exceed 60 characters; `KindForm` applies the 60-character check only when the name was edited.
5. **The matcher is ported ONCE, into the migration.** `0010_asset_kinds.py` holds `TABLE`, `words()` and `suggest_icon(kind) -> str` (a catalogue id such as `"panel"`, `"generic"` when no word is recognised), a line-for-line port of `lib/kindIcon.ts` (plan review I1 ran the TypeScript against a draft port on 20,100 inputs; the traps are exactly these): `\p{L}\p{N}` splits as `re.split(r"[\W_]+", ...)` (proven identical); the digit boundaries are `([A-Za-z])([0-9])` and `([0-9])([A-Za-z])`, NEVER `\d` (Python's `\d` matches every Unicode digit, JavaScript's only ASCII: `UPS٣` and `Rack１` must stay generic); the clamp counts UTF-16 code units like `kind.slice(0, 200)`: `s.encode("utf-16-le", "surrogatepass")[:400].decode("utf-16-le", "surrogatepass")` (a string of 100 emoji plus ` pump` is 105 code points but 205 units and must stay generic); the token joins use `re.fullmatch`, not `^...$`; lookahead `(?!s(?![a-z]))`, `[A-Za-z]` and the replace semantics port unchanged. The migration's functions are loaded by the tests through `importlib` (the file name starts with a digit). The runtime never needs it (the front end suggests icons).
6. **The effective icon is resolved by the server (`kind_icon`).** `AssetOut.kind_icon: str | None` and `data.py`'s summary `"asset"` dict gain it. Computation: one query for the whole registry (`key -> icon`), `kind_key(asset.kind)` once per DISTINCT kind in the response (a dict cache), no per-asset query. `list_assets`, `create_asset` and `update_asset` return it (a helper `asset_out(asset, icons)` or equivalent; `response_model=AssetOut` keeps its `from_attributes`). It is NOT stored on `assets`. A stored kind-row icon the catalogue does not list is returned as stored (the front end treats an unknown id as generic, never throws).
7. **Display rule, front end.** `assetIcon(asset: { kind: string; icon?: string | null; kind_icon?: string | null })` in `lib/assetIcons.ts`: (1) `icon` when it is a catalogue id; (2) else `kind_icon` when it is a string: the catalogue entry, or generic for an id the catalogue lacks; (3) else (`kind_icon` null or undefined: the kind is not in the registry, or an old fixture) `kindIcon(kind)`. `iconIdFor(name: IconName): string` (the catalogue id of a `kind*` icon name, `"generic"` otherwise) is added for the suggestion. The `AssetsSummary` "By kind" list resolves a kind NAME through the registry list (`useAssetKinds`) by `kindKey`, else `kindIcon(name)`.
8. **Permissions (M5).** NO new permission. Reads need `assets.view`; create, rename, change the icon and delete need `assets.edit` (a kind is a property of assets, a rename rewrites `assets.kind`, which `assets.edit` already allows; `assets.delete` is for deleting assets). Consequence, stated plainly: everyone who can save an asset can register its kind, so the brief's "person without the permission" path of M6 cannot occur through the dialog; the dialog still treats a failed registration as non-fatal. The catalogue description of `assets.edit` changes to "Add and edit assets and asset kinds, and map points to them." in `core/permissions.py` ONLY (review M1: `frontend/src/lib/permissions.ts` carries no descriptions and `test_permissions_parity.py` compares ids, order and labels) and in the README's permission table (around README.md:455, which repeats the old text; `test_readme_ops.py` may pin it: run it). Add the four routes to `tests/auth_expectations.py::ROUTE_PERMISSIONS`.
9. **Rename cascade (M4).** `PATCH /api/asset-kinds/{id}` with a new `name`: lock the kind row (`SELECT ... FOR UPDATE`); compute the new key; another row with that key is a 409 (`A kind named "X" already exists`); the SAME row with the same key (a case change, a blank fix) is allowed. The spellings to rewrite are found in Python: `SELECT DISTINCT kind FROM assets`, keep those whose `kind_key` equals the OLD key, then `UPDATE assets SET kind = :new WHERE kind = ANY(:spellings)`; `asset_count` = rows updated. All in the request's one transaction; the audit row (`kind.renamed`) is added before the single commit. A duplicate that two requests race into is caught as `IntegrityError` on the unique index (`exc.orig.sqlstate == "23505"`, as `roles.py` does), rolled back and answered as the same 409. Order inside the route (review M3): look the row up `with_for_update` FIRST (an unknown id, even with an empty body, is a 404, never a 500: the gate probes send `PATCH .../999999` with `{}`); set `name`/`key`, then `await db.flush()` INSIDE the 409 guard (like `roles.py:167-176`) BEFORE the `SELECT DISTINCT`, otherwise autoflush raises the `IntegrityError` from inside the read, outside the guard. **No table lock** (review M4, a Ruling): an asset written with the OLD spelling mid-rename, or created during a delete's count, leaves the same state a stale client produces anyway (free text, an unregistered key falls back to the matcher), and `LOCK TABLE assets IN SHARE ROW EXCLUSIVE MODE` would deadlock with `delete_asset` (ROW SHARE then ROW EXCLUSIVE). If a lock is ever wanted it is `IN EXCLUSIVE MODE` right after the kind-row lock.
10. **Delete (M4).** `DELETE /api/asset-kinds/{id}`: lock the row, count the assets whose key matches (as in decision 9); more than zero is a 409 with `{"detail": "3 assets use this kind. Change their kind first.", "assets": 3}`; otherwise delete and audit (`kind.deleted`, with the name and icon). No force option, no `confirm` parameter, no impact route: the list already carries `asset_count`. Deleting the unused kind `generic` is allowed (new assets still default to the text `generic`), and the asset dialog NEVER re-registers the key `generic` (decision 16; review M7), so a deleted `generic` stays deleted and the matcher answers generic for it.

It carries the brief's samples (`DC`, `LV_Panel`, `LV Panel`, `UPS`, `Battery`, `CRAC`, `Fan`, `Pump`, `Sensor`, `Pump Control Panel`, `Cooling Pump`, `Fuel Transfer Pump`, the nine starters, `generic`) and key edge cases whose answer follows from the ES spec: surrounding and inner blanks, a tab, a no-break space (U+00A0), an ideographic space (U+3000), a BOM (U+FEFF), `Éclair` as NFD and NFC (same key), `ΑΣ` final sigma, mixed case; and, from plan review I1 (answers taken from the REAL TypeScript), these `icon` rows: `UPS٣` generic, `Rack１` generic, `Pump๓` generic, 100 emoji (U+1F600) followed by ` pump` generic, `LVPanel` panel, `lvpanel` generic, `UPSRoom` ups, `PDUs` pdu, `PDUS` pdu, `DC1` site, `12Rack` rack, `Transfer Switches` circuit, `data centres` site, `Distribution Unit` pdu, `İstanbul Room` room, `ups_room` ups; and these `key` rows: `Pump\u0085Room` -> `pump\u0085room`, `Pump\u001cRoom` -> `pump\u001croom` (JS does not treat U+0085/U+001C as whitespace, Python's `split()` does), `﻿Rack` -> `rack`, `​` -> `​`. Write the characters as `\u` escapes in the JSON, never as literal invisible characters. The Python test (`test_asset_kinds_parity.py`) loads the migration's `suggest_icon` and `core.asset_kinds.kind_key` and asserts every row; the vitest test (`lib/kindSamples.test.ts`) asserts `kindKey` and the catalogue id of `kindIcon(kind)` on the same rows.
