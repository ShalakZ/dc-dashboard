# W7c: default dashboard and the Billing year/month picker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** An administrator can mark one dashboard as the default; the sidebar's Dashboards entry and the landing after sign-in then open it directly, and the list of all dashboards stays one click away (O-6). Billing gets a Year select and a Month select beside Previous/Next, so a month far back is one jump away; the years offered start at the first month that has energy data (O-8).

**Architecture:** One site setting (`settings` table, key `default_dashboard`, value `{"dashboard_id": <int>}`, no migration, no foreign key) behind `GET`/`PUT /api/dashboards/default`; deleting the default dashboard clears it in the same transaction. One read endpoint `GET /api/billing/months` returns the site-local month of the first energy reading. The front end reads both through TanStack Query hooks; the pages that use them are small edits. All CSS stays in `@layer w6`.

**Tech Stack:** FastAPI + SQLAlchemy async (pytest with a Timescale test container), React 19, react-router 7, TanStack Query 5, plain CSS, Vitest + Testing Library, Playwright (controller only).

## Decisions taken here (defaults the owner may overrule; none blocks the build)

1. **Who sets it:** administrators only (`PUT` is admin; `GET` is any signed-in user). Operators can still create, edit and delete dashboards; they just do not see "Make default".
2. **Where it is set:** the Dashboards list, in the row's `⋯` menu: "Make default" on a row that is not the default, "Clear default" on the one that is (W7b's hand-over note asked for exactly this). The owner's wording "on the dashboard screen" is read as the dashboards screen. The default row carries a small "Default" badge beside (outside) its name link so the link keeps its plain name. The dashboard page itself gets no new control.
3. **What "default" does:** the sidebar's Dashboards entry opens `/dashboards/<id>` (it stays highlighted on every `/dashboards…` path); `/` opens the default dashboard when there is one, else `/assets`; sign-in without a remembered page goes to `/` (a remembered page still wins, but an EXPLICIT sign-out forgets the page it was done on, so signing out and in again lands on `/`; an expired session (401) still remembers its page: Task 4b). The list `/dashboards` is always the list: the "Dashboards" crumb on the dashboard page and Quick find's "Dashboards" page entry go there. None set = exactly today's behaviour (sidebar to the list, landing on `/assets`). The roadmap's "All dashboards" link is the existing "Dashboards" crumb on the dashboard page (a new link named like that would collide with unscoped `getByRole("link", { name: "Dashboards" })` lookups); say so in the morning report.
4. **Deleting the default:** clears the setting in the same transaction; the `dashboard.deleted` audit row gets `"was_default": true` (only when true); the confirm text says so. A stored value that is not a positive integer, or names a dashboard that no longer exists, reads as "none".
5. **Audit:** `dashboard.default_changed` through `audit_change`, subject `{}`, before/after `{"dashboard_id", "dashboard"}` (id and name, `null` when none); setting the same value again writes nothing. `auditText.ts` gets the sentence (the parity test `test_audit_describers.py` demands it).
6. **Billing months:** "first month with data" = the site-local month (site timezone) of the earliest `readings_1h` bucket of any metered point (the meters the energy engine uses: `load_meters`). No data: `first_month` is `null` and the picker offers only the current month. Years run from the first month's year to the current year; the Month select lists only months inside `[first month, current month]` for the chosen year; changing the year clamps the month into range; Next is disabled at the current month (as today). TWO separate bounds: `selectLow = min(first_month ?? month, month, current)` and `selectHigh = max(month, current)` build ONLY the Year/Month options (so the selects always contain the selected value, even if a time-zone change moves "current" back); **Previous is disabled only when the endpoint answered with a month and `month <= first_month`**. While the request is pending, after it failed, or when it answered `null`, Previous stays enabled exactly as today.
7. Process: lighter process. One Opus plan review (it should RUN the risky parts), implementer + targeted tests per task, one short scoped Opus review of Task 1 after its commit (it changes the audit and data-deletion path, and the plan review already found a lost update there), none for the other tasks, full suites and the whole Playwright suite once at the end, ONE whole-wave Opus review that looks at the pages in a browser and uses the keyboard, one fix wave, one scoped re-review.

2. **Stored garbage:** `{"dashboard_id": "7"}`, `true`, `0`, `-1`, `1.5`, `null`, `[]`, a missing key, `99999999999` (above int32: `dashboards.id` is a 4-byte SERIAL, the driver raises on a bigger one), a value naming a dashboard that is gone (no foreign key) all read as none; so does a stored whole value that is not an object (`true`, `"x"`, `1.5`: `get_setting` raises on those, `default_dashboard()` must catch `(TypeError, ValueError)`). *Test: Task 1.*
3. **PUT body:** `dashboard_id` required; `StrictInt` with `Field(ge=1, le=2_147_483_647)` (the codebase's own pattern, `api/audit.py:114`) or `null`; `true`, `1.0`, `"3"`, `0`, `2147483648`, a missing key, extra keys → 422; unknown dashboard → 404; viewer/operator → 403; signed out → 401; same value again → 200 and no audit row. *Test: Task 1.*
4. **Delete the default** clears it in the same transaction and says so in the audit row; deleting another dashboard leaves it; PUT (set X) racing DELETE (X) ends consistent (the PUT holds the row lock `FOR UPDATE`; the DELETE's conditional clear runs after ITS row lock), and **PUT (set X) racing DELETE (Y, the old default) must NOT lose X** (the Opus plan review reproduced the lost update with a read-then-upsert delete). *Tests: Task 1, both races as real two-connection tests.*
5. **Landing:** `/` waits for the default (no flash of `/assets` first), falls back to `/assets` on an error; a remembered page (`RETURN_KEY`) beats the default; the sign-in page itself never calls the default endpoint (signed out). *Tests: Task 4.*
6. **Sidebar:** the Dashboards entry is `aria-current="page"` on `/dashboards`, `/dashboards/3` and `/dashboards/9` whatever the default is; the minimized strip's tooltip still says "Dashboards". *Tests: Task 4.*
7. **Billing months:** the first reading at 22:00 UTC on the last day of a month is already next month in Qatar (UTC+3) and still the old month in UTC; readings of points that are not meters are ignored; no data → `null`; a non-UTC process time zone changes nothing. *Tests: Task 2.*
8. **Picker:** selects always contain the selected value; Year change clamps Month into range; Previous disabled at the first month and Next at the current one; a cleared bound (endpoint failed) keeps today's behaviour; keyboard: both selects reachable by Tab, change with the arrow keys, focus not stolen by the re-render. *Tests: Task 5.*
