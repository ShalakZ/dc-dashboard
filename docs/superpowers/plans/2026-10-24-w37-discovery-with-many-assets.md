# w37: Discovery with hundreds of mapped assets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A parent asset with more than 50 sub-assets is drawn as ONE summary node that shows them 50 at a time, so Discovery with the owner's 414 assets draws 17 nodes and about 24 edges instead of 416 and 822; the next fixes follow the measured profile.

**Architecture:** `buildGraph` (pure, `lib/graph.ts`) gets two optional view fields (`assetPageSize`, `assetsShown`); absent they change nothing, so `NO_VIEW` and every existing caller build today's graph. The walk draws the first `shown` children of a summarised parent, then one `more:asset:<parentId>` node (new node type `moreAssets`), hides the rest with their subtrees, and ends the hidden children's mapped edges on the summary. The page keeps `assetsShown` in state (session only, like a group's pages) and passes `ASSET_PAGE = 50`. Find extends the page of each summarised ancestor.

**Tech Stack:** React 19, @xyflow/react 12.12, TypeScript, vitest (jsdom), Playwright (e2e, controller only).

**Spec:** `.waves/w37.md` (the brief; rulings R1 to R16 are binding, this plan refines them).

## Decisions (refining the brief)
- **D1 Node type and id:** type `moreAssets`; id `nodeId.moreAssets(parentId)` = `more:asset:<parentId>`; data `MoreAssetsNodeData = NodeActions & { parentId: number; parentName: string; left: number; step: number; shown: number; mapped: number; navParent: string }` with `onMoreAssets?: (summaryId: string) => void` added to `NodeActions`. `draggable: false, selectable: false, focusable: false`, a left (target) handle only.
- **D2 Constants:** `export const ASSET_PAGE = 50` in `lib/graph.ts`. The summary takes TWO rows (`SUMMARY_ROWS = 2`, 128 px) so its three fixed lines never overlap the next asset; plain assets keep one row, so a graph without a summary is byte for byte as today.
- **D3 View:** `GraphView` gains optional `assetPageSize?: number` (absent = `Infinity`) and `assetsShown?: ReadonlyMap<number, number>` (parent id to how many of its children are drawn; absent = 0). A parent is summarised only when it is not closed (`assetsClosed`), has MORE than `assetPageSize` children (children by the walk's rule: `parent_id` set, not itself, and in the model) and `shown < children`. A ROOT with 60 children is summarised; what is never cut into pages is the SET of root assets (roots, orphans, self-parents, cycle heads). When a cycle head's children were already visited, only the not-yet-visited ones count in `left`. `NO_VIEW` stays as is.
- **D4 Edges:** hierarchy edge `a:<parent>>more:asset:<parent>` (plain, like asset edges); a mapped point under a hidden child ends on the summary, one edge per source, group or point, id `m:<from>>more:asset:<parent>`, label `N mapped` above one. A hidden child's subtree is hidden with it (marked visited, so a cycle or a second walk never draws it); a hidden child that is itself folded keeps its fold.
- **D5 Words:** title `400 sub-assets` (`350 more sub-assets` once something is shown; `1 sub-asset` for one); muted line `400 mapped` (the points mapped to the hidden children and everything under them, over the whole model; the line is EMPTY at 0 but its slot keeps its height, so the button never moves between presses, A2); button `Show 50` first, then `Show 50 more`, the last press `Show 30 more`; `aria-label` `Show 50 of the sub-assets under Room 3, 400 left` first, `Show 50 more of the sub-assets under Room 3, 350 left` after. The summary's wrapper has no label of its own (unfocusable).
- **D6 Show 50:** `onMoreAssets(summaryId)` sets `assetsShown[parent] = min(children, drawn + 50)` and moves the focus to the first child just drawn (`nodeId.asset`, the `onMore` pattern); after the last page the summary is gone and the focus is on that child. A parent that gets folded (`assetsClosed` has it) forgets its pages (`pruneAssetsShown`, same idea as `pruneShown`). Expand all / Expand branch never touch the pages.
- **D7 Find:** an asset target hidden behind summarised ancestors extends each such ancestor's page to the next multiple of 50 that holds the child on the path. Walk the summarised ancestors from the OUTERMOST inward with a running cost (the children each extension newly draws; their subtrees draw only what is already unfolded, so this is a guard, not an exact count): extend while the running cost stays within `EXPAND_NODE_BUDGET` (600); at the first ancestor whose extension does not fit, keep the extensions so far, do not extend that one, and target THAT ancestor's summary (`targetId` = `more:asset:<id>`, drawn because its parent is unfolded and on a page). Note, with thousands separators: `Room 3 has 5,000 sub-assets; PDU4321 is too far down to draw at once. Showing the first ones: use Show 50 more to go on.` One exported pure helper, `extendPagesFor(model, view, assetId, budget): { assetsShown; stoppedAt: number | null }`, does the walk; `findPlan` and the page's new-asset path both call it.
- **D9 New sub-asset under a summarised parent:** `onNewAssetCreated` (`DiscoveryPage.tsx:747`) calls `extendPagesFor` for the new asset once the read brought it in, so the asset is drawn and gets the focus like today (T3). A parent that is folded is unfolded by `addUnder` as today.
- **D10 Alt-drag:** the summary is never pinned (it has no place of its own) and follows its parent in every drag, like a group's `more` node; no test beyond the plain drag follower test.
- **D8 Measure the same way before and after:** `.waves/w37/measure37.mjs`, look stack 18265, 1440 x 900, unthrottled and 4x.
