# W7g: a chosen icon per asset (live preview and picker in the asset dialog) and the "Assets Tree" rename Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An admin can give every asset an icon of their choice. The Add/Edit asset dialog gets an "Icon" field with a live preview tile and an inline picker; the choice shows in the tree rows, the asset page header, and quick find. "Automatic" (the default, stored as NULL) keeps today's behaviour: the icon follows the free-text kind. The Assets workspace is renamed "Assets Tree" wherever the page is named (O-22, O-23).

**Architecture:** One additive nullable column `assets.icon TEXT` (migration 0008, no default, no backfill, no CHECK: the allow-list lives in code so the catalogue can grow without a migration). The server owns the allow-list (`backend/dcdash/core/asset_icons.py`, 28 stable lowercase ASCII ids); `POST /api/assets` and `PATCH /api/assets/{id}` validate against it (422 otherwise); `AssetOut` and the asset summary carry the raw stored value. The front end mirrors the id list in `lib/assetIcons.ts` (id, label, `IconName`), one display rule `assetIcon(asset)` (a known stored id wins, anything else falls back to `kindIcon(kind)`, never throws), and a PARITY test compares the two lists. The dialog shows a 40 px preview tile plus a caption and a "Change icon" disclosure that opens an inline grid of native radio inputs (the W7d profile-panel precedent): no nested popover, so the Modal's focus trap, Esc and z-index stay as they are.

**Tech Stack:** FastAPI + SQLAlchemy async + Alembic (pytest with a Timescale test container), React 19, react-router 7, TanStack Query 5, plain CSS, Vitest + Testing Library, Playwright (controller only).

**Resume (any fresh session):** continue executing this plan; read `git log --oneline` on `w7g-asset-icons` and the checkboxes below (a ticked step is done and committed); ledger `.superpowers/sdd/2026-10-12-w7g-asset-icons/progress.md`.

**Spec:** the owner's brief `.superpowers/sdd/overnight-w7/W7g-asset-icons.md` (G1 to G8, the owner's words, review focus), roadmap `docs/superpowers/plans/2026-10-11-w7-owner-feedback-roadmap.md` (rows O-22, O-23 are added at close-out). Model plans: W7d (a wave with a migration and the parity test), W7e (the front-end half). **Not in W7g:** uploaded or custom icons, an admin-editable kind-to-icon table, a colour per asset, icons in the Billing or Sources tables, the widgets.

## Decisions taken here (the brief's G1 to G8 stand; these refine them; the owner may overrule any)

1. **The catalogue: 28 icons.** Stored ids are stable and independent of the React names. The picker order (also the order of `ICONS`): `site` Site, `building` Building, `room` Room, `row` Row of racks, `rack` Rack, `panel` Panel, `meter` Meter, `circuit` Circuit breaker, `ups` UPS, `battery` Battery, `pdu` PDU, `generator` Generator, `transformer` Transformer, `fueltank` Fuel tank, `chiller` Chiller, `crac` Cooling unit, `fan` Fan, `pump` Pump, `server` Server, `switch` Network switch, `controller` Controller, `sensor` Sensor, `lighting` Lighting, `camera` Camera, `door` Door, `fire` Fire, `leak` Water leak, `generic` Generic. Fourteen are the existing `kind*` icons of `Icon.tsx` (site to chiller, generic; the brief said 15, the file has 14); 14 are new: `kindBattery kindFuelTank kindCrac kindFan kindPump kindServer kindSwitch kindController kindSensor kindLighting kindCamera kindDoor kindFire kindLeak` (the name is `kind` + the id in PascalCase, `fueltank` is `kindFuelTank`). Drawing brief (24-unit viewBox, 1.7 stroke from the shared `svg.i` CSS, `currentColor`, no fills except dots, distinct at 16, 24 and 40 px): **server** two stacked wide units with LED dots and a slot; **switch** one wide short unit with a row of port squares and a two-way arrow above; **crac** a tall louvred cabinet with three arrows pointing down out of its base; **battery** a vertical cell with a top terminal and a plus/minus pair; **sensor** a thermometer (tube, bulb, two ticks); **pump** a round casing with an inlet pipe on top and an outlet pipe at the right; **fan** a ring with three curved blades and a hub; **lighting** a bulb with a base and short rays; **camera** a body with a lens circle and a wall bracket; **door** a frame with a leaf, a handle dot and a floor line; **fire** a flame; **leak** a water drop over a wavy line; **fuel tank** a horizontal capsule on two legs with a cap on top; **controller** a box with a small screen and three buttons. The controller looks at a contact sheet at 16, 24 and 40 px and notes the closest pairs (expected: ups/battery, chiller/fan, rack/server, circuit/switch).
2. **Automatic is unchanged.** `kindIcon`'s word table is NOT extended with the new icons: an asset whose kind is "Pump" keeps the generic cube until someone picks the pump (the brief: "nothing changes until someone picks one"). Cost if wrong: a few kinds do not get a smarter automatic icon; one table row each later.
3. **PATCH semantics need a special case.** `update_asset` today skips every `None` in `changes` (`if value is not None: setattr(...)`), so a plain null would mean "unchanged". `icon` is handled BEFORE that loop: `if "icon" in changes: asset.icon = changes.pop("icon")` (a validated id or None); absent stays unchanged (the `exclude_unset` dict has no key). `AssetIn.icon` defaults to None.
4. **Validation shape.** A shared annotated type in `asset_icons.py`: a `BeforeValidator` that raises `ValueError("unknown icon")` unless `isinstance(value, str) and value in ICONS` (so `5`, `["server"]`, `""`, `"Server"`, `" server"`, 33 characters and `"nope"` are all 422 BEFORE any type coercion); `None` passes (field type `AssetIcon | None`). The output model has a plain `icon: str | None` (a stored id that is no longer in the list, or one a newer server wrote, is shown as stored and never fails a GET). A failed validation changes nothing (the request model fails before the route body).
5. **The asset summary carries the icon.** The asset page header reads `data.asset` of `GET /api/assets/{id}/summary` (`backend/dcdash/api/data.py`, the `"asset"` dict), not the list: that dict gets `"icon": asset.icon`. `Summary.asset` in `api/types.ts` gets `icon?: string | null`.
6. **Audit.** `_asset_values` gains `"icon"`; `audit_change` already writes only changed fields (a missing key counts as None), so editing the icon writes `before: {icon: null}, after: {icon: "server"}` and creating writes `icon` with the other fields. `auditText.ts`: `describeChange` maps the field `icon` to the label "Icon" and its values to the catalogue label (null or missing to "Automatic", an id the front end does not know to the raw id); the audit entry page must not break on a null. Existing tests that pin the exact create detail get the new key (minimal edits).
7. **TS types.** `Asset.icon?: string | null` (OPTIONAL in TypeScript, because dozens of fixtures build `Asset` literals; the API always sends it), `AssetIn.icon?: string | null`. **The dialog sends `icon` only when the user changed it** (edit) or when it is not Automatic (add): an edit of an unrelated field never re-sends a stored id, so an id the server later drops cannot make every edit of that asset a 422. Saving "Automatic" after a choice sends `icon: null`.
8. **Display rule.** `assetIcon(asset: { kind: string; icon?: string | null }): IconName` in `lib/assetIcons.ts`: the catalogue entry for `icon` when it is a string that is in the catalogue, else `kindIcon(kind)`. Used by `AssetTree` (row icon), `AssetPage` (header tile), `QuickFind` (`FindHit` gains `assetIcon?: string | null` next to `assetKind`; `quickFind.ts` fills it). `AssetsSummary`'s "By kind" list keeps `kindIcon(name)` (it counts kinds). The dashboards' asset picker shows no icons: untouched.
9. **The dialog.** Placed after Kind / New kind, before Sort order. Markup: `<div role="group" aria-labelledby=… aria-describedby=…>` with a visible label "Icon"; a row with the preview tile (`<span className="page-tile icon-preview" aria-hidden="true">`, the 40 px tile of the asset header), the caption text (`Automatic (Panel)` while Automatic, following the Kind field live including the typed new kind; the chosen icon's name otherwise) and a `Change icon` button (`aria-expanded`, `aria-controls`). Opening the grid moves focus onto the checked radio (Automatic when none); the grid is `<div role="radiogroup" aria-label="Icon choices">` of native `<input type="radio" name="asset-icon">` inside `<label className="icon-cell check" title=name>` with the SVG (`aria-hidden`) and a visually hidden name; the first cell is "Automatic" (its icon is the kind's current icon and its label says "Automatic"); the checked cell uses `--accent` / `--accent-tint` and a ring, never colour alone. Native radios give Tab to the checked one and arrow keys with selection; Home/End are NOT added. The grid stays open after a pick (arrows try icons); Esc is the Modal's (closes the dialog; nothing half-open survives because the grid state is local). A stored id the front end does not know: no cell is checked, the caption reads `Unknown icon "xyz"`, the preview shows the kind icon, and the payload leaves icon out unless the user picks. Playwright names: group `Icon`, radiogroup `Icon choices`, button `Change icon`, cells by their catalogue label (Task 4 greps these against `e2e/*.ts`). `.dialog.narrow` is 440 px wide: the grid is 8 columns of 40 px cells with a 4 px gap (about 350 px, 4 rows), inside the dialog; the collapsed dialog must fit 1024 x 640 without scrolling and the open one with at most the dialog's own scroll (`.dialog` has `overflow: auto`), judged by the controller's screenshots. All new rules inside `@layer w6`, tokens only.
10. **The rename.** "Assets Tree" in: the `navItems.ts` label (sidebar and quick find's page hit), the first crumb of `AssetPage`, the `.tree-title` of `AssetTree`, the `PageHeader` title of `AssetsSummary`, the `NotFoundPage` link ("Back to Assets Tree"). There is no `document.title` anywhere. NOT renamed: `region aria-label="Asset tree"`, the tile caption "Assets", quick find's "Tree matches / Assets" caption, the picker legend, "Add asset", "Needs attention" text, the W7f hidden status line. E2E fallout is real: `shell.ts` `navLink` matches `exact: true`, `w7a.spec.ts` has `toHaveText(["Assets", "Site"])` and `getByRole("link", { name: "Assets", exact: true })`, `w7e.spec.ts` the same crumb lookup, `heading1(page, "Assets")` is a substring match and survives, `w7d.spec.ts` and `w7e.spec.ts` route tables pair `"/assets"` with `"Assets"`; unit tests pin `"Assets"` in Layout, AssetPage, AssetsSummary and others. Task 4 audits every lookup.
11. **Process (a migration wave, lighter chain):** ONE Opus plan review that runs the risky parts, a short Opus review of Task 1 (migration, validation, PATCH null semantics, audit), none for Tasks 2 to 5, targeted tests per task, the controller's migration rehearsal on a restored copy of the dev DB, the FULL backend and frontend suites, the isolated Playwright run on a build of the final commit, ONE whole-wave Opus review in a real browser, ONE fix wave, one scoped re-review.
