# w14 Polish after w12c and w13 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Six small front-end fixes the owner agreed to after looking at w12c and w13: readable bar-chart labels (P1), a Discovery source card that shows its name and a visible empty progress track (P2), words in the Discovery bar's counts and an "on" state that does not look like focus (P3), a plain Details table (P4), a link to Tariffs from "no rate" (P5), and no sideways scroll at 800 px (P6).

**Tech Stack:** React 19, TypeScript, ECharts 5.6 (`echarts-for-react`), React Flow, plain CSS in `@layer w6`, Vitest, Playwright (`playwright-core` for looks, the `w14` project for the gate).

**Spec:** `.waves/w14.md` (the brief; the owner's words and rulings R1 to R4). Standing orders: `.waves/RESUME.md`, lessons: `.waves/LESSONS.md`.

**Tier:** M (front end only, six surfaces, several layers of one app; no data, security or money). Ruling: tier M, because six independent UI changes need the plan review, one full frontend suite, one Playwright gate and the whole-wave browser review; no backend suite (nothing under `backend/` changes; the three doc tests run after the docs edit). If wrong: a missed risk in a visual wave, mitigated by the browser review.

## Decisions

1. **P1: wrap, do not rotate or drop.** New pure module `frontend/src/components/dashboard/widgets/barAxis.ts`:
   - `export const CHAR_PX = 7.2` (estimated width of a 12 px label character, wider than the measured average so a wrapped line never reaches its neighbour), `LABEL_LINES = 3`, `LABEL_LINE_PX = 14`, `MIN_SLOT_PX = 56`, `GRID_SIDES_PX = 80` (the grid's `left: 60` + `right: 20`).
   - `export interface AxisLayout { mode: "wrap" | "rotate"; slot: number; lines: number; labels: Map<string, string>; bottom: number }`.
   - `export function barAxisLayout(labels: readonly string[], chartWidth: number): AxisLayout`: `slot = (chartWidth - GRID_SIDES_PX) / labels.length`. If `slot >= MIN_SLOT_PX`: mode `wrap`; each label becomes up to `LABEL_LINES` lines of at most `floor((slot - 8) / CHAR_PX)` characters (words are kept whole where they fit; a word longer than a line is cut by characters; what does not fit in the last line is cut in the middle with `…` while the identifying suffix `~`, `*`, `(#id)` stays whole, as `shortLabel` does). Two labels whose wrapped texts are equal keep their FULL text, wrapped over as many lines as it needs (the rule of `shortLabels`). `lines` is the longest result in lines, `bottom = 16 + lines * LABEL_LINE_PX`. If `slot < MIN_SLOT_PX`: mode `rotate`; labels are `shortLabels(labels, AXIS_CHARS)`, `bottom = 84`.
   - `barOption(data, timezone, theme = LIGHT_CHART, chartWidth = 480)`: the value-mode axis takes `interval: 0`, `formatter` from the layout (the lines joined with `\n`), `width: slot - 2` and `overflow: "break"` as a net under our own wrapping, `hideOverlap` only in `rotate` mode, `rotate: 40` in `rotate` mode, and `grid.bottom = layout.bottom`. The data keeps the full names; the tooltip is unchanged.
   - `BarWidget` measures its `.widget-chart` box (`useLayoutEffect` + `ResizeObserver`, guarded by `typeof ResizeObserver === "function"` like `AssetTree.tsx:223`) and passes the width in steps of 8 px; with no observer (jsdom, server render) the default 480 stands.
   - A slot with no data stays empty and keeps its label (R1: no new "no data" text mark; the table and tooltip already say it; backlog item).
2. **P2: two lines for the name, same `SOURCE_H`.** The title may take two lines (`-webkit-line-clamp: 2`, line-height 18, the full name stays in `title` and every accessible name); the fold, the tile and the Source actions button align to the FIRST line. The arithmetic is re-added in `graph-nodes.css.test.ts` (head max 36 + three lines of 16 + mapped 20 + Details 20 + seen 16 + padding 8 + border 2 = 130). The empty track becomes `var(--border-strong)`. **Measure first** (Task 2 step 1): if a two-line title does not fit 136 in Chromium, the fallback is to move the protocol tile from the head to the protocol line (the title gains 24 px) and show the full name in the existing `title`; the ruling is then written in the ledger.
