# w33 Discovery freshness and moving a source - Implementation Plan

> For agentic workers: implement task by task (superpowers:subagent-driven-development). Steps use checkbox (`- [ ]`) syntax. One commit per task, `git add` named files only.

**Goal:** (1) Discovery marks the discovered sources the latest scan of the same range did not find, and removes the unmapped ones in one go; (2) a source remembers who its server is (OPC UA application URI and certificate thumbprint, the simulator's instance id), and when the same server turns up at a new address the platform OFFERS to move the old source there with a preview and Undo, so its mappings (and the money behind them) survive; (3) for addresses Docker hands out, it suggests the container's name.

**Architecture:** migration `0017` adds `sources.identity JSONB NULL`. A new package `backend/dcdash/moves/` (pure matcher, loaders, the move service, URL helpers) sits OUTSIDE `core/`, so the only `core/` edit is `core/models.py` (one column; the ledger's engine id changes once: the CHANGELOG says so). Connectors learn identity through `Claim.identity` (probe) and an optional `Connector.identity()` hook (Test and the connection check). `api/moves.py` holds the two new routes; `api/discovery.py` and `api/sources.py` get additive fields. Front end: Discovery card/panel/bar changes, one new `MoveSourceDialog` used from Discovery and Sources, an Undo in the audit drawer.

**Tier L** (a migration; a write that decides which device feeds a meter's mappings). Per-task Opus reviews (effort high, `model: "opus"`): T1 migration (database-reviewer), T3 matcher, T5 move and Undo (database-reviewer). Mandatory scoped re-review after any logic fix.

## Rulings of this plan (all also in the ledger as `Ruling:`; the brief's R1-R10 stand unless changed here)
- **P1 Tier L**, per-task Opus reviews as above - cost if wrong: a missed finding surfaces in the whole-wave review.
- **P2 The identity record** (one JSON object in `sources.identity`; keys optional, never a secret, never the certificate itself): `application_uri`, `application_name`, `product_uri` (OPC UA), `thumbprint` (SHA-1 of the server certificate's DER, upper-case hex pairs joined by `:`), `instance` (the HTTP simulator's `SIM_INSTANCE_ID`), `name_hint` (`{"name": "simulator", "host": "172.20.0.5"}`, R7), `different` (`{"application_uri", "thumbprint", "instance", "at"}`: another server answered at this address; cleared when the stored server answers again). No `seen_at` (it would turn every scan into a write).
- **P3 "Usable" identity**: `usable_key(connector_type, identity)` returns `("uri", value)` for OPC UA when `application_uri` is non-empty and not in the deny-list (`urn:freeopcua:python:server`, `urn:open62541.server.application`, empty, `urn:unconfigured:application`, compared case-insensitively); `("instance", value)` for the HTTP simulator; else None. The simulator's OPC UA server announces `urn:dcdash:simulator:<id>`, so its key is a `uri`.
- **P4 Writing identity (`collector/identity.py: remember`)**: one transaction, `SELECT ... FOR NO KEY UPDATE`. Stored empty -> store what was seen. Stored and seen equal on the usable key (and the thumbprints, when both have one) -> no write, except a `name_hint` change and clearing a stale `different`. Seen differs from stored (other usable key, or the same key with another thumbprint) -> keep the stored identity, set `different`, write the journal event `source.identity_changed` (warning, both identities' fields, no secret) at most once per (source, other identity) per 24 h (`journal.allow`), never stop polling (R3). A default-URI identity is stored (it is what the server said) but is no key. No `CONFIG_CHANNEL` notification: identity is not configuration. Called by the scan (new source at creation, an existing source when met), `_test_source` and `_check_connection` (through `connector.identity()` after a decisive OK), never by the poll loop.
- **P5 Not seen (R2)** is computed by `moves/freshness.py: not_seen_map(db, sources)` in two statements: the distinct scans of the sources' newest findings (`scope_snapshot` -> `scan_digest`), and every DONE scan newer than the oldest of those; per source the NEWEST done scan with an equal digest and a larger id. Only `origin = 'discovered'` sources with a finding are ever marked. Result `{scan_id, at, last_seen_scan_id, last_seen_at}`. A deleted or edited scope changes nothing (the snapshot is what counts).
- **P6 The matcher** (`moves/match.py`) is pure; its inputs are plain frozen dataclasses built by `moves/load.py` (one pass for all offline mapped sources, no query when none is offline). Eligible old source O: type `opcua` or `simulator`, at least one mapping, and unreachable = open incident with code `unreachable` or `timeout`, or marked not seen (P5). Candidate C: discovered, `mapped == 0`, at least one point, same type, same port, same endpoint path (OPC UA; the simulator has none), a different id, and its newest finding's scan finished after O's `last_seen` (O never answered: any). Decision, in this order: (a) usable keys on BOTH sides and different -> never; both thumbprints present and different -> never; (b) usable keys equal and not ambiguous (a third source that is `online` holds the same key: ambiguous = no identity) -> `same_server`; (c) O has no usable key -> `possibly` if every address mapped on O is among C's points; (d) otherwise never. One C -> an offer; two or more -> `two` (the card says `Two servers could be this one; edit the address by hand`); none -> nothing. Extra fact on every offer: `missing_addresses` = how many of O's mapped addresses C lacks (always 0 for `possibly`), shown as a warning by the dialog.
- **P7 The move service** (`moves/service.py`) serves `dry_run` and the real run from ONE function (the dry run stops before the first write and rolls back), so the preview cannot drift from the action. Lock order: `pg_advisory_xact_lock(SCAN_START_LOCK)`, scan refusal, then `_lock_source` of the lower id and of the higher id. Everything the preview showed is re-derived on server data under those locks.
- **P8 URL rewrite** (`moves/urls.py: swap_host_port(url, host, port)`): `urlsplit`, replace only the host and port inside the netloc, keep user info verbatim (split at the LAST `@`), path, query, fragment, scheme and bracketed IPv6; the config key is `endpoint` (opcua) or `url` (simulator). Labels: `OPC UA server at {host}:{port}`, `DCDash simulator at {host}:{port}`; a name equal to the old label with an optional ` (n)` is renamed to the new label with the same ` (n)` rule used by `_insert_source` (first free); any other name is kept (R6).
- **P9 Audit rows**: `source.moved` detail `{source_id, name_before, name_after, host_before, port_before, host_after, port_after, address: "as_found"|"name", identity_before, identity_after, match: {kind, evidence, value, addresses, missing_addresses}, mappings, removed: {source_id, name, points}}`; `source.move_undone` detail `{audit_id, source_id, name_before, name_after, host_before, port_before, host_after, port_after}`. Never a config, never a URL with user info.
- **P10 Name hint (R7)** is last in the back end and carries the brief's cut line: `collector/names.py: name_hint(host)` (private IPv4 only, `ipaddress`; reverse lookup `socket.gethostbyaddr` in an executor, 3 s each; candidates shortest first: every dash-suffix of the part before the first dot with the trailing `-<digits>` removed, then that part, then the full reverse name; a candidate is offered only when its forward lookup returns exactly `{host}`; at most 50 hosts per scan). Stored as `identity.name_hint`. The graph route shows `name_hint` (a string) only while the source's current host equals the stored hint's host.
- **P11 Task 0 (live baseline)** is reduced: the "before" run is skipped (it is in the code and in the brief); the "after" proof is Task 8's spec plus a look at the real scratch stack (the gallery). Cost if wrong: no measured "before" in the CHANGELOG.
- **P12 Events page**: the new journal kind needs a line in `src/lib/eventText.ts` only if unknown kinds fall back badly there (T6 checks; the System events page must show `source.identity_changed` in plain words).
- **P13 Permissions**: no new one. Discovery's Move button needs `sources.edit` (hidden otherwise, the card keeps its sentence); the Undo needs `sources.edit` (`AuditDrawer` gate like the tag-list Undo).

## API contract (the backend produces, the front end mocks and consumes)
`GET /api/discovery/graph` - every source gains (additive; all present, null when not applicable):
```
not_seen: { scan_id, at, last_seen_scan_id, last_seen_at } | null     # discovered sources only
identity: { application_uri, application_name, product_uri, thumbprint, instance, usable: bool, different: bool } | null
name_hint: string | null                       # a Docker name for the source's current host, else null
move_candidate: { kind: "offer", from_source_id, from_name, from_endpoint, from_since: iso|null, mappings, assets, match } |
                { kind: "two", count } | null   # on a NEW (unmapped, discovered) source: it looks like an old one
```
`GET /api/sources` - every row gains `move_candidate: { kind: "offer", to_source_id, to_name, to_endpoint, match } | { kind: "two", count } | null` (offline sources only; null otherwise; no extra query when none is offline).
`match = { kind: "same_server" | "possibly", evidence: "uri" | "instance" | "addresses", value: string | null, addresses: int, missing_addresses: int }` (`addresses` = how many of O's mapped addresses C has).
`POST /api/sources/{id}/move?dry_run=1|0` (`sources.edit`), body `{ to: int, address: "as_found" | "name", expect?: { mappings, address_before, address_after } }` (`expect` is required for a real run; `address_before`/`address_after` are `host:port` strings as the preview showed them). Dry run answers 200:
```
{ dry_run: true, source: {id, name}, target: {id, name, points},
  from: {host, port, endpoint}, to: {host, port, endpoint}, address: "as_found"|"name", name_hint: string|null,
  rename: {from, to} | null, match, mappings, mapped_points, assets, needs_tick: bool }
```
A real run answers 200 `{ dry_run: false, audit_id, source: {id, name}, from, to, rename, undo_until: iso }`. Refusals are `detail` sentences: 404 (source or target gone), 409 (a scan is queued or running; counts or addresses differ from `expect`; the old source answers again / is not offline any more; the new source got a mapping or holds readings; no longer a unique match; the name is taken), 422 (type not movable; `address: "name"` without a hint for the target).
`POST /api/sources/moves/{audit_id}/undo` (`sources.edit`) -> 200 `{ source: {id, name}, restored: {host, port, name}, text }`; 404 not a `source.moved` row; 410 older than 24 h; 409 already undone, the source was deleted, or its host, port or name changed since (each in words).
