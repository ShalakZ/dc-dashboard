# w20: Billing toolbar - the month bar and the table controls share one row when the window is wide enough

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. One fresh Sonnet implementer per task, a brief per task in `.waves/w20/brief-T*.md` (it carries the signatures, test names and assertions below). Steps use checkbox (`- [ ]`) syntax.

**Goal:** on a wide window the month group (Previous month, month name, Next month, Year, Month) and the table group (filter box, Collapse all, Expand all, Show levels with its `?`) sit on ONE level row; on a narrower window they stack exactly as today. The "Showing N of M rows" line moves to the table's caption row.

**Architecture:** the controls bar leaves `BillingTable` and is rendered by `BillingPage` next to the month bar inside one `div.billing-toolbar` (the state both read, the fold model and the visible rows, is computed once in a small hook). A size container (`.billing-main`) switches the toolbar between "stacked" (default, today's look) and "one row" with ONE `@container` rule in CSS; the same rule picks the smaller `--billing-chrome` value for the table box. The count becomes a sticky-right span inside the table's `<caption>`.

**Tech stack:** React 19 + TypeScript, plain CSS in `@layer w6`, vitest (CSS read as text), Playwright (`page.route` mocks from `e2e/billingModel.ts`), `playwright-core` scripts for looking.

**Spec:** the brief `.waves/w20.md` (R1 to R5) as refined in "Rulings" below (the brief's "1440 shares a row" is not reachable: see F2).

## Facts checked in the code (the brief corrected)
- F1. The controls bar is `components/BillingTools.tsx`, rendered by `BillingTable` (live, after the banners) and as an inert `idle` copy by `BillingPage` (while loading or failed) and by `BillingTable` (the two empty states). `BillingTable` owns the model (`billingModel`), the effective fold (`sizeDefaultFold` or the remembered fold, `restricted`) and the rows (`visibleRows`). The month bar (`.row.billing-bar`) is a direct child of `section.billing-page`; the closed box and the missing-rate banner sit BETWEEN the two bars in the DOM today. So one row needs the bars to be siblings: the state is hoisted into the page (T1), CSS order tricks would put the banner's link out of visual tab order.
- F2. Measured on the look stack (Chromium, DejaVu fonts, which are wider than Windows or macOS fonts), 2026-10-18: the page content is 1628 px at 1920 (sidebar open, 264 px + padding), 1148 at 1440, 988 at 1280, 916 at 1024 and 692 at 800 (sidebar minimised). The month group is 881 px (153 + 152 label + 84 chip room + 129 + 331 selects, gaps 8; the W11 chip room and the label width stay). The table group is 853 px with the filter at its 22rem maximum and 661 px with the filter at its 10rem minimum. One row therefore needs 881 + 16 + 661 = 1558 px of content: **the threshold is `@container (min-width: 99rem)` (1584 px, 26 px of slack)**, and it only holds if, INSIDE that container block, the filter's flex-basis drops to its minimum (`.billing-page .billing-toolbar .tools-filter { flex-basis: 10rem; }`): the plan review measured that with the default 14rem basis a wrapping flex line is filled by the items' hypothetical sizes, the table group then needs 725 px (1622 in all) and at 1877 px (container 1585) the tools wrapped into two lines, 76 px tall, 35 px past the window (with the rule: one line, 34 px, the filter 187 px; at 1920 the filter is 230 px; `flex-wrap: nowrap` instead was measured worse: it shrinks every item and wraps the "Show levels" label). 1920 shares a row; 1440 and below stack. ## Rulings (plan level)
- Ruling: tier S (front end only, one page, no data or permission); the plan review and the whole-wave review stay.
- Ruling: the toolbar is switched by a CONTAINER query on a wrapper (`.billing-main`), not by natural `flex-wrap` and not by a viewport media query - the layout is then a function of the container width alone, so the idle copy, the placeholder bar (no month yet) and the loaded bar always take the same rows (no shift), the sidebar open or minimised is honoured, and the chrome value can follow (a container query can restyle only descendants, and the table box is one). Cost if wrong: between the real wrap point and 99rem on a wider-font machine the row stacks although it could share (today's look, harmless).
- Ruling: the brief's R1 "1440 shares a row" is not reachable (F2): 1920 and the owner's own width share it; the plan says so and the review focus is 1920 / 1860 / 1440 / 1280 / 1024 / 800 as listed above.
- Ruling: R2 keeps the how-to-read sentence as the `<caption>` text and adds the count INSIDE the caption (sticky right, F3), with `aria-labelledby` on the table naming only the sentence (the caption's live count would otherwise rename the table at every filter).
- Ruling: in the one-row layout the table group is right-aligned (`justify-content: flex-end`) so the row reads month nav on the left, table tools on the right; stacked, the groups start at the left as today.
- Ruling (review I3): the count scrolls away with the caption when the rows are scrolled down (the caption is not sticky and must not become sticky: the header's `top: 0` and a W17 pin depend on it). Accepted: a new filter scrolls the box to the top (the existing effect), the toolbar above never scrolls, and the live region still speaks every change. MORNING.md names it as the thing most likely to want a tweak.
- Ruling (review minor): the caption becomes the table's accessible DESCRIPTION with the count run on after the sentence; the sentence span ends with `{" "}` so the two do not run together. No `aria-describedby`.
- Ruling (review minor): the placeholder bar (no month yet) and the idle copies are invisible (empty or `visibility: hidden`), so the filter's left edge moving about 120 px when the real bar lands is not a visible shift; heights and the right-aligned buttons do not move. Accepted, no `min-width` on the placeholder.
- Ruling: the hook that holds the shared state is `src/hooks/useBillingView.ts` (a file of its own, `hooks/` is where the other hooks live), the predicate is `billingHasRows` in `src/lib/billingRows.ts` (pure, next to `visibleRows`).
