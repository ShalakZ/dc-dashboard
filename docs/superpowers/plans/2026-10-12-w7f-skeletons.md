# W7f: loading skeletons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner asked (2026-10-12, roadmap row O-21) for loading skeletons: while a page waits for its first data it shows quiet grey shapes in the layout the data will have, instead of a bare "loading…" line. Initial loads only, no flash, no layout shift, reduced-motion safe.

**Architecture:** Front end only. Nothing under `backend/`, no migration, no API change. One file `src/components/Skeleton.tsx` holds the primitive (`Skeleton`), the region wrapper (`SkeletonRegion`) and the shapes; two tokens `--skeleton` and `--skeleton-shine`; rules inside `@layer w6` of `app.css`. Each page keeps the condition it uses today for "no data yet" and swaps only what it renders. Shapes are built from the REAL layout classes (`.page-head`, `.tiles`, `.tile`, `.table-wrap`, `.trend-frame`, `.tree-col`), so heights come from the same CSS as the real content.

**Tech Stack:** React 19, react-router 7, TanStack Query 5, plain CSS (`@layer w6` plus the unlayered `themes.css`), Vitest + Testing Library, Playwright (controller only).

## Decisions taken here (the owner may overrule; none blocks the build)

1. **S1 to S8 of the brief stand**, refined by the rest of this list.
2. **Keep each page's own "no data yet" condition; never normalise `isLoading` to `isPending`.** A disabled query stays `isPending` forever (`useAuditEntry` has `enabled: isEntryId(id)`, the billing costs `enabled: month !== null`, the series `enabled: metric !== null`), which would be a permanent skeleton. A page that uses `isLoading` keeps `isLoading`, one that uses `isPending` keeps it, and a compound condition (`site.isPending || (month !== null && costs.isPending)`) is copied as it is. The skeleton replaces the text only. Because those conditions are all "no data for this key yet", polling (`refetchInterval`), invalidation refetches and `keepPreviousData` (Audit) never bring a skeleton back, and an error or an empty list still wins (the error and empty branches stay where they are). A switch inside a mounted page that already replaces its content with a bare line (the Billing month, the Storage range) gets the skeleton of that content: it is the same "no data for this key" state.
3. **Assets workspace: one transition, not two.** Today `AssetsPage` returns a bare line while `/api/assets` loads and the child page then starts its own load. Now `AssetsPage` always renders `.assets-layout`: `<AssetTree loading={isLoading} />` beside `.assets-detail` with the real `<Outlet>`, and the children gate on `useAssets().isLoading` themselves (`AssetsSummary`: the real "Assets" `PageHeader` plus `FleetSkeleton`; `AssetView`: `AssetSkeleton` while the summary OR the asset list is loading, since the crumbs need the list). `context.locked` is `true` while the list loads (put `isLoading` into `AssetsPage`'s local `locked`, which `openAdd`/`openEdit` and the tree's `disabled` use, not only into the context), so Add asset (and every action) is disabled and no form opens without a parent list. An assets ERROR still replaces the whole layout with the error, as today. `AssetsSummary`'s `Fleet` shows the same `FleetSkeleton` while `useFleetSummary` loads, so the two steps look alike.
4. **The tree skeleton lives inside `AssetTree`** (a `loading?: boolean` prop), not in a second component: the same `<section className="tree-col" data-state style={--tree-user-w}>` keeps the stored width, the minimized state and the resize handle, so a user who resized the tree sees no sideways jump. While `loading`: the header shows (title, the add button disabled, collapse and expand disabled as for an empty list), the filter slot is a 34 px block with the filter's padding, and `.tree-scroll` holds `TreeSkeleton` (rows of the real `.node` height 32 px at three indent levels, each a 16 px circle plus a name line) inside a `SkeletonRegion` labelled "Loading the asset tree". `AssetTree`'s effects already return early for `nodes.length === 0`.
5. **Fidelity by construction** (measured by the Opus plan review in Chromium). Placeholders sit INSIDE the real wrapper elements, so line boxes and paddings come from the real CSS: a text placeholder is an inline-block (`vertical-align: middle`, height `0.8em`, width in `ch`/`%`) **wrapped in a plain `<span>`** (the `Skeleton` line variant renders `<span aria-hidden="true"><span className="sk sk-line"/></span>`): a bare inline-block that is a direct child of a flex or grid parent (`.tile-label`, `.crumbs li`, `.kind-name`, `.page-head`) is blockified and loses the text's line height (the label row measured 16 px against 18.19 px, so every tile came out 2.19 px short); the wrapping span becomes the flex item and keeps the strut. It goes inside the real `.big`/`.tile-label`/`h1`/`small`/`th`/`td`. Measured facts to build to: a real fleet "Live power" tile always has a `<small>` note, so the fleet's second tile does too (real 99.8 px against 78.8 px without); the trend toolbar is about 62 px (each `label` is a grid: an 18.2 px text line, a 6 px gap, the 38 px select), so `TrendSkeleton`'s toolbar is a label column (line + 38 px block) plus a 38 px range block aligned to the bottom, and the frame's HEIGHT is measured in Task 5; a `.page-head` without its actions slot is 6.5 px shorter (68.5 against 75), so where the loaded header has data-dependent actions (Sources, Scans, Source points) the skeleton header carries an `aria-hidden` 34 px block in the actions slot; the Storage page has a real `PageHeader` and five `.storage-tiles` (`.muted` labels, three with notes); `DashboardPage` has no `.page-head` (its top is `Crumbs` plus `.row.dash-head`); the Discovery skeleton sits inside `.graph-page` (its 100vh chain).  tables are real `<table>` markup in `.table-wrap` (row height from `--row-y`); the asset skeleton's header carries `.crumbs`, `.page-title`, `.page-tile` and `.sub` (the rules `.page-head:not(:has(.crumbs))` and `.page-head:has(.page-title) > .sub` in `pages-assets.css` key on them); `.fleet-tiles` is kept on the fleet tiles (22 px figure). Static page titles use the REAL `PageHeader`; only data-dependent titles (an asset, an audit entry, a source's points) use placeholders. Text placeholders never contain a real word that a test could match; the headings `Trend` and `Metrics` in `AssetSkeleton` are `aria-hidden` `h2`s holding a line placeholder, so `.asset-page > h2` styles them and no heading appears in the accessibility tree.
6. **Lazy-chunk rule.** Every shape a `Suspense` fallback uses lives in `Skeleton.tsx` and imports nothing from `TrendChart.tsx`, `DashboardsPage.tsx` or `DashboardPage.tsx` (that would pull the chunk into the main bundle). The one number both sides need, the chart's height 320, goes into `src/lib/chartBox.ts` (`export const CHART_HEIGHT = 320`), imported by `TrendChart.tsx` and `Skeleton.tsx`. Task 1 records `npm run build`'s chunk list before and after; the lazy chunks must stay separate.
7. **`Pending` placement.** `<Pending />` is mounted ONLY in `Suspense` fallbacks and in `HomeRedirect`, next to the skeleton, never inside `SkeletonRegion` (a skeleton under a condition that never resolves would otherwise pin the top bar). Query-driven skeletons are already counted by the bar's `useIsFetching` predicate (initial loads).
8. **CSS.** `.sk-region` fades in with `animation: sk-in 120ms linear 150ms both` (opacity 0 to 1; `both` keeps it at 0 during the delay, which is the no-flash rule S4, in pure CSS). The sweep is a separate animation on a `::after` of each block (`sk-sweep 1.4s linear infinite`, `translateX(-100%)` to `100%`, the gradient built from `--skeleton-shine`), the block has `position: relative; overflow: hidden`. `@media (prefers-reduced-motion: reduce)` sets the `::after` to `animation: none; display: none` and leaves the delayed fade (dropping the delay would bring the flash back); the existing reduced-motion rule only stops transitions. Radius `--radius-sm` for lines, `--radius` for blocks, 50% for circles; no pills.
9. **Tokens.** `app.css` `:root`: `--skeleton: #dde2ea; --skeleton-shine: #eef1f6;`. `themes.css` `:root[data-mode="dark"]`: `--skeleton: #2c323d; --skeleton-shine: #394150;`. Presets do not change the grounds, so the ratios hold in all eight looks: base against `--bg` and `--surface`, measured 1.30 / 1.22 (light) and 1.38 / 1.27 (dark), the test asserts at least 1.15 against both, in both modes, and that neither token equals or contains an accent. `themes.css.test.ts` derives `DARK_SET` from the dark block and builds `ISLAND_SET` from it, so adding the two tokens to the dark block REQUIRES the widget island block in `themes.css` to re-pin them with the light values above (the widgets stay light cards); there is no literal list to extend, and no assertion is loosened.
10. **Screen readers (S6): one region per area, shapes are bodies.** `SkeletonRegion` is the ONLY thing with `role="status"`: `<div role="status" aria-busy="true" className="sk-region …">` with one `<span className="sr-only">{label}</span>`; it takes `className` so it can BE the real wrapper (`asset-page`, …). Every shape (`TilesSkeleton`, `TableSkeleton`, `FormSkeleton`, `TreeSkeleton`, `TrendSkeleton`, `ChartBlock`, `PageHeaderSkeleton`, …) renders only a body whose root carries `aria-hidden="true"` (a skeleton `<table>` included: its rows must not satisfy `getByRole("row")` before the data arrives, e.g. `phase3.spec.ts:366`, `discovery.spec.ts:174`, `w3c.spec.ts:74,141,155`), and a shape given a `label` prop wraps itself in one region. A composite (`FleetSkeleton`, `AssetSkeleton`, `PageSkeleton`) is ONE region around bare shapes. Nothing inside a region is focusable. Labels are short and specific ("Loading the asset", "Loading the asset tree", "Loading users"); tests find them with `getByText(label)` (a status takes no accessible name from its content, so `getByRole("status", { name })` finds nothing); each label is checked against `frontend/e2e/*.ts` matchers in Task 5.
11. **Diagnostics has nothing to skeleton** (its only "pending" text is the Build-report button's), and `RequireAuth`'s bare line stays (no shell exists yet); both go to the backlog.
12. **A query that failed once never brings the skeleton back (review I2).** On a polling query without data, every refetch sets `status: pending, error: null` and `retry: 1` waits 1000 ms, so the error and the skeleton would swap at every poll, forever (Fleet 15 s, the asset summary 60 s, Sources 10 s, Billing costs 60 s, the TrendChart series). On exactly those five the rule is `skeleton only while the query's errorUpdateCount === 0`; once it has failed, the loading branch keeps TODAY's muted `loading…` line (not the skeleton, and not the empty state: Sources would otherwise show "No sources yet." and the asset page "not found" in that window). Other pages do not poll, so a remount after a failure is a fresh visit and gets its skeleton.
13. **Chained skeletons do not blink (review I6).** Several hand-offs go from one skeleton to the next (the summary page's assets step to its fleet step, a lazy route's fallback to the page's own table skeleton, `AssetSkeleton` to the chart's block): each new region would restart the 150 ms fade and leave the area blank for 150 ms. `SkeletonRegion` therefore reads, at RENDER time, a module-level counter of mounted regions and the time the last one unmounted (maintained in its effect cleanup): if a region is mounted or one unmounted less than 250 ms ago, the new region gets `data-instant` (CSS: `animation: none`, opacity 1, the sweep still runs). This needs no JavaScript timer (the delay itself stays pure CSS) and also covers a swap inside one commit (the old region has not cleaned up yet when the new one renders). Two regions mounting in the same commit (the tree and the pane) both see none and both delay. In addition `AssetView` starts loading the TrendChart chunk when it mounts (`void import(...)` in an effect, the same module the `lazy()` uses), so the Suspense fallback rarely shows. The Suspense fallback (`TrendSkeleton`) and `ChartBlock` are ordinary regions (they get `data-instant` through the rule above when they follow a skeleton).
14. **Process.** The lighter process of W7e: ONE Opus plan review (focus: decisions 2, 3, 4 and 6 against `api/queries.ts`, `AssetsPage.tsx`, `AssetTree.tsx`, `lib/treeWidth.ts`), Sonnet implementers (one per task, fresh), targeted tests per task, no per-task Opus review (no data, auth, billing or migration), then the controller's gates, ONE whole-wave Opus review in a real browser, ONE fix wave, one scoped re-review. No backend suite (`git diff main --stat -- backend` stays empty). For the implementers' looks, the controller runs ONE seeded scratch stack `dcdash_e2e_w7f_vis` (ports 18196 and 18550) and ONE Vite dev server (`VITE_API_TARGET=http://127.0.0.1:18196 npx vite --port 5196 --strictPort --host 127.0.0.1`); a skeleton is looked at by holding a request with `page.route` in a `playwright-core` script.

## Global Constraints

- Hard bans (any one is a failure): no cream or off-white page background; no italic accent words; no numbered "01/02/03" labels; no monospace labels; no pill shapes (radius 4 to 8 px, 50% only for circles); no gradient blobs, glassmorphism or shadow on skeletons. The sweep gradient is the only gradient and is theme-neutral (never `--accent`).
- Colours: raw colours only in `src/themes.css` and `app.css`'s `:root` block; every other rule uses `var(--…)`. New component rules go inside `@layer w6` of `app.css` (page rules in the matching `src/styles/pages-*.css`). The frozen widget/editor block at the end of `app.css` is not edited.
- Playwright matches names by case-insensitive SUBSTRING. Region labels must not collide with the labels, headings and texts the specs use (Task 5 greps every `getByText(`, `getByRole(`, `getByLabel(` value in `frontend/e2e/*.ts`; a hidden label counts).
- jsdom has no `matchMedia`, zero-size rects and no layout: unit tests check markup, roles, classes and the stylesheet text; layout and animation are checked in a real browser (Task 5 and the controller).
- Implementers run only: `cd frontend && npx vitest run <files>`, `npm run typecheck`, `npm run build`, the e2e type-check `npx tsc --noEmit --strict --module esnext --moduleResolution bundler --target es2022 --skipLibCheck e2e/*.ts 2>&1 | grep -v -E "TS2307|TS2580|TS7006"` (must print nothing), git, grep, `bash -n`, and `node` scripts with `playwright-core` against the controller's Vite dev server (`http://localhost:5196`, login `admin` / `correct-horse`) for a LOOK. Never `docker`, `scripts/*`, `npx playwright test`; never touch `backend/`, `.env`, `backups/`, `~/.claude`.

## Review Focus (inputs the happy path does not exercise)

1. **Layout shift, measured:** skeleton to content on the asset page (first tile, the Trend block), the summary page (tiles, "By kind"), the tree column at a non-default stored width and when minimized; the 1024 px width where the tiles wrap.
2. **Flash and flicker:** a fast response shows nothing (computed opacity 0 during the delay); polling (fleet 15 s, summary 60 s, sources 10 s, status 10 s) and invalidation refetches never bring a skeleton; a failing query replaces the skeleton with its error (note `retry: 1`: the error appears after the retry); an empty list shows the empty state.
3. **Disabled queries:** no skeleton that never ends (Audit entry with a bad id, Billing with no month, the series with no metric).
4. **Accessibility:** one `role="status"` per area, no repeated announcements, nothing focusable inside, focus is not lost when the content replaces the skeleton (the Users page moves focus to its h1 after a delete: it must still find it).
5. **Looks:** quiet but visible in all eight looks; the sweep is not accent-coloured; reduced motion has no sweep and still no flash.
6. **Bar and fallbacks:** the W7e bar still counts the lazy fallbacks (StrictMode double mount; a slow lazy route) and does not stay pinned.
7. **Test churn:** the unit tests and e2e helpers that waited on "loading…" still test what they meant to.
8. **Leaks:** no skeleton in the widget frames, the editor or the dashboard widgets' own lines; the lazy chunks stay separate.
