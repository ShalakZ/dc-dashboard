# w17 Billing at scale Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Billing page stays usable with a real data centre (370 assets, 2,000 in the future): the rows fold like the Assets Tree, a filter box finds rows, the day-number header stays while the rows scroll, and a big month (and a big Assets Tree) opens folded. No figure, marker, rate, total, CSV or closed-month snapshot changes.

**Architecture:** Front end only (no backend, no migration, no permission). Three pure modules (`foldLevels`, `foldMemory`, `billingRows`) decide what is visible; `BillingTable` (moved out of `BillingPage.tsx`) renders only the visible rows; `BillingTools` is the controls bar (the same component, inert and invisible, holds its slot while loading, empty or failed); CSS gives the table's scroll box a height so its header row can stick; `AssetTree` gets a default fold for a big tree and scrolls the selected row into view.

**Tech Stack:** React 19, TypeScript, plain CSS in `@layer w6`, Vitest, Playwright (`playwright-core` for looks, the new `w17` project for the gate).

**Spec:** `.waves/w17.md` (the brief; the owner's words and rulings R1 to R8). Standing orders `.waves/RESUME.md`, lessons `.waves/LESSONS.md`.

**Tier:** M (front end only; one page rebuilt in part plus one default in the Assets Tree; no data, security, money or migration). Ruling: tier M. The plan review and the whole-wave review stay; one full frontend suite; one Playwright gate; no backend suite (no backend change: only the three doc-reading backend tests after the docs commit).

**Scratch stack:** project `dcdash_e2e_w17_vis`, ports **18223 / 18577** (both free per `ss -ltn`; the highest used so far is w16's 18222/18576). Scripts in `.waves/w17/` (copied from w14, renamed, `bash -n` ok, the guard refuses `dcdash`): `vis-rebuild.sh` + `vis-up.sh` (rebuild from the current tree and run the whole suite on an EMPTY database: never seed before it), `stack-up.sh` (a LOOK stack: rebuild, first-run admin, the pilot-hall seed, a 0.12 site rate; no suite).

## Decisions

1. **One fold model, shared.** New `frontend/src/lib/foldLevels.ts` (pure):
   - `export interface FoldItem { id: number; parent_id: number | null }`; `export const FOLD_ROW_LIMIT = 60`.
   - `export function foldModel(items: readonly FoldItem[]): FoldModel` with `depth: Map<number, number>`, `children: Map<number, number[]>` (list order), `below: Map<number, number>` (descendants of each id), `foldable: readonly number[]` (ids with a child, list order), `maxDepth: number`, `total: number`. Items may arrive in any order; a parent that is not in the list makes the item a root; a cycle (impossible from the API) must not hang: ids on a cycle count as roots.
   - `foldedForLevel(model, level): Set<number>`: LEVEL L (1 to `maxDepth`) shows rows at depth below L (level 1 = roots only); the set is every foldable id with depth >= L - 1 (so opening one row shows ONE more level, never its whole subtree). `rowsAtLevel(model, L)` = rows with depth < L. `maxDepth === 0` (a flat list) has no levels.
   - `levelOfFold(model, folded): number | "all" | null`: the folded set restricted to `model.foldable`; empty = `"all"`; equal to `foldedForLevel(L)` = `L`; anything else = `null` (custom).
   - `sizeDefaultFold(model, limit = FOLD_ROW_LIMIT)`: `total <= limit` gives an empty set (a small tree opens as today); otherwise the DEEPEST level L in 1..`maxDepth` with `rowsAtLevel(L) <= limit` (never less than 1: a 100-root list still folds to level 1). For the seed this is level 4 (24 rows: Site, halls, Electrical, pods, panels, rows).
   - `fixedLevelFold(model, level, limit = FOLD_ROW_LIMIT)` for the tree: `total <= limit` gives empty; otherwise `foldedForLevel(model, min(level, maxDepth))`. R5 says level 2 for the tree: `TREE_DEFAULT_LEVEL = 2` lives in `AssetTree.tsx`.
   - **Why the billing rule is adaptive and the tree's fixed:** the brief's R2 lets the plan choose ("level 3 or the deepest level that keeps about 60 rows"); the deepest-level rule shows the rows (Row 1 to 4) a person wants first on the seed and adapts to any tree shape; R5 names level 2 for the tree, which in a narrow column reads cleaner (Site, halls, Electrical), so the tree keeps it.
2. **Remembered state.** New `frontend/src/lib/foldMemory.ts`: `readFoldMemory(key): Set<number> | null` (null = nothing stored, junk, a storage that throws, or more than 5000 ids; entries that are not whole numbers are dropped) and `writeFoldMemory(key, ids)` (sorted, each once, at most 5000, never throws). `treeFold.ts` keeps its exports and API (`readFolded() = readFoldMemory(KEY) ?? new Set()`, `saveFolded` = `writeFoldMemory(KEY, ..)`) and gains `readFoldedOrNull()`. Billing's key is `dcdash.billingFolded`. `null` means "nothing remembered": the size default applies and is NOT written (a visit alone remembers nothing). The first change by the person (a twisty, Collapse all, Expand all, Show levels) writes the full set. Written sets contain only ids of the month on screen (a closed month's snapshot may lack assets: their fold state resets to open; accepted, it costs nothing).
3. **Visible rows.** New `frontend/src/lib/billingRows.ts` (pure): `visibleRows(assets, model, folded, needle)` returns `{ rows: RowView[]; shown; total; matches }`, walking the tree depth-first from the roots in list order (an explicit stack, no recursion). `RowView = { asset, depth, below, mode: "leaf" | "open" | "folded" | "context" | "match-open", ... }`; precisely: `leaf` (no children, nothing to fold), `open`, `folded`; and, with a filter, every row is a match (name contains the trimmed needle, case-insensitive, ONLY the name, never the path) or `context` (shown only because a descendant matches; it counts as open and its twisty is decorative). A filter ignores the fold set; the fold set is untouched by it, so clearing the filter restores the previous fold. A match's non-matching descendants are not shown (same as the Assets Tree). A needle of spaces filters nothing. Also here: `twistyLabel(name, open, below)` = `"Collapse Hall 1, 59 rows below"` / `"Expand ..."` (`1 row below`), `rowsLine({ shown, total, matches, filtering })`: no filter and all shown `"All 370 rows shown"` (`"1 row"` for one), no filter and folded `"Showing 24 of 370 rows"`, filter `"12 of 370 rows match"` (`"No rows match"` at zero), and `noMatchText(filter)`.
4. **The table.** `BillingTable` moves to `frontend/src/components/BillingTable.tsx` together with `FigureCell`, `Legend`, `Empty` and the two icons only it uses; `BillingPage.tsx` keeps the page. Props: `{ costs, canSetRates, folded: ReadonlySet<number> | null, onFold(next), filter, onFilter(text) }`. Only visible rows are rendered (never `display: none`). A `memo`'d `BillingRow` takes `(row, depth, mode, below, days, onToggle)` with `onToggle` stable (a ref to the latest fold), so a fold re-renders the toggled row and the rows that appear. The name cell stays `th scope="row"` with the same `title={path}` and the same `paddingLeft: 8 + depth * 16` (a test pins it) and holds `<span class="bill-name">` = twisty (a `button.twisty`, `type="button"`, `aria-expanded`, `aria-label={twistyLabel(..)}`) or a spacer (leaf, 20 px) or a decorative caret (filter mode, `aria-hidden`), then `<span id="billing-asset-{id}" class="bill-label">name</span>`. **The `th` gets `aria-labelledby` pointing at that span**, so its accessible name stays the asset name and every `getByRole("rowheader", { name })` (unit and e2e) keeps working. Figure cells and their markers are untouched; `td` order and count do not change (e2e reads cells by index). With a filter and no match the body is one `tr` with one `td colSpan` holding `noMatchText`.
5. **The controls bar.** `BillingTools` (new, `frontend/src/components/BillingTools.tsx`), always one row that may wrap, `margin 0 0 12px`, min-height 38 px: (1) the filter, `type="search"`, label (sr-only) **"Filter assets"**, placeholder "Filter by asset name", Escape clears it (and stays focused), a **"Clear filter"** icon button inside the field while it has text (a click clears and focuses the input), the native cancel button hidden like `.qf`; (2) **Collapse all**, **Expand all** (text buttons, `type="button"`); (3) **"Show levels"** `<select>` (`All`, `1` ... `maxDepth`; value `custom` shown as "Custom" only while the fold matches no level) with an `InfoTip` "A folded row still shows its own totals, which already include everything below it."; (4) the rows line, a role-less `aria-live="polite"` `<span>` right-aligned with a fixed `min-width` (`22ch`) so its words never move the controls. Tab order is exactly that. While a filter has text, Collapse all, Expand all and the select are disabled (the filter has its own view); they are also disabled when nothing can fold (`maxDepth === 0`). `idle` mode renders the same markup with `inert`, `aria-hidden` and `visibility: hidden` (it holds the slot exactly, at every width, because it is the same box). Idle is used (outside the skeleton region) while the costs load or fail and, inside `BillingTable`, for the two empty states (R7).
6. **Fold and filter state live in `BillingPage`** (they survive a month change and the loading step): `folded` from `readFoldMemory`, `changeFold(next)` sets state AND writes memory; `filter` is plain state (not remembered); the table gets `useDeferredValue(filter)` for the rows and the line so typing stays responsive. Collapse all = `foldedForLevel(1)`; Expand all = empty; Show levels = `foldedForLevel(L)` or empty for All; a twisty toggles one id. Every action starts from `folded ?? sizeDefaultFold(model)` restricted to the model.
7. **The header that stays (R4).** `.billing-page .table-wrap.table-scroll { max-height: max(20rem, calc(100dvh - var(--billing-chrome))); overflow: auto; scroll-padding-top: 2.75rem }` with `--billing-chrome` measured in Task 3 (starting guess 24rem: top bar 52 + page header + month bar + bar + caption, plus the legend 40 and `--toast-clear` 96 below) so that **at 1440 x 900 and 1920 x 1080 the page itself does not scroll with a big month, expanded or folded** (no scrollbar appears or goes when folding); `@media (max-height: 699.98px)` gives `max-height: none` (the page scrolls instead). `thead th { position: sticky; top: 0; z-index: 2 }`, the corner `thead th:first-child` gets `top: 0; z-index: 4`, row headers stay `left: 0; z-index: 1` (the header covers rows scrolling up under it, the corner covers both). Caption and legend are not sticky. `scroll-padding-top` keeps a Tab-focused twisty from hiding under the sticky header. No page-level horizontal scroll at 800 px (existing check).
8. **Keyboard and screen readers (R8).** Twisties are tab stops with names; leaf rows have none, so tabbing visits only parents. Focus stays on the twisty after a toggle because its row (same `key`) and button are never replaced; no `.focus()` call is added (W7q). Native `disabled` on Collapse all, Expand all and the select is allowed because the only thing that disables them is typing in the filter (focus is in the filter) or an empty fold model; the inert idle bar is not focusable. `aria-expanded` announces a fold; the rows line announces the new count. No `role=status` is added (the page's one status stays the missing-rate banner); no `aria-controls` (rows are removed, not hidden).
9. **The Assets Tree (R5).** `AssetTree`: `stored: ReadonlySet<number> | null` state (`readFoldedOrNull`), `defaultFold = useMemo(() => fixedLevelFold(foldModel(flatten(nodes)), 2), [nodes])`, `const collapsed = stored ?? defaultFold` (so every existing use of `collapsed` is unchanged and a big tree never renders expanded for one frame). One `changeFold(updater)` replaces every `setCollapsed(updater)`: `setStored(cur => { const base = cur ?? defaultRef.current; const next = updater(base); return next === base ? cur : next })` (an updater that changes nothing keeps "nothing remembered"). The save effect writes only when `stored !== null`. The prune effect and the selection-path unfold go through `changeFold`. **Scroll into view:** when the selection (or its path) changes, a ref marks it pending; after the commit (an effect with no dependency list, cheap guards first) the selected `.node.is-selected` is looked for; if its ancestors are still `hidden` (`closest("[hidden]")`) or it is absent, the mark stays; otherwise, if the row lies outside `.tree-scroll`'s box, `scrollTop` is set to centre it (never `scrollIntoView`, which also scrolls the page); the mark clears. Not while minimized or loading.
10. **Performance.** Measured before: 197 ms (370 rows) and 995 ms (2,000 rows) to draw everything. After: the default fold draws at most 60 rows. Expand all on 2,000 rows redraws about 2,000 (about a second, the old cost, on a click that asked for it); Task 2 re-measures with `.waves/w17/measure.mjs` and, if Expand all at 2,000 rows blocks the page for more than 1.5 s, wraps `onFold` in `startTransition`. No virtualisation this wave.
