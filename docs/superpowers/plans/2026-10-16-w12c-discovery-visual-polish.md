# w12c Discovery visual polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Discovery gets one regrouped toolbar, a shortcuts bubble, a clearer source card, icons on every node and in Find, a page icon, and a last-value card on mapped points.

**Architecture:** Front end first. Two small additive read-only backend changes feed the icons (asset `icon` and `kind_icon` on `GET /api/discovery/graph`) and the value card (`GET /api/mappings/{id}/latest`). The toolbar is one component (`GraphBar`) that now also holds Find, Snap, Refresh, Shortcuts and an overflow menu; its width tiers are CSS container queries. The bubble and the value card are standalone components that the page wires in.

**Tech Stack:** React 19, React Flow 12 (`@xyflow/react`), TanStack Query, vitest + Testing Library, Playwright (isolated scratch stack), FastAPI + SQLAlchemy + pytest.

**Spec:** `.waves/w12c.md` (the owner's words and the rulings C1 to C6). Roadmap row and backlog section are written at close-out.

**Tier: M** (a behaviour change across layers plus two additive, permission-gated reads; no migration, no new permission, nothing deleted). The plan review and the whole-wave review stay.

- NO new colour token (it would need all 21 presets). Use existing ones (`--ok --warn --crit --accent --accent-tint --border-strong --surface --text --text-2`).
- Every implementer brief says: "Edit files with the Edit tool or an anchored sed, never with a script that rewrites a whole file; after any scripted edit check the size and run `git diff --stat` on the file." CSS, `.tsx` and tests too.
- CSS: one `@layer w6` block per file; a class is named in ONE page file only (the clash guard in `app.css.test.ts`); before adding a selector grep `app.css` and `src/styles/*.css` for the same element; every selector names a class; no transition on node paints (a guard in `graph-nodes.css.test.ts`); every animation gets its own reduced-motion off switch. The new files `graph-keys.css`, `graph-source-card.css` and `graph-value-tip.css` are created EMPTY by the controller's scaffold commit (imported in `main.tsx`, listed in `app.css.test.ts`): a task fills only the file it owns.
- Width thresholds are CSS (`@container`), not script. jsdom cannot test them: Playwright does, at 1440, 1024 and 800, sidebar minimised AND expanded (LESSONS A4).
- Ages come from the server's clock (`age_seconds`), grown in the browser with `ageNow` (`lib/age.ts`), never the browser's clock against the server's.
- Accessible names: keep every name an existing test or e2e spec uses, or update every use (the A1 list below). Playwright matches by case-insensitive SUBSTRING: audit each new `aria-label`, heading or `<label>` against `getByLabel(` and `getByRole(` values in `frontend/e2e/*.ts`.

## Facts checked in the code (the brief's guesses, settled)

- Connectors that exist: `opcua`, `modbus`, `simulator` (`protocolLabel` in `lib/graphStatus.ts`). There is NO HTTP connector: the brief's "HTTP" icon is dropped; an unknown type gets the generic `sources` icon.
- A discovered OPC UA source is auto-named `OPC UA server at {host}:{port}` (`backend/dcdash/connectors/opcua.py:220`), so its name already carries host and port. "Short name" therefore means: the title is `source.name` on ONE line (ellipsis, full text in `title`), and the muted second line shows the protocol word and the endpoint (`endpointOf` in `lib/graphFind.ts`, to be exported as `sourceEndpoint`).
- `GET /api/discovery/graph` assets carry id, parent_id, name, kind only (`backend/dcdash/api/discovery.py` ~line 178). `/api/assets` serves `icon` (stored) and `kind_icon` (registry, resolved) with `kind_icons(db)` and `icon_for(kind, icons, cache)` from `dcdash.core.asset_kinds`; `assetIcon(asset)` in `lib/assetIcons.ts` needs both.
- A graph point already carries `mapping_id`, `asset_id` and `mapped_metric` (`point_json`). The latest value lives in `point_latest` (one row per polled point: value, ts, quality); the scale is on the mapping; `GET /api/assets/{id}/summary` serves it with the whole rollup and cost (too heavy for a hover); the stream is for pages that stay open. `is_stale(ts, now, interval_seconds)` is `dcdash.core.widgets.is_stale`; `unit_for(Metric(m), custom_unit)` is `dcdash.core.metrics.unit_for`.
- `Find` today is a card in a React Flow `Panel` (`CanvasTools.tsx`) with `openRef` for Ctrl+K; `useCanvasKeys` ignores keys from outside the canvas element and from `.graph-find, .graph-menu`.
- `SOURCE_H = 136` (`lib/graph.ts`) is the room a source node takes; e2e `w7t`/`w7u` and `graph.test.ts` pin it. The new card must fit in 136 px at 220 px width; if Chromium measures more, raise it to the next multiple of 8 and update those pins (Task 3).

## Decisions (each is also a Ruling in the ledger)

1. **C4 data: additive `icon` and `kind_icon` on `GET /api/discovery/graph` assets** (same helpers as `/api/assets`, nothing in `backend/dcdash/core` changes). A second read of `/api/assets` needs `assets.view`, which a Discovery-only role may lack. Optional in the TS type (old fixtures).
2. **C6 data: a new `GET /api/mappings/{mapping_id}/latest`**, gated `assets.view` (the permission every value read needs), in `backend/dcdash/api/mappings.py`. Response: `{mapping_id, value, unit, ts, quality, age_seconds, stale}`; `value` is already multiplied by the scale; value, ts, quality and age_seconds are null when `point_latest` has no row. 404 for an unknown mapping. The front end asks only while a card is wanted and only when `can("assets.view")`; one read per hover (no interval). No new permission, so the permission checklist is the route gate only.
3. **Find moves into the bar**; its card is a positioned child of the Find button's wrapper (absolute under the button, right edges aligned, `z-index` above the canvas), not a portal and not in the Panel. Ctrl/Cmd+K inside the bar (outside the Find card) opens Find, as it did on the tools panel's buttons.
4. **Source card actions:** Details is the one visible button; a visible `⋯` button (same `MenuButton` pattern as W12a: it only reports its element, the page opens the node menu outside the canvas) opens a menu with "Create assets for N groups…" and "Remove from Discovery…". The same items join the source node's right-click menu. The node no longer draws Create assets or Remove.
5. **Toggle items in the narrow overflow are plain items** with the state in the words ("Turn on Unmapped only", "Turn off Snap to grid"), not a new menu role.
6. **Bar tiers** (container width of `.graph-bar`, thresholds measured by the implementer and written in a CSS comment): full labels; chips compact (icon and number, the words go to `title`); controls icon-only below 900 px; below 700 px "Unmapped only", "Tidy layout" and "Snap to grid" move into the overflow menu (the inline copies are `display: none`; the menu lists them only when the bar is narrower than the exported constant `OVERFLOW_BELOW_PX = 700` at the moment the menu opens; a vitest reads the CSS and checks it holds the same number).
7. **The live summary stays ONE sentence** (`graphSummary`, unchanged words) in `.graph-summary`, visually hidden, `aria-live="polite"`: the chips are decoration (`aria-hidden`) built from `graphCounts(model, view)`.
8. **No `role="toolbar"` roving focus** (every control stays a Tab stop, as today). Parked: backlog.
9. **Per-task Opus review: none** (no migration, no new permission; the new read reuses `assets.view` and the route-gate test pins it). The whole-wave review gets the two backend changes in its focus.
10. **No new colour token.** Status dot, chips, key caps and the progress bar reuse existing tokens; the progress bar's words ("60 of 60 mapped") are the signal, colour is not.
