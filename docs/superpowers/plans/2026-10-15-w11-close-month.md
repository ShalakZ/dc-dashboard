> Scratch E2E project `dcdash_e2e_w11_*`, ports 18215 (web) and 18569, budget cap 100.

**Goal.** Once the first official bill exists, a finished month must stop moving. Today a past month is recomputed from today's
tree, mappings and tariffs, so moving an asset, mapping or unmapping a point, editing a tariff, or deleting an asset or a source
changes past figures. W11 lets an administrator **close** a finished month: the exact output of `month_costs()` is stored, the
Billing page and the Billing CSV show that stored output, and a quiet line says what today's tree and rates would give. **Reopen**
(with a reason) goes back to live figures and keeps the old snapshot. A small seeder makes a month of history on dev and scratch
stacks only, so the feature can be seen and tested.

## Rulings (the brief's C1 to C9 stand; these refine them)

- **R1 Permission count.** The brief says "the count moves to 30". The code already has 30 (W7o added `assets.kinds`), so `billing.close` is the **31st**. Every count in tests and docs moves 30 → 31 (`test_permissions.py` lines 58 and 105, `roleEditor.test.ts:33` 29 → 30, the `permissionFixtures.ts` comment, `docs/roles-and-permissions.md` lines 5 and 11).
- **R2 Permission rules.** `billing.close`, area "Billing and tariffs", kind "risky", label "Close and reopen billing months", placed right after `billing.export` in the catalogue and in `frontend/src/lib/permissions.ts`. Admin holds it from the code (`ALL_IDS`). It is NOT in `NOT_FOR_CUSTOM_ROLES` (an admin may tick it on a custom role, like `billing.export`). **Migration 0012 grants it to no role** ("nothing changes on upgrade"). `PERMISSION_NEEDS["billing.close"] = ["billing.view"]`. Viewer and Operator do not get it.
- **R3 Month type.** `billing_closes.month` is TEXT `YYYY-MM` (the API's own month format), not DATE, so no time-zone conversion can slip in.
- **R4 Header totals.** `total_kwh` and `total_cost` are the sums of the ROOT assets' `total` (assets with `parent_id` null). An asset's total already includes its subtree, so summing every asset would count energy several times. A root with `total = null` adds nothing; `total_cost` is null when no root has a cost. These two numbers feed the list header, the audit detail and the delta; the snapshot itself holds everything.
- **R5 What "has data" means.** A month can be closed when at least one asset has a day entry with `no_data == false`. Otherwise 409 "no energy data was recorded for that month".
- **R6 What "completed" means.** The month's local end (`month_bounds(month, tz)[1]`, exclusive) is at or before `_now()`, in the CURRENT site time zone. Otherwise 409 "that month is not over yet". `billing._now` stays the one clock tests replace.
- **R7 Close note optional, reopen note required.** Close: `note` optional, stripped, at most 500 characters. Reopen: `note` required, stripped, 5 to 500 characters (422 otherwise). The audit and the row keep the stripped text.
- **R8 The costs route.** `GET /api/billing/costs` keeps its signature. Its body gains `closed` (null for an open month) and, only for a closed month, `live`. For a closed month the rest of the body (`month, timezone, currency, days, assets`) is the STORED snapshot, equal, as JSON, to the object `month_costs()` returned at close time (A-M1: JSONB sorts keys, so not byte for byte). `closed = {id, closed_name, closed_at, note, total_kwh, total_cost}`. `live = {total_kwh, total_cost, delta_kwh, delta_cost, differs}` is a fresh `month_costs()` reduced with the same root-sum rule (R4); `differs` is true when `round(delta_kwh, 3) != 0`, or `round(delta_cost, 2) != 0`, or one side has a cost and the other has none. If the live recompute raises (for example the site time zone has become unusable for billing) `live` is null: viewing a closed month must never fail because today's tree cannot be priced. `GET /api/billing/months` is NOT changed (`test_api_billing_months.py` pins `{"first_month"}`).
- **R9 Closed CSV.** `GET /api/billing/costs.csv` of a closed month writes the stored days with the same columns, through ONE shared row builder (`csv_rows(figures)` in `core/billing_close.py`) that the open path also uses, so the two cannot drift. The file name is `billing-<month>-closed.csv`; an open month keeps `billing-<month>.csv`.
- **R10 Close and reopen routes.** `POST /api/billing/months/{month}/close` (body `{note?}`, 201 with `closed`) and `POST /api/billing/months/{month}/reopen` (body `{note}`, 200 with `{month, reopened_at}`), both gated by `billing.close`, month path pattern = `MONTH_PATTERN` (422 otherwise). Close order: pattern → "already closed" pre-check (409 "that month is already closed by <name> on <date>") → completeness (R6) → `month_costs()` (its own 409 for an unusable zone) → data (R5) → finite check (`json.dumps(..., allow_nan=False)`; failure is a 409 "the figures contain a value that cannot be stored") → INSERT. Two simultaneous closes: the partial unique index makes the second INSERT fail; the route catches the unique violation (SQLSTATE 23505, constraint `billing_closes_open_uq`), rolls back and answers the same 409 as the pre-check. Reopen is one atomic `UPDATE ... WHERE month = :m AND reopened_at IS NULL RETURNING ...`; no row → 409 "that month is not closed". A reopened row is kept; a re-close inserts a NEW row.
- **R11 Audit.** `billing.closed` detail `{month, close_id, total_kwh, total_cost, currency, note}`; `billing.reopened` detail `{month, close_id, closed_name, closed_at, total_kwh, total_cost, currency, note}` (`note` = the reopen reason). Names are written into the detail (the closer's name, `closed_name`), so no `refs` kind is needed: **this refines C5** ("names through refs") because nothing in these details points at a renameable thing. The audit text, icon and filter entries follow the neighbouring `tariff.*` entries.
- **R12 Warnings (C6).** One new sentence everywhere, constants in one place each. Move (`frontend/src/lib/moveText.ts` `BILLING_NOTE`): "Months that are not closed are recalculated at the new place, and the totals of both branches change. Closed months keep their billed figures." Delete (`frontend/src/lib/impact.ts` `HISTORY`, the bulk-delete text in `frontend/src/lib/assetsBulk.ts`, and the server texts at `backend/dcdash/api/assets.py:216` and `backend/dcdash/api/sources.py:323`): "... disappear from Billing and dashboards, except in closed months, which keep their billed figures." Tariffs page sub-line (`TariffsPage.tsx:337`): "Editing a past rate recalculates the months that are not closed; closed months keep their billed figures." (no test pins that sub-line; the tips stay unchanged). The sentence is constant (it does not fetch whether any month is closed): it is true either way.
- **R13 Restore caveat (C7).** `docs/backup-and-restore.md` and `docs/upgrading.md`: a restore of an older backup also brings back the older set of closed months. A downgrade below 0012 drops the closed months (the table is dropped); the lossless claim is for everything that existed before the upgrade.
- **R14 Snapshot size.** About 2,000 assets x 31 days x ~90 bytes is ~5 MB of JSON for a big site, stored once per close and compressed by TOAST; no cap. The docs say so.
- **R15 No months-list change, no client segregation, no per-asset-month lines.** Closed months are found by opening the month (the page shows a "Closed" chip beside the month name). `path` stays in the snapshot (C8).
- **R16 Seeder shape (C9 refined).** A module `backend/dcdash/seed/history.py`, run as `python -m dcdash.seed.history` (inside the `api` container for a stack, or `uv run --project backend python -m dcdash.seed.history` against a database URL in the environment). It ships in the image but is inert: it writes nothing without BOTH `--yes` and the environment switch `DCDASH_ALLOW_SEED_HISTORY=1`; with neither it prints its plan and exits 0 ("nothing written"), with `--yes` but no switch it exits 2. It refuses (exit 1, nothing written) when a source named `seeded-history` already exists. Everything it makes is under source `seeded-history` (a disabled source the collector never polls) and the asset subtree "Seeded demo"; the normal deletes of that subtree and that source undo it. It does not touch any other row. Default range: from the start of the PREVIOUS site month to now (so there is always one complete month to close); `--days N` overrides. Readings go through `dcdash.collector.writer.Writer` (the collector's own write path: `readings` and `point_latest`), then the two rollups are refreshed over the written range. Deterministic (`--seed`, default fixed). The daylight-saving change needs no special code: the curve is a function of the LOCAL hour, so a transition in range shifts it.
- **R17 Seeded data.** Under "Seeded demo": Panel A with an `energy_kwh` counter (daily load curve, 5-minute samples); Panel B with `active_power_kw` only (estimated energy); Panel C with an `energy_kwh` counter that resets once mid-range; one counter has a 6-hour gap on one day. The test asserts the figures the engine documents for the reset (never negative) and for the gap (the hour of arrival).

## Amendments after the Opus plan review (2026-10-15; 1 Critical, 5 Important, 10 Minor, all folded in; report: `.superpowers/sdd/2026-10-15-w11-close-month/plan-review.md`). These OVERRIDE the rulings above where they differ.

- **A-C1 Seeder cannot delete real rollup history (R16 changed).** A rollup refresh recomputes every invalidated bucket in its window from raw data, and the raw retention policy logs an invalidation over every chunk it drops (`0004_billing_dashboards.py:220-226`), so a refresh over a window that holds a dropped chunk would DELETE real `readings_1m`/`readings_1h` rows. So: (1) the range is clamped: `start = max(previous_site_month_start, now - (raw_retention_days - 1) days)`, `raw_retention_days` read from the `storage` setting (`core/storage.py`, default 30); `--days N` is clamped the same way and the dry run says so; if the clamp leaves the previous site month with no day at all, exit 1 with a plain message, nothing written. The previous month therefore holds only its LAST days on most days of the month; that is enough for R5 and for the e2e close. (2) Before writing anything, exit 1 (nothing written) when `readings_1m` holds any bucket in `[start, now)` that lies before the oldest raw reading (the `_MINUTES_WITHOUT_RAW` idea of 0004) — that is "a drop invalidation is pending in my window". (3) A test: raw rows for a pre-existing point, both rollups refreshed, `drop_chunks('readings', older_than => ...)`, the seeder refuses, and that point's `readings_1m`/`readings_1h` rows are byte-identical before and after; a second test that the range is clamped. (4) `developing.md` says the seeder writes only inside the raw retention and refuses on a stack whose rollups outlive their raw data.

## Data model (migration 0012, `backend/migrations/versions/0012_billing_closes.py`)

```
billing_closes
  id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  month         TEXT NOT NULL CHECK (month ~ '^[0-9]{4}-(0[1-9]|1[0-2])$')
  closed_by     <same type as users.id> NULL REFERENCES users(id) ON DELETE SET NULL
  closed_name   TEXT NOT NULL CHECK (btrim(closed_name) <> '')
  closed_at     TIMESTAMPTZ NOT NULL DEFAULT now()
  note          TEXT NOT NULL DEFAULT ''
  timezone      TEXT NOT NULL
  currency      TEXT NULL
  total_kwh     DOUBLE PRECISION NOT NULL
  total_cost    DOUBLE PRECISION NULL
  figures       JSONB NOT NULL CHECK (jsonb_typeof(figures) = 'object')
  reopened_at   TIMESTAMPTZ NULL
  reopened_by   <same type as users.id> NULL REFERENCES users(id) ON DELETE SET NULL
  reopened_name TEXT NULL
  reopen_note   TEXT NULL
  CHECK ((reopened_at IS NULL) = (reopened_name IS NULL) AND (reopened_at IS NULL) = (reopen_note IS NULL))
UNIQUE INDEX billing_closes_open_uq ON billing_closes (month) WHERE reopened_at IS NULL
INDEX billing_closes_month_ix ON billing_closes (month, id)
```
Up creates the table and the two indexes and touches nothing else. Down drops the table (the closed months are lost; no other data is). Nothing is imported from `dcdash`. A JSONB float round-trips exactly (Python writes the shortest repr, PostgreSQL stores it as numeric, `json.loads` reads the same float), which is why the frozen CSV can equal the open one.

## Review focus (for the plan review and every Opus review)

1. A closed month's figures, totals and CSV do not change when an asset moves, a tariff changes, a point is unmapped, or an asset or source is deleted; late readings show only as the delta; the frozen CSV equals the open CSV taken at close time.
2. No way to close an open or empty month, to close twice, or to reopen without the permission and a note; two simultaneous closes give one; audit rows read well.
3. The migration is lossless both ways on a restored copy of the dev DB; permission matrix, coverage gate and counts agree everywhere.
4. The seeder cannot touch real data, refuses without its switches, and its figures match the engine.
5. Every old billing sentence and the tests that pin it are updated; the doc-reading tests pass.
