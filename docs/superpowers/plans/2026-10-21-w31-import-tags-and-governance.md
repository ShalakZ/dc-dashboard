- **D4 Import: limits, parse, safety** (brief R2, R3, R5). Raw body, `Content-Type` one of `text/csv`, `text/plain`, `application/csv`, `application/vnd.ms-excel`, `application/octet-stream` (anything else 415; `multipart/*` 415 with a sentence). Read with `request.stream()` in a loop with a hard cap and an overall `asyncio.timeout(300)` (408): a `Content-Length` above the cap answers 413 before reading; a body that goes on is cut at 20 MB + 1 byte (413). Limits as constants of the module (documented): 20 MB, 500,000 rows, 4,096 bytes per line, 50 columns, 64 characters per time cell, a tag of at most 500 characters. UTF-8 with or without BOM; UTF-16 (BOM) and any other undecodable file get a sentence that says "save it as CSV UTF-8"; a NUL byte is refused. One import at a time: a session advisory lock `pg_try_advisory_lock(7_312_001, 0)` on a dedicated pool connection, held for the whole run, also for a dry run (409 "an import is running"). The pre-scan (decode, NUL, line lengths, row count, SHA-256) and each chunk's parse run on `core/compute.run` (the engine's thread; pure functions: arguments only read, a new object returned, per the contract in `core/compute.py`); the writes are async with `await asyncio.sleep(0)` between batches. A chunk is 10,000 lines = one transaction of at most 10,000 rows, which first runs the engine's `_UNCAP` (`SET LOCAL timescaledb.max_tuples_decompressed_per_dml_transaction = 0`; raw chunks compress after 7 days, so an import writes into compressed chunks routinely and the conflict check decompresses segments: w30 measured 20,434 rows in 0.86 s and 60,100 in 2.2 s with the cap off) and then takes `FOR KEY SHARE` on the points it writes (ordered by id), so a source deleted meanwhile cannot strand rows; a point that is gone is rejected `point_deleted`. T2 has a test that imports a full 10,000-row batch spread over a few dozen tags into a COMPRESSED chunk (reuse the w30 test helper that compresses a chunk; grep `compress_chunk` in `backend/tests`) and re-imports it (0 new, no error). The final `readings.imported` audit row, the journal event and the lock release run in a `finally` shielded with `asyncio.shield`, so a cancelled handler (a closed tab, a shutdown) still leaves the partial audit row (`complete: false`); a test cancels `run_import` mid-way and finds the row. Records never span lines: a line with a `"` is parsed with `csv.reader([line], strict=True)` (an unbalanced quote is a problem line), a line without one is split directly. A value must match `^[+-]?(\d+(\.\d*)?|\.\d+)([eE][+-]?\d+)?$` (ASCII digits; with decimal `,` spaces and `.` thousands separators are removed first), be finite and at most 1e15 in magnitude (else `value_out_of_range`); an empty value is rejected `empty_value`. No file name or path from the client is ever opened; a file name, when shown, is clipped to 80 characters and only displayed. Echoed cells (unknown tags, problem lines) are clipped to 80 characters with control characters replaced by `?`; React shows them as text; this wave writes no CSV, so `safe_cell` is not needed (a test pins that no report text is written to a file). The CSRF risk of a raw body is NOT nil (the adversarial pass, I1): `SameSite=strict` keeps out another SITE only, and a page on another port of the same host (or a sibling subdomain) is the same site; a `text/plain` or typeless body is a CORS "simple" request that needs no preflight. So the two upload routes and the Undo take the display claim's rule (`deps.refuse_another_site`, a copy of `display._comes_from_another_site` that a test keeps in step: refuse `Sec-Fetch-Site: same-site` or `cross-site` and a foreign `Origin`, 403) after their permission gate; a request without those headers (curl, the import command) passes.
- **D5 What a row becomes** (brief R3, R4). Header names are matched case-insensitively after trimming (a column may also be given as `#3`, the third column); a duplicate header name in a needed column is refused with a sentence. For each data row: tag (stripped, exact match against `points.address` of THE CHOSEN SOURCE, mapped or not; an import never creates points) -> unknown-tag rows are counted (`unknown_rows`) and the first 20 tag names kept; time -> `normalise.parse_time` (offset or `Z` converted; a naive time uses the profile's `zone`, carrying the last instant per tag so the repeated autumn hour resolves; `time_format` `iso`, `epoch_s`, `epoch_ms` or a `strptime` format limited to the directives `%Y %m %d %H %M %S %f %z %y %b`, no other) -> for `reading = interval`: `normalise.period_start(ts, period_seconds, stamp)` -> `normalise.check_window` (FUTURE beyond 5 minutes, TOO_OLD past retention minus a day); value as above; quality: `good_codes` (default `["good"]`, compared stripped and lower case; an empty quality cell or no quality column means good), any other code is stored BAD with its label counted (`normalise` label rules); a unit cell (if the profile names one) must give the same scale as the point's mapping: `scale_for(unit, mapping.metric) != mapping.scale` -> rejected `unit_differs_from_mapping`, an unusable unit (`NormaliseError`) -> `unit_not_valid_for_metric`; an unmapped point or metric `custom` is not checked. An `interval` profile against a point mapped as `energy_kwh` -> every row of that tag rejected `interval_energy_in_counter_point` (`refuse_interval_as_energy`). Readings keep the SOURCE's unit and value (the mapping's scale converts when a figure is computed). Rejections are counted by reason; the first 20 problem lines carry the line number and a plain reason.

- **D8 Tag list** (brief R7). `ingest/tag_list.py` holds the pure parser/planner (no database): CSV header names (case-insensitive) `tag`, `asset`, `metric` required; `unit`, `scale`, `interval_seconds`, `kind` (the kind of an asset the run creates, default `generic`), `reading` (`counter`/`power`/`interval`) optional; delimiter detected; at most 1,000 rows, 1 MB, 1,024 bytes per line, 12 columns, UTF-8 (BOM ok). `asset` is a path `Hall 1 / Row A / Rack 01` (split on `/`, each segment trimmed and folded like `asset_names._KEY`, 1 to 100 characters, at most 8 levels). A scale is taken from `scale_for(unit, metric)`; given both, they must agree (else a problem line); `custom` takes `unit` as `custom_unit` (required) and scale 1 unless given; an interval tag as `energy_kwh` is a problem line (`refuse_interval_as_energy`). Route `POST /api/sources/{id}/tag-list` under **`discovery.accept`**: points are created only on a `file` source (address = tag, name = tag, `unit_hint` = unit); on any other connector an unknown tag is a problem line ("no point with this address on this source: run Browse first"). The plan (points to create, assets to create as full paths, mappings to create, per-unit scales, problem lines with line numbers) is computed by the same function for the dry run and the real run. The real run (one transaction): `SELECT ... FROM sources WHERE id = :id FOR NO KEY UPDATE` first, then `lock_asset_names(db)`, then the asset and point reads, the plan, and the writes; the dry run returns a `plan_digest` (SHA-256 over the sorted point addresses to create, the asset paths to create and the sorted mapping triples `(address, asset path, metric, scale, interval)`), and the real run requires it back as `expect_plan` together with `expect_points`, `expect_assets`, `expect_mappings` (422 without them): two lists with the same counts but other names must not pass (LESSONS back end 3); it re-plans under the locks and answers 409 with the new numbers when the digest or a count differs (nothing written); any problem line in the plan -> nothing written (all or nothing); `IntegrityError` -> rollback, 409. One audit row `tags.mapped`: `{source_id, sha256, lines, points: [created point ids], assets: [{id, parent_id, name}], mappings: [{id, point_id, asset_id, metric, scale, interval_seconds, custom_unit}]}`, plus `notify(db, CONFIG_CHANNEL)`.
- **D9 Undo** (brief R7). `POST /api/tag-lists/{audit_id}/undo` under `discovery.accept`: the row must be a `tags.mapped` of the last 24 hours (404 / 410 with sentences) and not already undone (a `tags.unmapped` row whose `detail.audit_id` equals it, checked under the lock). Lock order: source row `FOR NO KEY UPDATE` (gone source -> 409 "the source was deleted, its mappings went with it"), `lock_asset_names`, the recorded points `FOR UPDATE ORDER BY id`, the recorded mappings `FOR UPDATE ORDER BY id`, the recorded assets and their subtree `FOR UPDATE ORDER BY id` (the `_lock_subtree` pattern). It refuses, naming what changed, when: a recorded mapping is missing or its values differ from the audit row (edited), a created asset was renamed or moved, has a child that this run did not create, a mapping this run did not create, or a tariff; nothing is partly undone. It then deletes the mappings, the created assets leaf-first, and the created POINTS that hold no reading (a bounded `LIMIT 1` probe per point); a point with readings stays as an unmapped point. It writes `tags.unmapped` `{audit_id, source_id, mappings, assets, points_removed, points_kept: [ids]}` and notifies `CONFIG_CHANNEL`. A widget or dashboard that names a deleted asset id is the same case as the existing asset delete (no check there either).

- **D11 Rollups after an import** (brief R3). The UTC days of every batch that stored at least one new row and that are older than `now - (REFRESH_WINDOW_DAYS days - 1 hour)` are collected; at the end, contiguous days are refreshed in windows of at most 7 days: `pending_drop_range` first (unsafe -> that window is reported, not refreshed), then `refresh_range`. Newer days are covered by the policy and real-time aggregation. A failure is reported in the report (`refresh.state = "failed"`, the exception class only) and in the journal event; the rows stay stored. The COMMAND (not the route) accepts `--refresh` to refresh the days of ALL accepted rows older than the window, for the repair case (a re-import stores nothing new and so refreshes nothing).

## API contract (frozen; the front end and the back end build to it)
- `GET /api/import-profiles` (`readings.import`) -> `{"profiles": [ImportProfile, ...]}` sorted by name. `PUT /api/import-profiles/{name}` body `ImportProfile` (the path name wins) -> 200 the stored profile; 409 over 20. `DELETE /api/import-profiles/{name}` -> 204 (404 unknown).
- `POST /api/sources/{id}/import?profile=NAME&dry_run=1` (`readings.import`, body = the CSV) -> 200 **ImportReport**:
  `{dry_run, source_id, profile, sha256, size, rows_read, new, already, differing, rejected, unknown_rows, unknown_tags: {count, names[<=20]}, rejected_by: {reason: n}, closed_months: {"YYYY-MM": n}, differing_samples: [{tag, ts, stored, file}<=5], problems: [{line, reason}<=20], problems_total, refresh: {state: "not_needed"|"done"|"failed", days, note}, complete, error, text}`; `text` = `12,480 rows read, 12,000 new, 480 already there, 0 differing, 0 rejected, 3 unknown tags (TAG-A, TAG-B, TAG-C)` (rows read = new + already + differing + rejected + unknown_rows; the clause "N rows for unknown tags" follows when unknown_rows > 0). 404 source or profile; 409 an import is running; 413 too large; 415 content type; 422 `{detail: sentence}` for a refused file (encoding, NUL, header, too many rows or columns, a line over 4,096 bytes). `dry_run` defaults to **true** when absent (a real import needs `dry_run=0` explicitly).
- `POST /api/sources/{id}/tag-list?dry_run=1&create_assets=0|1&expect_points=&expect_assets=&expect_mappings=&expect_plan=` (`discovery.accept`, body = the CSV) -> 200 **TagListReport**: `{dry_run, source_id, sha256, plan_digest, lines, points_to_create, assets_to_create: [path]<=50, assets_to_create_total, mappings_to_create, units: [{unit, metric, scale, count}], problems: [{line, tag, reason}]<=50, problems_total, ok, text, audit_id, undo_until}`; 409 `{detail, points, assets, mappings}` when the real plan differs from `expect_*` (the digest included); 422 missing `expect_*` on a real run or a refused file. `dry_run` defaults to true.
- `POST /api/tag-lists/{audit_id}/undo` (`discovery.accept`) -> 200 `{mappings, assets, points_removed, points_kept}`; 404 / 410 / 409 with a sentence.
- `POST /api/sources/{id}/history/fill?dry_run=1` (`sources.edit`) body `{start, end, before_first_reading}` -> dry: 200 `{plan, windows, expected_rows}`; real: 202 `{job_id}`; 409 `{detail, job_id}`; 422 `{detail}`. The job's `GET /api/jobs/{id}` `result` = `{ok, text, read, new, already, differing, rejected}` or `{error}`.
- `GET /api/sources` entries gain `history` (D10); `GET /api/connectors` entries gain `polls`, `description` (D7). All additive.
