- **Measured on TimescaleDB 2.30.2** (`.waves/w30/probe-unique.out`, `probe-unique2.out`, scratch database): a UNIQUE index `(point_id, ts DESC)` builds over compressed chunks; with duplicates planted and then compressed, both a whole-table duplicate count and the unique build SEE them (the build refuses); the conflict-skipping insert into a compressed chunk refuses an existing pair and keeps the stored value; a plain duplicate insert errors; a new pair is accepted and the chunk stays compressed; the DML decompression cap is `timescaledb.max_tuples_decompressed_per_dml_transaction` (default 100,000) and a 20,400-row batch of new pairs over 600 points into a compressed chunk did not hit it. **Fallback F1 is not built.**

- `Connector` has no history; `SimulatorConnector.read` passes the source's `ts` through, the plain simulator `/read` stamps `now`. `Scheduler.poll_once` writes `value.ts`.
- `seed/history.py` has `pending_drop`, `_refresh`, `refresh_rollups`, `forget_figures`, `hour_floor`, `write_batches` (uses `Writer`, checks `written == len(rows)`). `core/ledger.py:137-151` hashes every file under `core/` and `figures/` into the engine id: **this wave edits nothing under `core/` or `figures/`** (R13).
- The engine's first-reading bound is `min(bucket)` of `readings_1h` per point (`api/billing.py:42`, `core/energy.py:184,209-212`).

## Decisions (D)
- **D1** F1 not built (measured). Cost if wrong: the dev-copy drill shows it and F1 is added to T1.
- **D2 Migration (review C1, C2, M2, M3).** ONE transaction. Upgrade: (1) count the duplicate pairs over the WHOLE table with one grouped query (compressed chunks included; 7 s on the dev copy); if any, refuse BEFORE changing anything with a plain `RuntimeError` in the style of 0004/0013 (the count, "still at the revision it was at before", stop the api, backup, the read-only listing query in `docs/upgrading.md` "Duplicate readings"); (2) build `CREATE UNIQUE INDEX readings_point_ts_key ON readings (point_id, ts DESC)` inside a SAVEPOINT (`bind.begin_nested()`); a unique violation here (a duplicate that arrived after the count) rolls back to the savepoint, recounts and refuses with the same text; (3) `SET LOCAL lock_timeout = '120s'`, drop the old index `readings_point_ts`, reset the timeout; (4) create `history_status`. The build holds ShareLock (writers wait, readers do not) until commit, the drop AccessExclusive for an instant. Downgrade: create the plain index, drop the unique one (same lock_timeout), drop `history_status`; lossless. No row seeded. Name every constraint.
- **D3 `history_status`** (one row per source, `source_id` PK, named FK to `sources` ON DELETE CASCADE): `state` text CHECK in (`idle`,`filling`,`backing_off`,`not_supported`), `answered_through` timestamptz NULL (the frontier), `reread_through` timestamptz NULL (D5), `last_cycle_at`, `last_success_at`, `next_try_at` timestamptz NULL, `short_hours` integer, `rows_new`, `rows_already`, `rows_differing`, `rows_rejected`, `requests`, `failures` bigint (totals since the collector restarted, reset at its start), `last_error` text NULL (scrubbed), `updated_at`. The collector writes it; marks update with `GREATEST`. Readers use raw SQL (no ORM model: nothing is added to `core/models.py`).
- **D4 Write function (R3; review I4, I7, M5, M6).** `ingest/store.py: async def insert_readings(conn, rows, *, notify) -> WriteResult(new, already, differing, rejected, samples, newest_new, first_new, last_new)`. Steps: (1) non-finite value -> `(None, BAD)`; (2) de-duplicate the batch (first occurrence wins); (3) sort by `(point_id, ts)` and insert with ONE statement from `unnest(...) ORDER BY point_id, ts` using the conflict-skipping form on `(point_id, ts)`, returning the stored `point_id, ts`; (4) rows NOT returned: ONE comparison query -> `already` or `differing` (`value IS DISTINCT FROM`, `quality <>`); the first stored value wins, a reading is never updated; (5) `point_latest` from the NEW rows only, ONE statement from `unnest(...) ORDER BY point_id` (lock order), `ON CONFLICT (point_id) DO UPDATE ... WHERE point_latest.ts < EXCLUDED.ts` (strict), the `EXISTS (SELECT 1 FROM points ...)` guard, `RETURNING` the rows it really inserted or changed; (6) with `notify=True`, NOTIFY only those RETURNING rows (an old backfilled value never reaches a widget), chunks of 100, payload as today. `journal_conflicts(pool, result, source_id=None)`: one `readings.conflict` warning per allowed event, gated by `journal.allow(("readings.conflict", source_id), 600)` with the counts of the suppressed calls added in between (100 conflicting flushes = 1 event). `Writer(pool, max_buffer=100_000, notify=True)`; `flush` keeps its buffer, `_trim`, keep-on-failure (a `DeadlockDetected` is an `Exception`: rows kept) and returns `len(rows)` (handled, new or already, so `written == len(rows)` in the seeder holds); the seeder's `write_batches` builds `Writer(pool, notify=False)`.
- **D5 Backfill cycle (R7 refined; review I1, I11).** Each hour is asked at most twice, by two marks: the frontier `answered_through` (the new data) and the late pass `reread_through`. A cycle per source: lease (D16) -> read raw retention fresh -> compute the window `[max(frontier, lookback start), now]` (first run: from the lookback start) -> check `pending_drop_range` over it BEFORE asking (if unsafe: journal `history.failed` once, skip the cycle) -> **ascending time slices** (about 6 hours or fewer by the row cap); for each slice every address batch is asked; when all batches of a slice answered (or a batch was set aside after 3 consecutive failures: counted, journaled once, it never holds the mark), the frontier is persisted (`GREATEST`) and the slice's rows are refreshed (D8). 429/503/timeout: retried inside the cycle after the back-off (exponential from 30 s to 15 minutes, `Retry-After` honoured), up to 3 times per request, then the cycle ends in `backing_off`. Late pass: the window `[reread_through, min(now - REREAD, the frontier at the start of the cycle)]` once per cycle after the frontier; ranges the frontier fetched in this cycle that are older than `now - REREAD` advance `reread_through` without a second ask; first run: `reread_through := now - REREAD` after success. A cut answer continues from `complete_until` per address batch; a cut without progress is a failure of that batch. `DCDASH_HISTORY_EVERY <= 0` switches the loop off.
- **D6 Requests.** At most `DCDASH_HISTORY_MAX_ROWS` expected rows (addresses x seconds / the mapping interval) and at most 200 addresses per request; one request in flight per source; at most `DCDASH_HISTORY_RATE` a minute (a token bucket); statuses `timeout`, `unreachable`, `protocol_error`, `rate_limited` back off; `auth_failed` backs off 15 minutes and journals once; `not_supported` waits one day (journals once). `ConnectorError.retry_after: float | None = None` (seconds, or an HTTP date parsed to seconds).
- **D7 What may be stored (review M11, I12).** Per point: not older than the point's first bucket in `readings_1h` (`min(bucket)`, the engine's `own_from`; a point with none is skipped and counted), not older than `now - (raw retention - 1 day)`, not later than `now + 5 minutes`; a point no longer mapped is dropped; an address the Historian does not return is counted, never holds the mark. **D15 Thinning**: for every mapping whose metric is not `energy_kwh`, a history sample is kept only if no stored sample of that point (read for the slice) and no already-kept sample lies within half the mapping's `interval_seconds` of it (ascending, greedy): holes fill at the mapping's density and a covered hour is never thickened (a power-only estimate must not move). Energy counters keep every sample.
- **D8 Rollups (review I3, I11).** `ingest/rollups.py`: `hour_floor`, `pending_drop_range(pool, lo, hi)`, `refresh_range(pool, lo, hi)` (minutes first, then hours; lock retry as `seed/history._refresh`; the end of the hourly refresh is clamped to `hour_floor(now) - 1 hour`, of the minute refresh to the minute before now; nothing is refreshed when the clamped range is empty). The seeder keeps its names `_refresh` and `pending_drop` as thin wrappers (tests patch `history._refresh`) and `forget_figures`; the backfill never calls `forget_figures` (R9). After a slice that wrote NEW rows: one `refresh_range` over `[hour_floor(first_new), last_new + 1 hour]` clamped as above.
- **D9 Wire format of the stand-in.** `GET /read?addresses=` -> `{"values": [{"address","ts","value","quality","zone"?,"period_seconds"?,"stamp"?}]}`: the SAME per-value fields as `/history`, with `ts` the tag's newest visible grid instant (the plain simulator's `/read` sends none of the extra fields). `GET /history?addresses=&start=&end=&limit=` -> `{"values": [...], "complete_until": ISO-UTC, "unknown": [...]}` ordered by INSTANT then address (grouped per address, so a repeated local hour is seen as an ascending series), `quality` the string `good|uncertain|bad|substituted|interpolated`, `zone` exactly when `ts` is a naive local time, `period_seconds` + `stamp: "end"` for an END-stamped interval value; `complete_until` is cut by the row limit ONLY (never by lateness: a LATE value is simply missing until visible and the late pass finds it). `/history` is a sync `def`. `/points`, `/stats` as in R5.
- **D10 Connector (review I2, I13, M8, M9, M10).** `read_history(addresses, start, end, resolution=None, *, after=None)` where `after` maps address to the last UTC instant already received (fold context across pages). `HistoryPage(values, complete_until, rejected=0, unknown=())`. `supports_history` on `Connector` (False), True on `SimulatorConnector`. The mapping 404 -> `not_supported`, 429 -> `rate_limited` (+ `retry_after`), 503 -> `unreachable` lives inside `read_history` only (`read()`/`test()` keep `protocol_error`). `read()` runs the same normalise path when the per-value fields are present, and `read()` and `read_history` chunk at 200 addresses per request. Conversion of an answer over 2,000 items runs in a thread (`asyncio.to_thread`).
- **D11 Report line.** `history:` line per source in SOURCE HEALTH only for a source with a `history_status` row; read by raw SQL; the eleven sections and `docs/field-debugging-examples/*.txt` do not change.
- **D12 Journal kinds and settings live in `dcdash/ingest/`** (`kinds.py`: `HISTORY_FILLED`, `HISTORY_FAILED`, `HISTORY_CLOSED_MONTH`, `READINGS_CONFLICT`; `settings.py`: the `DCDASH_HISTORY_*` reader with defaults: EVERY 600, MAX_ROWS 20000, RATE 30, LOOKBACK_DAYS 7, REREAD_HOURS 3). Nothing under `core/` or `figures/` changes (R13).
- **D13 Closed months (R9, review I13).** The months that contain NEW rows of a cycle are worked out in the SITE time zone (`core.timeutil`, imported) and one `history.closed_month` is journaled per closed month (`billing_closes`); nothing else.
- **D14 The fill command** `python -m dcdash.ingest.backfill --source N [--start ISO --end ISO] [--yes] [--before-first-reading]`: takes the lease (D16) and refuses with a sentence when the loop holds it; explicit windows only; dry run prints windows and expected rows and writes nothing; with `--yes` fills, always refreshes (D8), prints `12,480 rows read, 12,000 new, 480 already there, 0 differing, 0 rejected`; never writes `history_status`; range not older than raw retention minus a day; before a point's first reading only with `--before-first-reading` (the dry run then says in plain words that it changes a parent's past figures).
- **D16 Lease.** `pg_try_advisory_lock(<constant>, source_id)` on a dedicated connection held for the cycle; a second loop, the command or a second collector skips or refuses.
- **D17 Route.** `GET /api/sources/{id}/history` (`sources.view`): 404 for an unknown source, otherwise 200 with `supports_history` and, without a row, `state: "never_run"`.
- **D18 Settings through compose.** Every `DCDASH_HISTORY_*` setting is passed in `x-backend-env` (empty = default) and pinned in `test_compose_config.py`.
- **D19 Collector tests.** `test_collector_main.py` sets `DCDASH_HISTORY_EVERY=0` where it runs `run()`; the new loop is cancelled within `SHUTDOWN_SECONDS`; every `except` in the loop logs and continues; an FK violation on `history_status` (source deleted meanwhile) skips the source.
- **D20 Not built, documented**: a config change keeps the marks and the one-day wait (M7); disable-then-enable fills the disabled span up to the lookback.
