## Decisions (D) taken in this plan
- **D1 F1 not needed** (above). Cost if wrong: the dev-copy drill (R2b) shows a problem and F1 (advisory lock + anti-join, R2) is added to Task 1.
- **D2 Migration shape.** Upgrade, ONE transaction: `CREATE UNIQUE INDEX readings_point_ts_key ON readings (point_id, ts DESC)` FIRST (while the old index still exists), then `DROP INDEX readings_point_ts`, then `CREATE TABLE history_status`. If the build fails with a unique violation (a duplicate exists), catch it, count the duplicate pairs with ONE query (compressed chunks included), and raise a refusal in the style of `0004` (nothing changed - the transaction rolls back and the old index stays; plain message; the count; where to find the read-only listing query, `docs/upgrading.md` "Duplicate readings"). The success path pays for the build once (the build IS the check). Downgrade: recreate the plain index, drop the unique one (create first, drop second), drop `history_status`; lossless (an index holds no data; `history_status` is derived). No row seeded. Name every constraint.
- **D3 `history_status`** (one row per source, `source_id` PK, FK `sources` ON DELETE CASCADE): `state` text CHECK in (`idle`,`filling`,`backing_off`,`not_supported`), `answered_through` timestamptz NULL (the frontier), `reread_through` timestamptz NULL (D5), `last_cycle_at`, `last_success_at`, `next_try_at` timestamptz NULL (back-off and the one-day `not_supported` wait), `short_hours` integer, `rows_new`, `rows_already`, `rows_differing`, `rows_rejected`, `requests`, `failures` bigint (all totals since the collector restarted, reset at its start), `last_error` text NULL (scrubbed), `updated_at` timestamptz. The collector writes it; the api only reads it.
- **D4 Write function (R3, exact shape).** `ingest/store.py: async def insert_readings(conn, rows, *, notify: bool) -> WriteResult` where `WriteResult(new: int, already: int, differing: int, rejected: int, samples: list[dict], newest_new: dict[int, Row], first_new: datetime|None, last_new: datetime|None)`. Steps: (1) non-finite value -> `(None, BAD)`; (2) de-duplicate the batch (first occurrence of a `(point_id, ts)` wins); (3) sort by `(point_id, ts)` and insert in THAT order (`INSERT ... SELECT ... FROM unnest($1::int[], $2::timestamptz[], $3::float8[], $4::smallint[]) ORDER BY 1,2 ON CONFLICT (point_id, ts) DO NOTHING RETURNING point_id, ts`) so two writers with overlapping batches take row locks in one order (no deadlock: test it); (4) for the rows NOT returned: ONE comparison query against the stored rows (`value IS DISTINCT FROM`, `quality <>`): `already` or `differing` (a differing re-send changes neither the reading nor `point_latest`); (5) `point_latest` from NEW rows only, newest per point, with a STRICT `WHERE point_latest.ts < EXCLUDED.ts` and the existing `EXISTS (SELECT 1 FROM points ...)` guard; (6) with `notify=True`, NOTIFY the newest NEW row per point in chunks of `NOTIFY_CHUNK`, same JSON payload as today. `store.py` also holds `async def journal_conflicts(pool, result, source_id=None)`: ONE `readings.conflict` warning event per call (counts, the source, at most five samples of point, time, stored value, re-sent value) via `journal.record_soon`; the Writer calls it after its transaction (source looked up from the first differing point when not given). `Writer.flush` keeps its buffer, `_trim`, the keep-on-failure rule and its return contract (`len(rows)` handled, new or already); its transaction is `insert_readings(conn, rows, notify=True)`.
- **D5 Backfill cycle (R7, refined).** The brief re-reads the last `DCDASH_HISTORY_REREAD_HOURS` on every cycle, which asks every recent hour about 18 times and contradicts "an answered hour is never asked again". Ruling: **each hour is asked at most twice, by two marks**: the frontier `answered_through` (window `[mark, now]`, the new data) and the late pass `reread_through` (window `[reread_through, now - REREAD_HOURS]`, one more look at an hour `REREAD_HOURS` after it ended, for late data). First run: frontier window `[lookback start, now]`, `reread_through := now - REREAD_HOURS` after success (nothing older gets a second pass); after an outage the frontier window is the outage. Neither mark moves unless every request of its window answered. Costs if wrong: late data later than REREAD_HOURS is missed (the same as the brief); the cycle code is two window calls instead of one.
- **D6 Windows and requests.** Windows are cut on whole hours of UTC where possible; per request: at most `DCDASH_HISTORY_MAX_ROWS` expected rows (addresses x seconds / the mapping interval), one request in flight per source, at most `DCDASH_HISTORY_RATE` a minute (a token bucket in the engine), `ConnectorError` statuses `timeout`/`unreachable`/`protocol_error`/HTTP 429/503 back off exponentially from 30 s to 15 minutes (honour `Retry-After`; the connector exposes `retry_after` on the error as an attribute `ConnectorError.retry_after: float | None = None`, default None, so existing constructors are unchanged); `auth_failed` backs off 15 minutes and journals once; `not_supported` waits one day (journal once). A cut answer (`complete_until` before the end) continues from `complete_until` for that address batch; a cut that makes no progress counts as a failure. The mark of a window = the oldest final `complete_until` over its batches, never later than the window's end captured at the cycle start. `DCDASH_HISTORY_EVERY <= 0` switches the loop off (the kill switch; documented).
- **D7 What may be stored** (`ingest/backfill.py` filters the rows before `insert_readings`): not older than the point's FIRST stored GOOD reading (cached per point; a point with none is skipped and counted), not older than `now - (raw retention - 1 day)`, not later than `now + 5 minutes` (normalise rejects, counted as `rejected`); a point not mapped any more is dropped from the window. An address the Historian does not return is counted once per cycle, never holds the mark back.
- **D8 Rollups.** `ingest/rollups.py` gets `hour_floor`, `pending_drop_range(pool, lo, hi)`, `refresh_range(pool, lo, hi)` (minutes first, then hours, lock-retry as `seed/history._refresh`); the seeder imports them back (behaviour and its tests unchanged); `forget_figures` stays in the seeder (R9: the backfill never forgets figures). After a cycle that wrote NEW rows: ONE `pending_drop_range` then `refresh_range` over `[hour_floor(first_new), last_new + 1 hour]`; if `pending_drop_range` says no, journal `history.failed` once and skip the refresh (the rows stay written).
- **D9 Wire format of the stand-in (fixes Tasks 4a and 4b together).** `GET /read?addresses=a,b` -> `{"values": [{"address","ts","value"}]}` where `ts` is the tag's newest visible grid instant (aware UTC ISO), exactly the plain simulator's shape. `GET /history?addresses=a,b&start=ISO&end=ISO&limit=N` -> `{"values": [{"address","ts","value","quality","zone"?,"period_seconds"?,"stamp"?}], "complete_until": ISO-UTC}` ascending by `ts` then address; `quality` is the string `good|uncertain|bad|substituted|interpolated`; `zone` (an IANA name) is present exactly when `ts` is a naive local time; `period_seconds` with `stamp: "end"` marks an interval value stamped at the END of its period. `GET /points` -> `{"points": [{"address","name","unit","kind","zone"?,"stamp_start","stamp_end","interval"}]}` (kind counter | interval | power). `/stats` -> `{"requests": {"GET /history": n, ...}}`. The `unknown address` case: omitted from `values` and listed in `"unknown": [...]` (the connector reports it). Time parameters accept aware ISO only. All routes need `X-API-Key` except `GET /`.
- **D10 `read_history` on `SimulatorConnector`**: GET `/history`; HTTP 404 -> `ConnectorError("not_supported", ...)`; 429/503 -> `ConnectorError("unreachable"/"rate_limited", ...)` with `retry_after` from the header; naive `ts` + `zone` -> `normalise.to_utc`; `stamp: "end"` -> `ts - period_seconds` via `normalise`; quality via `normalise.quality`; rows rejected by `normalise` are returned as nothing and counted in `HistoryPage.rejected: int` (an extra field with default 0). `SimulatorConnector.read()` is unchanged (it already passes the source's time through).
- **D11 Report line.** A `history:` line per source inside SOURCE HEALTH only for a source that has a `history_status` row (the collector creates one for a source whose connector `supports_history`); no row, no line, so the eleven sections and `docs/field-debugging-examples/*.txt` do not change. The new tests cover with and without.
- **D12 Journal kinds** in `core/journal.py`: `HISTORY_FILLED = "history.filled"` (info, once per cycle that wrote NEW rows: counts), `HISTORY_FAILED = "history.failed"` (warning, on a transition into failure and once per 15 minutes while it lasts), `HISTORY_CLOSED_MONTH = "history.closed_month"` (info, once per month and cycle), `READINGS_CONFLICT = "readings.conflict"`.
- **D13 Closed months (R9)**: the backfill asks `billing_closes` for the months that contain NEW rows of the cycle and journals one `history.closed_month` per month; nothing else.
- **D14 The fill command** `python -m dcdash.ingest.backfill --source N [--start ISO --end ISO] [--yes] [--before-first-reading]`: reuses the engine with explicit windows; dry run (no `--yes`) prints the windows, the expected rows and writes nothing (no `history_status` row either); with `--yes` it fills, always refreshes (D8), and prints `12,480 rows read, 12,000 new, 480 already there, 0 differing, 0 rejected`. Range limits: not older than raw retention minus a day; without `--before-first-reading` not before each point's first stored GOOD reading (the dry run says so); with it the dry run says in plain words "this changes a parent's past figures".
