- **The W7d arrow-key step assumes Chromium on Linux or Windows:** an arrow on a closed `<select>` changes its value there, while on macOS it opens the popup. The Playwright projects run Desktop Chrome (Chromium) only. W7e's keyboard steps never arrow a closed select; they rely on Chromium delivering only the Escape keyup while a popup is open (the popup closes alone, the panel stays open) and wait a fixed 250 ms after opening a popup, because an open native popup has no DOM to wait for.
- **Rulings of the wave worth keeping:** (1) Esc on an OPEN select popup needs no code: Chromium 153 (both headless modes) delivers only the Escape keyup to the page, so the popup closes alone and the panel stays open; opening the popup fires no focusin, blur or outside pointerdown. Escape after arrowing inside an open popup keeps the highlighted option (and saves it). Another browser may close the panel from an open popup (one extra click to reopen). (2) ArrowDown on the profile trigger still lands on Password; the selects are reached with Tab and the panel's arrow walk ignores them. (3) The kind matcher splits camelCase, acronym and digit boundaries, keeps a lone plural `s` attached to an acronym (`PDUs`, not `PD Us`), clamps the kind to 200 characters before its regexes, and matches whole tokens only: `Panelling` and `LVP01` get the generic icon, `panelboard` and `switchboard` are listed aliases. (4) The asset header grows from 111 to 123 px for a one-line title, because the 40 px icon tile is taller than the 28 px title line (negative margins on `.page-tile` would restore 111). (5) The bar sits at z-index 46: above the top bar (45), below the sidebar tip (50), the pop-ups and every dialog (1000), so a dialog's backdrop covers it. (6) Under reduced motion the fade is instant (the layer's universal `transition: none`), accepted. (7) The restart of the bar from zero after a load that arrives during `finish` or `fade` is verified as the phase sequence in jsdom only, not as a picture.
- **Tooling:** the bar is recorded inside the page by `w7e.spec.ts` (a `MutationObserver` on `data-phase` and a 50 ms sampler installed with `addInitScript`), because a flash of a few hundred milliseconds is missed by polling; React Query's own `setTimeout(0)` notifications make vitest's global fake timers unusable for the bar's component tests, which use an injected manual clock (`src/test/manualTimers.ts`).
